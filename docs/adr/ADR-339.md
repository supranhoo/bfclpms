# ADR-339 — Saved tiered option templates

**Status:** Accepted (2026-09-02)

## Context
`TieredOptionsBuilder` offered only seven hardcoded presets (`TIERED_TEMPLATES`).
Any admin-built ladder had to be retyped per KPI, violating the zero-hardcoding rule.

## Decision
Reuse the existing, previously unused `public.kpi_scoring_scales` table as the
tiered template library (`scale_kind = 'tiered'`). The builder merges built-in
presets and saved templates into one dropdown and adds a "Save as template"
action for admins, with name-normalised overwrite and soft delete.

Additive migration only: `scale_kind`, `description`, and an
`(scale_kind, is_active)` index. Rollback = drop the columns; the feature
degrades to built-in presets.

## Consequences
- No KPI row is touched; templates only seed the in-form option list (§88 intact).
- Admin write / oversight read RLS already present on the table is reused.
- Numeric R5–R0 ladders are out of scope, though the table supports them.

See POLICY §KPI-TIERED-TEMPLATE-LIBRARY, `src/tests/tieredTemplates.test.ts`.
