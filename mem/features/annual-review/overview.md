---
name: Annual Review System
description: Parallel annual appraisal module — 5 tables (annual_review_*), snapshot reviewer chain, advance_annual_review_status RPC, feature-flag gated
type: feature
---
- New module is namespace-isolated from monthly/quarterly PMS. Tables: `annual_review_cycles`, `annual_review_templates`, `annual_review_assignment_rules`, `annual_review_instances`, `annual_review_responses`. Two enums: `annual_review_status`, `annual_reviewer_role`.
- Reviewer chain is **snapshotted on instance creation** (`manager_id`, `skip_id`, `dept_head_id`, `bu_head_id`, `hr_id` columns) — mid-cycle org changes never break a running review. Canonical order: Self → Manager → Skip → Dept Head → BU Head → HR. `seedInstancesForCycle()` resolves the chain from `profiles.reporting_manager_id` (2 hops up = skip), `departments.head_user_id` (dept_head), and `business_units.head_user_id` (bu_head).
- Cycle-level default workflow chain lives on `annual_review_cycles.default_enabled_stages` (admin-editable on Annual Review Admin → Cycles); stamped onto each new instance.enabled_stages. Per-employee overrides via `set_annual_review_enabled_stages` still win and survive re-seed.
- Advance / Send-back walk `public.annual_review_effective_chain(instance_id)` — `enabled_stages` further filtered by per-stage skip rules evaluated in this order: `no_reviewer_mapped → self_assignment → reviewer_inactive → duplicate_reviewer`. Duplicate detection is top-down by seniority (`hr → bu_head → dept_head → skip_manager → manager`) so the highest tier wins when the same person is mapped to multiple slots. `self` is always kept. Auto-skips are recorded in `system_audit_logs` (`annual_review.stage_auto_skipped`) with a `skipped_stages` breakdown sourced from `annual_review_effective_chain_details(instance_id)`. TS mirror: `src/lib/annualReview/effectiveChain.ts`.
- Criteria card visibility (SSOT: `src/lib/annualReview/templateVisibility.ts`): hidden on a stage page when no criteria target the stage OR when `system_scores` weights already sum to ≥ 100. Replaced by a single muted info banner; Submit flow unchanged. Read-only views still render the full criteria list.
- Status semantics: `overall_status` reflects the CURRENT stage awaiting action (`pending_self` … `pending_hr` → `completed`). RPC `advance_annual_review_status(instance_id, role)` verifies caller against the snapshot, locks the role's response (`is_locked=true`), and bumps to the next stage. Admin/`hr_pms` may force-advance.
- Scoring (SSOT: `src/lib/annualReview/scoring.ts`): `criteria_total = Σ(weight*score)`, `max = Σ(weight*5)`. `overall = Σ system_scores + criteria_total` capped at 100. System scores are already-weighted (percentage points).
- Appraisal composition surface (SSOT: `src/lib/annualReview/scoringComposition.ts` + `AppraisalCompositionCard`): employee/reviewer forms, footer, and pre-submit dialog show System + Criteria → Overall (/100). `computeOverallScore` remains the persistence SSOT.
- Eligibility (SSOT: `src/lib/annualReview/eligibility.ts`): supports `equals | not_equals | gt | gte | lt | lte`; missing actual → fails.
- Multilingual: `useAnnualReviewTranslation` precedence = current===default ? fallback : template.translations[lang][key] → UI_I18N[lang][key] → fallback. Static dict in `src/lib/annualReview/i18n.ts` covers en/hi/es UI strings.
- Evidence reuses the existing `review-evidence` Supabase Storage bucket under `annual-review/{instance}/{role}/...`. Names are tagged `criterionId::originalName` in the response.evidence JSONB so the criterion-scoped uploader can rehydrate.
- UI feature flag: `admin_feature_flags.annual_review_enabled` (default off). Routes: `/annual-review` (employee), `/annual-review/team` (reviewer), `/annual-review/admin` (HR/admin 4-tab console: Progress / Cycles / Templates / Rules). Menu entries live in `menu_registry` keyed by `feature_key='annual_review_enabled'`.
- Auto-save: `useDebouncedResponseDraft` flushes 2s after the last edit; `submit` always calls `flush()` then `advance.mutateAsync(...)`.
- i18n SSOT: `AnnualReviewI18nProvider` + `useAnnualReviewI18n()` (in `src/components/annual-review/AnnualReviewI18nContext.tsx`). Child components read `t(key, fb)` for UI strings and `tTemplate(kind, id, field, fb)` for template-authored content. Static dict lives in `src/lib/annualReview/i18n.ts`. Adding a new visible string ⇒ add a key to UI_I18N for `hi`/`es` and call `t()` at the render site — do NOT hardcode English.
- Reviewer resolution SSOT: `src/lib/annualReview/stageForReviewer.ts`. MUST cover every `pending_*` status in `stageChain.ts` (self / manager / skip_manager / dept_head / bu_head / hr) — missing branches silently lock that stage's reviewer out of the detail page. Guarded by `stageForReviewer.test.ts`. Never re-inline the mapping in components.
- Variance justification: when a reviewer's score differs from the employee's self score on a criterion, `CriteriaScoringMatrix` renders an optional non-mandatory textarea; text is stored under `qualitative_responses['<criterionId>__variance']`. Never blocks Submit; hidden when scores match or no self entry exists. Policy: §AR-VARIANCE-JUSTIFICATION.
- Running final score (v2.66.80): Dept Head + BU Head detail pages render `RunningFinalScoreCard` above the criteria matrix. SSOT `src/lib/annualReview/runningFinalScore.ts` wraps `computeFinalScore` and includes ONLY `is_locked=true` responses (drafts never leak). Card hides when no stage locked. Policy: §AR-RUNNING-FINAL-SCORE.
- Overall Recommendation (v2.66.80): optional textarea on Dept Head + BU Head pages; stored in `annual_review_responses.qualitative_responses` under reserved key `__overall_recommendation` (constant `RECOMMENDATION_KEY`). Never gates Submit. Read-only aggregate shown to downstream reviewers and to the employee at acknowledgment via `EmployeeResultsView`. Reserved keys (`__overall_recommendation`, `__variance`) must be filtered from any criterion-remark iteration. Policy: §AR-OVERALL-RECOMMENDATION.
