# ADR-214 — Workflow Configuration export must fetch its own data

Date: 2026-07-31
Status: Accepted

## Context

An exported "Workflow Configuration Report" arrived with a correct header
(`Templates: 15 | Total Overrides: 397`) but every employee row printed `—` for
Name, Code, Email, PMS Grade, Department, Reporting Manager and Skip-Level
Manager.

Database verification ruled out the data:

- `workflow_config` holds exactly 397 employee override rows.
- All 397 `config_value` entries join cleanly to `profiles.id` (397/397).
- The directory is intact: 2,672 profiles, 2,584 active.

The defect was client-side. `WorkflowConfigExport` did not fetch employee data;
it consumed whatever `/admin/workflow-config` had loaded (`profiles || []`),
producing two failure paths:

1. **Timing.** The Export button was enabled immediately while the
   ~2,600-employee paged fetch was still in flight. An early click built an
   empty lookup map, so every cell fell through to `—`, while template and
   override counts (already loaded) printed correctly — exactly the reported
   file.
2. **Visibility.** That screen queries `public.profiles` directly, so row-level
   access can return a partial roster for non-admin exporters, silently
   blanking a subset of rows.

A third bug surfaced while reading the code: the "All Employees (Resolved)"
sheet hardcoded `is_active: true`, so deactivated people could be printed as
valid reviewers.

## Decision

1. The export fetches its own roster on click via the SECURITY DEFINER
   `get_reviewer_roster_slim` RPC through `fetchAllRpcPaged`, independent of
   screen state.
2. An empty roster aborts the export with an explicit error toast. A
   placeholder-only workbook is never written.
3. Individually unmatched overrides render `Unresolved (id: 30ec1688…)` instead
   of `—`, and a WARNING line under the report header states the count.
4. The button is disabled and labelled "Preparing…" for the whole
   fetch-and-build cycle.
5. Real `is_active` flows into the resolver; a new "Employee Status" column
   appears on the Overrides and Resolved sheets.
6. Row construction moved to pure builders in
   `src/lib/reports/workflowConfigExportRows.ts` so the regression is testable
   without a browser.

## Consequences

- The export takes marginally longer (it now fetches ~2,600 rows itself); the
  busy label communicates this.
- Every sheet reads one roster snapshot, so sheets can no longer disagree.
- Export-only change: no schema change and no effect on live review resolution.
  Rollback is reverting the component and page prop.

Guard: `src/test/reports/workflowConfigExport.test.ts`.
