# ADR-355 — Reviewers must be able to reopen a KRA after submitting (touch parity)

Status: Accepted — 2026-09-03

## Context

Auditor Shekhar reported: "After submitting a KRA from an iPad, I am unable to open it again."

iPad Safari (~834 CSS px) is above the 768px `useIsMobile` breakpoint, so it renders the
desktop `KpiDetailsTable` path with a horizontally scrolling action column.

## Root cause

The post-submit read-only affordance was desktop-shaped:

1. `KpiDetailsTable.tsx` — once a KPI leaves the audit stage (`management_review`),
   the action cell swapped the full "Continue"/"Review" button for a "Forwarded"
   badge plus an **icon-only ghost** eye button (~32px, no label, hover-discoverable,
   at the far right of a scrolling table). Same shape for Reviewed, Draft (Mgmt),
   Completed and N/A states.
2. `MobileKpiCard.tsx` — the forwarded and past-stage branches rendered a badge and
   **no reopen control at all**.
3. `AuditScorecard.tsx` — when a progress-tracker status chip was active, the
   just-submitted KPI left the filter and vanished from the list entirely.

## 5 Whys

1. Why can the auditor not reopen the KRA? — No obvious open action remains on the row.
2. Why? — The row drops to a badge with an icon-only eye button, or disappears under an active filter.
3. Why was that shipped? — The read-only path was designed for desktop hover + wide tables.
4. Why did desktop-only thinking survive? — Tablets take the desktop branch, so iPad was never exercised as a touch surface.
5. Why no guard? — There was no regression test for post-submit reopen or touch targets on reviewer scorecards.

## Decision

Read-only reopen is a first-class action, not decoration.

- `KpiDetailsTable` gets a single `renderViewButton()` helper: labelled, `variant="outline"`,
  `min-h-[44px]` on small viewports, used by every completed/forwarded/N/A branch.
- `MobileKpiCard` renders the same labelled View button on forwarded and past-stage rows.
- `AuditScorecard` clears the active `statusFilter` on every successful submit path and
  the forward toast states where the KPI went.

## Consequences

- Presentation and local UI state only: no schema, RPC, RLS, workflow or scoring change.
- `canReviewKpi` and every write path are untouched; who may act is unchanged.
- Regression guard: `src/tests/reviewerReopenAffordance.test.tsx`.

## CAPA

- Corrective: the three changes above.
- Preventive: POLICY §REVIEW-REOPEN-AFFORDANCE — reviewer completed-state rows must expose a
  labelled reopen control with a >=44px touch target, and a submit must never hide its own row.

## Rollback

Revert `KpiDetailsTable.tsx`, `MobileKpiCard.tsx`, `AuditScorecard.tsx` and the test file.
