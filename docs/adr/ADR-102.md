# ADR-102 — Bulk Review "self submitted" predicate widened beyond numeric `self_score`

- **Status:** Accepted
- **Date:** 2026-06-30
- **Related:** ADR-064 (Bulk Scoring), ADR-067 (Bulk Override + Org KPI), ADR-098 (per-stage achieved mirror), POLICY §88, §111.6

## Context

Auditors using `/review/bulk-scoring` saw cells marked
`Write skipped — self_not_submitted` even though the Self tile on the Unified
Scorecard showed a submitted value and Manager had already approved the cell
(e.g. **Jyoti Prakash Dwivedi → "Implement 5S practices", May 2026**, submission
`a68e9d59-80b5-4781-a821-a388e5cf904c`).

The row state at the time was:

| column | value |
|---|---|
| `self_score` | NULL |
| `self_achieved_value` | 2 |
| `self_remarks` | "2S Achieved" |
| `submitted_at` | 2026-06-05 12:48 UTC |
| `manager_score` | 2.00 |
| `manager_rating` | red |

`bulk_write_stage_scores` (migration `20260629090420_*.sql`, the bulk RPC behind
the dashboard) gated every non-override write on:

```sql
ELSIF NOT p_is_override AND v_cur.self_score IS NULL THEN
  v_reason := 'self_not_submitted';
```

This conflates **"Self stage submitted"** with **"Self stage computed a numeric
`self_score`"**. Two real-world paths populate Self without writing
`self_score`:

1. **Org KPIs** (per ADR-067): Data Owner propagation lands values on
   `self_achieved_value` / `achieved_value`; the numeric Self rating is not
   stamped until later in the workflow.
2. **Qualitative KPIs**: Self enters a label/remark; rating is derived
   downstream.

In both cases a Manager (or later reviewer) can have already scored the cell,
which logically proves Self submitted — yet the bulk RPC still rejected the
Auditor write. The single-cell auditor path does not use this guard, which is
why per-cell submissions kept working and only Bulk Review tripped it.

## Decision

`CREATE OR REPLACE` `public.bulk_write_stage_scores(...)` with two surgical
changes; no schema change, no behaviour change elsewhere in the function:

1. The `SELECT ... INTO v_cur` clause now also reads
   `self_achieved_value`, `self_remarks`, `submitted_at`, and
   `functional_manager_score`.
2. The `self_not_submitted` guard is replaced with a multi-signal predicate:

   ```sql
   ELSIF NOT p_is_override
         AND v_cur.self_score              IS NULL
         AND v_cur.self_achieved_value     IS NULL
         AND NULLIF(btrim(COALESCE(v_cur.self_remarks,'')),'') IS NULL
         AND v_cur.submitted_at            IS NULL
         AND v_cur.manager_score           IS NULL
         AND v_cur.functional_manager_score IS NULL
         AND v_cur.skip_level_score        IS NULL
         AND v_cur.hr_pms_score            IS NULL
   THEN
     v_reason := 'self_not_submitted';
   END IF;
   ```

Rationale: the row is treated as "Self submitted" if **any** of these signals
exist. Downstream stage scores are sufficient on their own because the workflow
cannot have advanced past Self without Self having submitted.

No other guard (`final_locked`, `auditor_takes_precedence`,
`row_version_conflict`, `not_terminal_for_template`), RLS check, audit log,
notification path, or return shape changes. Override (`p_is_override = true`,
admin-only) continues to bypass the guard exactly as before.

## Consequences

- Bulk Auditor (and Manager/Skip/HR-PMS) writes succeed on Org KPIs and
  qualitative KPIs whose Self stage stored a value/remark without a numeric
  rating.
- `self_not_submitted` continues to fire when Self genuinely never submitted
  (no scores, no value, no remark, no `submitted_at`, no downstream score).
- Final-score immutability and POLICY §88 guarantees are unchanged because
  the change is upstream of every write branch.
- Skip-reason taxonomy (POLICY §111.6) widens the *definition* of
  `self_not_submitted` but adds no new reason key.

## Rejected alternatives

1. **Silently coerce `NULL` self_score → 0 on bulk write** — hides genuine
   data-quality issues; can stamp 0 into a final score later via the
   cascade.
2. **Block Auditor stage entirely for Org KPIs** — contradicts ADR-067; the
   Data-Owner propagation model exists *because* the Auditor must score
   propagated values.
3. **Lift the guard altogether** — re-opens the regression where bulk writes
   could land on a row that Self has never touched.

## Rollback

`CREATE OR REPLACE` is reversible — re-run the function body from migration
`20260629090420_*.sql`. No data shape change → zero-cost rollback.

## Tests

`src/test/bulkWriteStageScoresSelfSubmittedGuard.test.ts` is a TS mirror of the
predicate covering all branches plus the exact V.A.V.S.S./Jyoti row that
triggered the bug.
