# ADR-322 — Group KPI editor: a real scope dropdown, its target, and data-entry owners

**Status:** Accepted · 2026-08-26

## Context

The Performance Console's group definition editor exposed the scope as a free-text
`Input` ("e.g. organization, business_unit, department"). A typo silently wrote an
invalid scope word, and the grouped scopes shipped in ADR-320 could not be used at
all because their target id (which business unit, which location) had nowhere to be
entered. Choosing who may enter a central value still meant leaving the dialog.

## Decision

1. **Scope is picked, never typed.** The `Input` is replaced by a `Select` fed from
   the SSOT vocabulary in `src/lib/review/kpiScope.ts` (ADR-319).
2. **A grouped scope names its target in the same dialog** via the ADR-320
   `ScopeTargetPicker`, which shows the live reach before anything is saved.
3. **Only the five grouped dimensions carry a target column on a `kpis` row** —
   `business_unit_id`, `location_id`, `division_id`, `pms_grade_id`, `level_id`.
   `department` and `employee` resolve from the row's own employee, matching the
   `kpis_scope_target_check` constraint, so those columns are never rewritten by a
   group edit. New client SSOT: `KPI_ROW_SCOPE_TARGET_COLUMNS` /
   `rowScopeNeedsTarget`; server mirror: `public.bu_console_scope_target_column()`.
4. **Server enforcement.** `bu_console_editable_fields()` whitelists the five target
   columns; `bu_console_validate_changes()` refuses an unknown scope word, a grouped
   scope with no target, a foreign target travelling with a scope, and a target that
   resolves to zero active employees.
5. **Data-entry owners are edited inline** (`GroupDataOwnersField`). Ownership is
   period-agnostic (category + KRA + KPI name), so it is written immediately and is
   deliberately outside the monthly "Apply to" change set.

## Consequences

- Additive: no column created, altered or dropped; existing KPIs are untouched.
- A scope change now travels through the same preview → confirm → audit path as any
  other group edit.
- Rollback: revert the two functions and the dialog; rows keep their target column.
- Tests: `src/lib/review/kpiRowScopeTarget.test.ts` (4 cases).
