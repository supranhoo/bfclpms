# ADR-183 — Workflow supersede must not rewind past already-actioned stages

- Status: Accepted
- Date: 2026-07-27
- Policy: POLICY §AR-SUPERSEDE-NO-FALSE-REWIND

## Context

On 2026-07-27 (16:17–16:25) an admin removed the `bu_head` stage from ten
annual review instances via **Admin → Progress → Edit workflow & reviewers**
(supersede mode). The BU Head (101969) was inactive; the ADR-173 succession
sweep had repointed the stage earlier that morning, and the admin chose to drop
the stage entirely instead.

All ten instances already had a **locked, submitted `dept_head` response**.
After the edit they showed `overall_status = pending_dept` with
`total_score`, `criteria_weighted_score`, `final_rating` and `finalized_at`
all NULL — i.e. the final approval visibly disappeared.

## Root cause

The supersede branch of
`set_annual_review_enabled_stages(uuid, jsonb, text, text)` resolved the new
status as:

```sql
SELECT ... FROM jsonb_array_elements_text(p_enabled_stages) s
 WHERE lower(s) <> 'self' LIMIT 1;
```

— the first non-`self` enabled stage in arbitrary JSON order, with **no check
for existing locked responses** — and then unconditionally nulled every
aggregate. Removing a *downstream* stage therefore rewound the review onto an
*upstream* stage that was already complete.

## Decision

1. Supersede resolves the new status as the first enabled stage, **in canonical
   order** (`self → manager → skip_manager → dept_head → bu_head → hr →
   management`), that has **no locked response**.
2. If every enabled stage is actioned, the instance is terminal: status becomes
   `completed` and the aggregates are **recomputed** via
   `annual_review_compute_final_summary`, not erased.
3. Aggregates are cleared only when the resolved status is a real `pending_*`.
4. Archiving of responses belonging to removed stages is unchanged.

## Repair

Seven instances with scored responses were finalised from the existing Dept
Head submission (100759, 101200, 101961, 101997, 102008, 102009 → Good;
200449 → Poor 31). Three narrative-only instances with empty
`criteria_scores` (100890, 101942, 101959) were deliberately **not** finalised
— stamping 0/"Poor" would be wrong; the Dept Head must score them.
Before/after state is logged in
`public.annual_review_bu_removal_repair_2026_07`.

## Consequences

- Admins can drop a trailing stage on an approved chain and the review stays
  Completed with a correct score.
- `mem/features/annual-review/supersede-no-false-rewind.md` records the rule.

## Rollback

Re-deploy the previous function body (see migration
`20260727163202_*.sql` for the current one) and, if required, restore the ten
instances from `annual_review_bu_removal_repair_2026_07`.
