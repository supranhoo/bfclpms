# ADR-218 — Bell Curve Analysis in the Annual Review Report

Date: 2026-08-01
Status: Accepted

## Context
Leadership needs to see whether annual ratings follow the expected normal
distribution, spot lenient or harsh departments and managers, and act before
increments are released. The report so far only listed employees; distribution
had to be rebuilt by hand in Excel each cycle.

## Decision
1. Ratings are read from the ADR-212 SSOT (`toRatingOutOf5(total_score)`) and
   banded to 1..5 by nearest integer. No new scoring path is introduced.
2. Target distribution and compliance thresholds are master data in
   `public.annual_review_bell_curve_config`: one global default row plus optional
   cycle-scoped overrides. Read: authenticated. Write: Admin / HR PMS.
3. `src/lib/annualReview/bellCurve.ts` is the single pure calculation layer
   (banding, distribution, summary, grouping, heatmap, normal-curve overlay,
   normalization hints), shared by the dashboard and both exports.
4. A new "Bell Curve" tab in the Annual Review Report renders KPI cards, the
   bell curve overlay, an actual-vs-target bar chart, a variance table, a
   group heat map with drill-down filtering, and normalization recommendations.
   It reuses the already-paged comprehensive dataset — no extra RPC.
5. Managers and skip-level reviewers are scoped to their own reporting line;
   HR/Admin/Management see the whole cycle. Targets are always org-level.
6. Exports are tab-local (`bellCurveExport.ts`, Excel + PDF). The report's
   existing download is untouched, per the "front UI only" requirement.

## Consequences
- One additive config table; no existing data mutated.
- Target changes take effect immediately (React Query, 5 min stale time).
- Rollback: drop the tab trigger and the config table; nothing else depends on it.

## Guards
`src/test/annualReview/bellCurve.test.ts` (14 cases). POLICY §AR-BELL-CURVE.

## Addendum — ADR-218a (2026-07-31): KRA / Non-KRA scoring source filter

The tab gained a **Scoring Source (KRA)** dropdown (*With KRA* / *Blended* /
*Without KRA*). The value is derived from the comprehensive report's existing
`scoring_mode` column, falling back to `kra_weight > 0` when that text is
absent, so every employee belongs to exactly one bucket. Blended employees stay
their own bucket rather than being folded into either pure one.

SSOT: `scoringSourceOf` / `matchesScoringSource` in
`src/lib/annualReview/bellCurve.ts`. Presentation-only: no schema, RPC or RLS
change; the filter narrows every chart, table and tab-local export, and the
exports record the active selection. Guards: 5 extra cases in
`src/test/annualReview/bellCurve.test.ts`.

## Addendum — ADR-218b (2026-07-31): Band mode switch (Rating bands ↔ Slab %)

The tab gained a **Band mode** switch: *Rating bands (1–5)* (default, unchanged)
and *Slab %*, which buckets the same population by the ADR-212 increment slab
resolved from the /5 rating.

`bellCurve.ts` now exposes a mode-agnostic banding layer — `BandMode`,
`BandDef`, `makeBanding(mode, config, slabs)`, `computeBands`, `summarize`,
`groupBands`, `heatmapBands` and the generic `DistRow`. The legacy rating-only
helpers (`computeDistribution`, `computeSummary`, `groupDistribution`,
`heatmapMatrix`) are thin wrappers over the generic layer, so rating-mode
output is byte-identical.

Slab bands carry no targets: `targetPct`, `targetCount`, `variancePct` and
`compliance` are `null` and the UI omits those columns, the compliance chips,
the normalization card and the target curve rather than rendering zeros. Slabs
come from `useAnnualReviewRatingSlabs()` and fall back to the seeded defaults
when the master is empty. Presentation-only: no schema, RPC or RLS change; the
mode applies to every chart, table and tab-local export, and the exports record
it. Guards: 5 extra cases in `src/test/annualReview/bellCurve.test.ts`.

## Addendum — ADR-218c (2026-07-31): Heat map cell drill-down

Clicking a heat map cell expands the employees behind that cell in an inline
row directly under the clicked group, for both rating and slab band modes.

`employeesInBand(rows, groupKey, groupId, banding, bandKey)` in
`src/lib/annualReview/bellCurve.ts` is the SSOT for the list: it reuses
`ratedRows` (excluded/unrated filtering) and `banding.keyOf`, guaranteeing
list length === cell count in either mode. `RatingHeatmap` turns cells into
buttons and renders an optional `renderDrilldown(rowId, bandKey, close)` slot;
`BandEmployeeList` provides search, 25-row pagination and a CSV export of the
filtered list. Cell click no longer toggles row selection — selection stays on
the checkbox and the group name. Expansion resets on view / band-mode / filter
change via `drilldownResetKey`.

Presentation only: no schema, RPC, RLS or network change (the tab's existing
comprehensive dataset backs the panel). Guard:
`src/test/annualReview/bellCurveDrilldown.test.ts` (6 cases).
