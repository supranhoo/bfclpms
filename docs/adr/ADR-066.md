# ADR-066 — Fix `bulk_management_approve` enum casts

**Date:** 2026-05-31
**Status:** Accepted
**Trigger:** Admin saw "Approval failed — invalid input value for enum kpi_status: 'approved'" on every Management Bulk Approve / Admin Bulk Override since ~2026-05-27.

## Context
`public.bulk_management_approve(...)` was written with two broken enum tokens:

- `kpi_status = 'approved'::kpi_status` — `public.kpi_status` enum only contains `open | submitted | approved_by_manager | locked`. `'approved'` is not a member, so Postgres aborts the transaction.
- `kpis.status = 'approved'::workflow_stage` (and the matching `<> 'approved'::workflow_stage` drift check) — type `workflow_stage` does not exist. The canonical type for `public.kpis.status` is `public.review_status` (see ADR-059).

Every other final-stage writer in the codebase (see all `20260313…`, `20260324…`, `20260325…` migrations) terminally sets `review_submissions.kpi_status = 'locked'`. Polluting the `kpi_status` enum with a new `'approved'` value would contradict that convention and break the existing drift / lock guards.

## Decision
`CREATE OR REPLACE` the function with two surgical changes inside the existing body — signature, RLS gate, audit-log writes, override/skip logic, and return shape are unchanged:

1. `kpi_status = 'approved'::kpi_status` → `kpi_status = 'locked'::public.kpi_status`.
2. Both `'approved'::workflow_stage` casts (UPDATE + drift guard) → `'approved'::public.review_status`.
3. The post-write drift check at the tail of the function now compares against the same corrected values.

No enum alteration, no schema change, no data backfill.

## Consequences
- Management Bulk Approve and Admin Bulk Override Final Stamp work again.
- Terminal `kpi_status` written by the bulk path is now `'locked'` — identical to the per-cell approval writers, so dashboards / `kpi_status`-based filters stay consistent.
- Source-level guard `src/test/bulkManagementApproveEnumGuard.test.ts` asserts no migration ever reintroduces `'approved'::kpi_status` or `::workflow_stage`, and that the latest `bulk_management_approve` body uses the corrected casts.

References: ADR-059, POLICY §88.1.
