# ADR-307 — Observation evidence resolves its context before KPI authorization

Date: 2026-08-21
Status: Accepted; supersedes ADR-305's generic RLS/session diagnosis
Related: ADR-256, ADR-303, ADR-305
Policy: POLICY §EVIDENCE-CONTEXT-RESOLUTION

## Context

Jitendra Bharti (101715) still could not attach an observation reply after refresh and re-login. The real path was `<user-id>/<observation-id>/observation-replies/<unique-file>`, while the consolidated private-file read policy treated every second segment as a KPI id. For OBS-02854 the observation and KPI ids are different. `upsert: true` also requested overwrite semantics for a unique filename, introducing read/update authorization that a create did not need.

## Decision

1. `public.can_read_evidence_context(context_id, folder)` resolves observation folders through `kpi_observations.kpi_id`, then falls back to a direct KPI id for legacy paths and ordinary evidence.
2. The canonical private `review-evidence` SELECT policy delegates to that resolver and then to the existing KPI-participant authorization. The resolver is `SECURITY INVOKER`, has a fixed search path, and is unavailable to PUBLIC/anon.
3. Unique timestamped evidence uploads are create-only (`upsert: false`).
4. A valid-session RLS denial is reported as an authorization/configuration problem. “Sign in again” is reserved for an absent live session.

## Consequences

- Existing observation-id and legacy KPI-id objects remain in place and become readable through one contract.
- No role, participant rule, object owner, bucket privacy, or evidence row is widened or changed.
- The context lookup is bounded by primary-key indexes.
- Rollback restores the previous SELECT policy and uploader option; no data rollback is required.
