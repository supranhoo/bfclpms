# ADR-049: Admin Step-Back Target Selection, Full Reset & Sibling Reversion

## Status
**Accepted**

## Date
2026-04-01

## Context
Admins needed flexible rollback capabilities: selecting any prior stage (not just the immediate previous), fully resetting KPIs, and handling multi-month sibling consistency.

## Decision
- **Target selection:** Admin can select any preceding workflow stage, including `kra_set`
- **Full reset:** "Clear all review data" nullifies ALL submission fields and resets to `kra_set` with `kpi_status = 'open'`. Audit action: `ADMIN_FULL_RESET`
- **Sibling reversion:** Approved multi-month KPIs stepped back automatically revert all sibling months to the same target stage. Audit action: `SIBLING_STEP_BACK`

## Alternatives Considered

### Alternative A: Allow step-back only to immediate previous stage
- **Description:** Restrict rollback to one stage at a time
- **Rejected because:** Forces admins to perform multiple sequential rollbacks to reach earlier stages. Inefficient for cases where data entry errors occurred at the beginning.

### Alternative B: Leave sibling months in approved state after step-back
- **Description:** Only revert the specific month being stepped back
- **Rejected because:** Creates inconsistent state — the terminal month is rolled back but siblings remain approved with now-stale percolated scores.

### Alternative C: Auto-delete sibling records on step-back
- **Description:** Remove sibling month KPI records entirely
- **Rejected because:** Destructive — removes audit trail and prevents re-approval without re-creation.

## Consequences

### Positive
- Flexible, efficient admin rollback capabilities
- Multi-month consistency maintained

### Negative
- Full reset is destructive (mitigated by confirmation checkbox and mandatory reason)

### Neutral
- Employee receives notification with reason and transition details
