# ADR-323 — Automatic field-aware group definition edits

**Status:** Accepted · 2026-08-26

## Context

ADR-321 introduced a safe descriptive-only backend path, but left activation to
an optional UI switch that reset off whenever the group editor opened. The UI
already classified Title + Description correctly, yet preview still sent the old
guarded mode and reported locked/in-review rows as skipped.

## Five Whys and root cause

1. Rows skipped because the request sent the descriptive flag as false.
2. It was false because classification only revealed a separate opt-in switch.
3. The switch existed because the first correction was modelled as an exception,
   not as normal field-aware behavior.
4. Tests covered classification and month spans independently, not the activation
   contract between them.
5. Client classification and server execution could therefore disagree.

The root cause was duplicated decision-making: the system knew the fields were
safe, but still required the operator to activate that known classification.

## Decision

- `bu_console_group_edit_definition` derives the edit class from `p_changes` and
  `bu_console_descriptive_fields()` on every preview and commit.
- Admin descriptive-only edits automatically bypass workflow/final-score row locks.
  Mixed edits use the strict protected path.
- Formula and Scoring Logic are explanatory text. Structured target, KPI/UOM type,
  threshold, options, rating bands, weightage, frequency/cycle and day count remain
  the scoring source of truth.
- Descriptive group standardisation is canonical and is not removed by stale
  per-employee descriptive override markers. Protected overrides remain protected.
- The UI shows the derived safety state instead of a switch, and distinguishes
  updates, protected skips and months with no KPI assignments.

## Consequences

No score, score input, workflow status or review submission is changed by the
descriptive path. Existing per-month audit and undo records remain intact. The
legacy RPC parameter remains only for call compatibility; it cannot widen access.

Rollback is function/UI restoration only; committed runs remain individually
undoable. Regression coverage pins every descriptive field, protected fields and
mixed changes.
