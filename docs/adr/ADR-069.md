# ADR-069: Increment "Eligibility Criteria" renamed to "Ineligibility Criteria"

- Status: Accepted (May 2026)
- Context: Admins repeatedly mis-read the module as "rules an employee must satisfy to be eligible" when in fact every row is a disqualification rule (breach ⇒ ineligible, eligible % = 0). The confusion was compounded by the exempt-list label ("Criteria-Exempt Employees") and the Run Details column header.
- Decision: Rename all user-facing strings to **Increment Ineligibility Criteria** / **Add Ineligibility Criterion** / **Ineligibility Criteria Exempt Employees**. Engine logic is unchanged — it already iterates `criteria[]` generically, so any future criterion added via this module automatically participates as an ineligibility rule. Internal table and column names (`increment_eligibility_criteria`, `increment_eligibility_configs`, `increment_eligibility_exclusions`, `ineligibility_reason`) are NOT renamed to preserve audit history, version history, RLS policies, and edge-function compatibility.
- Export wording: the Run Details table and Excel export now blank the `ineligibility_reason` column when `eligibility_status = 'no_score'`. PMS-missing is a required-data issue tracked in its own `no_score` bucket, not an ineligibility-criterion breach.
- Consequences: Pure presentation change; rollback is reverting the touched files. Historical run items remain reproducible because the engine criteria loop is untouched.
