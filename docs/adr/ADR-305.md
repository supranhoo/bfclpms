# ADR-305 — Evidence uploads bind to the live session identity

Date: 2026-08-21
Status: Accepted
Related: ADR-118 (proxy evidence RLS), ADR-256 (evidence read parity), ADR-303 (preview authorization plan)
Policy: POLICY §EVIDENCE-UPLOAD-SESSION-BOUND-IDENTITY

## Context

Jitendra Bharti (101715) could not attach a file to an observation reply: the
upload failed with `new row violates row-level security policy`.

Verified facts:

- Reply attachments go to the private `review-evidence` bucket at
  `<user-id>/<observationId>/observation-replies/<timestamp>_<name>.<ext>`.
- The only matching storage INSERT policy is `Users can upload their own
  evidence files`: `bucket_id = 'review-evidence' AND auth.uid()::text =
  (storage.foldername(name))[1]`.
- The bucket has no size or MIME restrictions (2 MB / JPEG-PNG-PDF-Excel are
  client-side rules only), so those cannot produce this error.
- The folder has 466 historical objects and other users uploaded successfully
  the same day, so neither the folder nor the policy is globally broken — the
  failure is actor/session specific.
- `MultiFileUpload` built the folder prefix from the in-memory React `user`
  object, never from the live session.

## Decision

Bind the upload path to the identity the request will actually carry.

1. `src/lib/evidenceUpload.ts` is the SSOT: `resolveUploadIdentity()` reads
   `supabase.auth.getSession()` and returns the live user id plus whether it
   matches cached React state; `buildEvidenceFilePath()` builds the path;
   `isRlsDenialError()` / `describeUploadFailure()` classify failures.
2. `MultiFileUpload` resolves identity immediately before each upload, aborts
   with a clear message when there is no session, and logs a warning when the
   live id differs from the cached one.
3. On an RLS denial the component refreshes the session once and retries the
   upload with the refreshed identity before failing.
4. The failure toast reads "Sign in again to attach files" for RLS denials,
   keeping the raw Postgres reason appended for support.
5. `AuthContext` treats `TOKEN_REFRESH_FAILED` (or a refresh that yields no
   session) as a hard sign-out, so a stale `user` object can no longer outlive
   a dead token.

## Consequences

- No storage policy is loosened; the bucket stays owner-scoped.
- All surfaces sharing `MultiFileUpload` (self, reviewer, auditor, management,
  observations, bulk approval) inherit the fix; the happy-path filename format
  is unchanged and covered by tests.
- Rollback: revert `src/lib/evidenceUpload.ts`, the `MultiFileUpload` upload
  block, and the AuthContext guard — independent of any other feature.

## Regression

`src/lib/__tests__/evidenceUpload.test.ts` — 9 tests (path prefix from session
id, sanitisation/truncation, RLS classification, message mapping, no-session
abort, cached-vs-live mismatch flag).
