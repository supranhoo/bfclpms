# ADR-319 — One scope vocabulary for KPIs

**Status:** Accepted · 2026-08-26

## Context

The Performance Console's "New KPI for this scope" dialog offered three cards —
Individual / Shared value / Department event — while the rest of the product
already spoke of scopes: Organization / Department / Employee, with Division,
Business Unit, Location, PMS Grade and Level marked "coming soon".

They were the same concept. `bu_console_kpi_create` translated the three cards
straight back into the existing columns:

| Card | Columns written |
|---|---|
| Individual | `is_org_level=false`, `org_level_scope='organization'` |
| Shared value | `is_org_level=true`, `org_level_scope='organization'` |
| Department event | `is_org_level=true`, `org_level_scope='department'` |

A third column, `kpi_group_type`, was also written and read by nothing — it is
`individual` on all 20,718 rows.

## Decision

One vocabulary, one model, two columns (POLICY §KPI-SCOPE-SINGLE-VOCABULARY):

- `src/lib/review/kpiScope.ts` owns the scope list, copy and the
  `toKpiColumns` / `fromKpiColumns` mapping. The create dialog and the
  scope-change menu both import it.
- The create dialog shows the four live scopes plus the planned scopes as
  disabled chips, matching the existing scope menu.
- `bu_console_kpi_create` accepts `scope` (still accepting the legacy `kind`),
  writes only `is_org_level` / `org_level_scope`, and no longer writes
  `kpi_group_type`.
- Individual KPIs now store `org_level_scope = NULL` instead of a phantom
  `'organization'`.

## Consequences

- No historical data rewritten, no column dropped; rollback is a revert of the
  function body.
- Adding a future scope (Division, BU, …) is a one-file change plus the
  cascade work, not a second vocabulary.
- Tests: `src/lib/review/kpiScope.test.ts` (7 cases) covers every scope →
  column mapping, the legacy aliases, the round trip and the fallbacks.
