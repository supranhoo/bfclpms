# ADR-042: Dynamic Program Configuration Tabs

## Status
**Accepted**

## Date
2026-03-30

## Context
Incentive programs needed extensible per-employee data entry capabilities (vessel rates, production targets, custom metrics). The question was whether to hardcode new tabs or make them database-driven.

## Decision
Configuration tabs are database-driven via `incentive_program_custom_tabs`. Core tabs (Mapping, Slabs, DQ Rules, Fields, BU Sub-Units, Allocation, Vessel Rates) remain hardcoded due to dedicated business logic. All new per-employee data entry needs must use the dynamic custom tab system.

## Alternatives Considered

### Alternative A: Hardcoded tabs in component
- **Description:** Add new React components for each data entry need
- **Rejected because:** Requires code deployment for every new tab. Cannot be customized per program. Violates the Zero-Hardcoding Rule.

### Alternative B: JSON configuration file
- **Description:** Store tab definitions in a config file
- **Rejected because:** Still requires deployment. No admin UI. Cannot vary per program.

## Consequences

### Positive
- Admins can add custom tabs without developer intervention
- Tab schemas stored in JSONB allow flexible field definitions

### Negative
- Custom tabs have generic rendering (no specialized business logic)

### Neutral
- Core tabs retained for complex, dedicated UIs
