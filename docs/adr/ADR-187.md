# ADR-187 — Final score scale invariant for annual reviews

- Status: Accepted
- Date: 2026-07-27
- Policy: §AR-FINAL-SCORE-SCALE-INVARIANT

## Context

42 completed FY2026-07 annual reviews displayed an inflated or missing final
score. Verified in the database:

- 41 instances stored `total_score` equal to `criteria_weighted_score` — the
  **raw** Σ(weight × score) sum (255 … 450) — instead of the normalised 0–100
  appraisal score. System-score points (7–19 pts) were also missing from the
  total.
- All 42 had a blank `final_rating`, so no rating band rendered anywhere.
- The 42nd (100638, Lakhee Kant Mahto) had a correct total (79.60) but a blank
  band.

Blast radius was exactly 41 / 2,019 completed instances with `total_score > 100`
and 42 with a blank rating. All 41 were finalised on 18-Jul and 20-Jul and
share an identical `updated_at` of `2026-07-24 12:19:03.863653+00` — a single
bulk repair script rewrote the field.

## Five Whys

1. The final score is wrong — `total_score` holds a raw weighted sum.
2. It holds a raw sum — a 24-Jul bulk repair copied `criteria_weighted_score`
   into `total_score`.
3. It copied — the script did its own arithmetic instead of calling
   `annual_review_compute_final_summary`.
4. That was allowed — no invariant constrained `total_score` range or required a
   rating band on a completed review.
5. No invariant — ADR-126 repaired the then-known rows but added no permanent
   guard, so any later write path could reintroduce the defect.

## Decision

1. `annual_review_instances.total_score` is **always** a normalised 0–100 value.
   `criteria_weighted_score` remains the raw weighted sum and may exceed 100.
   The two must never be conflated.
2. `public.annual_review_compute_final_summary(instance_id)` is the sole source
   of truth for `total_score` and `final_rating`. No script or RPC may compute
   them independently.
3. Trigger `trg_ar_total_score_scale` (BEFORE INSERT/UPDATE OF `total_score`,
   `final_rating`, `overall_status`) raises `check_violation` for any score
   outside 0–100, and auto-stamps the band via
   `annual_review_resolve_final_rating` when a completed instance carries a
   score but no rating.
4. `src/lib/annualReview/finalScoreScale.ts` mirrors the server rules for
   client display and drift classification.
5. `FinalScoreIntegrityCard` (rendered above the Orphaned Reviews console)
   surfaces a live count of out-of-range / missing-band completed reviews.

## Repair

All 42 instances were recomputed from
`annual_review_compute_final_summary`. Pre-images are stored in
`annual_review_final_score_repair_2026_07` (admin read-only, RLS enabled).
Post-repair verification: 0 completed instances with `total_score > 100`, 0
with a blank rating.

Examples: 101755 → 92.00 Outstanding (was 370), 101909 → 97.00 Outstanding
(was 450), 100323 → 67.00 Average (was 255).

## Rollback

```sql
UPDATE public.annual_review_instances i
   SET criteria_weighted_score = r.old_criteria_weighted_score,
       total_score             = r.old_total_score,
       final_rating            = r.old_final_rating
  FROM public.annual_review_final_score_repair_2026_07 r
 WHERE r.instance_id = i.id;   -- requires dropping trg_ar_total_score_scale first
DROP TRIGGER trg_ar_total_score_scale ON public.annual_review_instances;
```

## Consequences

- Reviewer answers, system scores and workflow state are untouched; only the
  derived score and band changed.
- Downstream consumers (increment / incentive eligibility) that already read the
  inflated totals for these 42 employees need recomputation — flagged to the
  business, not executed automatically.
- Regression coverage: `src/test/annualReview/finalScoreScale.test.ts`.
