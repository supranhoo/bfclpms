# ADR-352 — QualitativeSelect is container-driven, not a fixed 140px box

Date: 2026-09-03 · Status: Accepted

## Context

On Admin → Org KPI Data Entry, the tiered rating control for "Achieve 3X100 TPD
Power Generation target" painted its selected option text over the status chips,
the Remark field and the card body (screenshot, 3 Sep 2026).

`src/components/review/QualitativeSelect.tsx` hardcoded `w-[140px]` on the
trigger, and the selected-value content was a flex row with an unconstrained
`<span>`. Callers additionally pass `h-9`, so the control was pinned at
140×36px while real tiered labels ("90% – 94.99% Achievement (of the 5%
Incentive Target)") are several times longer — the text wrapped and escaped the
box in every direction.

## Decision

- Trigger width is container-driven: `cn('w-full min-w-0', className)`. Callers
  keep full override control; table cells stay narrow, wide cards use the space.
- Selected label truncates on one line (`min-w-0` flex + `truncate`) with the
  full text exposed through the trigger's `title` attribute.
- Dropdown items wrap (`whitespace-normal leading-snug`) instead of clipping;
  popover capped at `max-w-[min(28rem,90vw)]`; rating badges are `shrink-0`.
- Rating badge text switches from hardcoded `text-white` to the semantic
  `text-primary-foreground` token.

## Consequences

Display-only. `onChange(label, rating)` and all scoring paths are untouched; no
schema, RPC, RLS or query-key change. Rollback = revert the one component file.

Tests: `src/test/qualitativeSelectLongLabel.test.tsx` (2).
