# ADR-058 — Drop legacy `preview_org_kpi_propagation(uuid[])` overload

**Date:** 2026-05-06
**Status:** Accepted
**Trigger:** Ankan saw a red toast "Could not preview propagation — could not choose the best candidate function between public.preview_org_kpi_propagation(p_kpi_ids ⇒ uuid[]) and public.preview_org_kpi_propagation(p_kpi_ids ⇒ uuid[], p_new_value ⇒ numeric, p_new_self_score ⇒ numeric, p_overwrite_policy ⇒ text)" when clicking Propagate on the IT Awareness KPI.

## Context
ADR-053 introduced `preview_org_kpi_propagation(uuid[])`. ADR-054 added the richer `(uuid[], numeric, numeric, text)` form with all-default params but never dropped the legacy one. PostgREST cannot disambiguate because the new params all carry defaults — both signatures match a 1-arg call, and even a 4-arg call is rejected by Postgres' overload resolver as ambiguous.

## Decision
Drop `public.preview_org_kpi_propagation(uuid[])`. The 4-argument form is a strict superset and is the only signature any frontend caller uses (`src/hooks/usePreviewOrgKpiPropagation.ts` always passes all four params).

## Consequences
- Propagate dialog opens cleanly again for all data owners and admins.
- Future migrations must NOT re-introduce a single-arg overload — keep exactly one `preview_org_kpi_propagation` definition.
- Guard test: `src/test/orgKpiPreviewOverloadGuard.test.ts` documents the expected single-overload contract.

Reference: ADR-053, ADR-054.
