# ADR-030: Org KPI Audit Log Completeness

## Status
**Accepted**

## Date
2026-03-30

## Context
The Value History popover is the primary audit trail for org KPI data changes. Every mutation to `org_kpi_values` needs a corresponding log entry to maintain accountability.

## Decision
Every mutation to `org_kpi_values` must write a corresponding entry to `org_kpi_data_entry_logs`. Actions include: `created`, `updated`, `propagated`, `rollback`, `unlocked`, `imported`, `copied_from_previous`. Any new mutation path must include an audit log write.

## Alternatives Considered

### Alternative A: Client-side-only logging
- **Description:** Write audit logs from the frontend after successful mutations
- **Rejected because:** Unreliable — network failures, browser crashes, or direct API calls bypass client-side logging. Also bypassable by malicious actors.

### Alternative B: Periodic reconciliation batch job
- **Description:** Run a scheduled job to detect unlogged changes by comparing snapshots
- **Rejected because:** Cannot reconstruct who made the change or when; introduces delay between change and audit visibility.

## Consequences

### Positive
- Complete audit trail for all org KPI mutations
- Value History popover always reflects actual changes

### Negative
- Every new mutation path requires remembering to add audit logging

### Neutral
- Existing history gaps cannot be backfilled — only new operations are logged going forward
