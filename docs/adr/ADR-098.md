# ADR-098 — Bulk reviewer sign-off mirrors achievement onto `<stage>_achieved_value`

**Date:** 2026-06-29
**Status:** Accepted
**Trigger:** After an Admin Auditor bulk override stamped achievement **5** with score 2 on Jitendra Kumar Dwivedi / "Power generation from 45 MWh/AFBC" / May 2026, the Review Journey "Auditor" card still rendered **Value 2.5 / Rating 2**.

## Context

POLICY §88 freezes the per-stage snapshot the moment each reviewer scores. The Review Journey UI honours that contract: every reviewer card reads `<stage>_achieved_value` (its own frozen column), never the shared mutable `achieved_value`. Downstream reviewers can overwrite `achieved_value`, so the per-stage column is the only safe read.

`public.bulk_write_stage_scores` updated `achieved_value`, `<stage>_score`, `<stage>_rating`, `<stage>_remarks`, and `<stage>_evidence_urls`, but never wrote `<stage>_achieved_value`. The per-stage column kept whatever the prior draft saved (or stayed NULL), so the reviewer card diverged from the score the same RPC stamped. The sibling RPC `bulk_management_approve` (per ADR-067 / §88.1) already mirrors correctly; `bulk_write_stage_scores` was missed when that mirror policy was introduced.

Concrete row (`d82ed5d5-7e52-4583-9cc8-09cbb3fc178c`) before fix:
- `achieved_value = 5.00`
- `auditor_score = 2`, `auditor_rating = red`
- `auditor_achieved_value = 2.5` ← stale, never updated by the override
- `auditor_remarks = "As per approval by Management"`

## Decision

1. **Mirror in `bulk_write_stage_scores`.** Each of the five reviewer-stage UPDATE blocks (manager / functional_manager / skip_level / hr_pms / auditor) now sets `<stage>_achieved_value = COALESCE(v_achieved_num, v_cur.achieved_value)` in the same UPDATE that writes the score. N/A branches set the per-stage column to NULL for parity. `BULK_STAGE_SIGNOFF_<STAGE>` audit rows now carry `mirrored_achieved_value` in `new_value` and `policy = '§88.1.d / ADR-098'` in `metadata`.
2. **One-off backfill.** For every group-bulk-stamped row that is NOT yet `final_score`-locked, the per-stage achieved column is resynced to the row's top-level `achieved_value`. Each fix inserts a system audit row `BULK_STAGE_ACHIEVED_MIRROR_BACKFILL_<STAGE>` (`performed_by = NULL`, `policy = '§88.1.d / ADR-098'`). Frozen finals are deliberately skipped per §88 immutability — those will be visually corrected only after a fresh override.
3. **POLICY §88.1.d** captures the new invariant: every RPC that bulk-stamps `<stage>_score` MUST also write `<stage>_achieved_value` in the same UPDATE.

## Consequences

- Reviewer cards (Manager / Functional Manager / Skip-Level / HR PMS / Auditor) now reflect the achievement the override stamped instead of a stale draft value.
- No change to enums, status, final-score immutability, or any other branch of the RPC. `bulk_management_approve` was already correct (ADR-067) and is unchanged.
- Backfill is non-destructive — it only sets a per-stage column equal to a value the same RPC already computed against.
- Source-level guard `src/test/bulkWriteStageScoresAchievedMirror.test.ts` introspects the live function body and asserts each reviewer-stage UPDATE writes `<stage>_achieved_value`, so a future migration that drops the mirror fails CI.

References: ADR-067, POLICY §88, §88.1, §88.1.d, `mem/features/review/self-snapshot-display.md` Part 4.
