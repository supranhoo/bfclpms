# ADR-284 — Performance Console access tiers + Review Pipeline

Status: Accepted · 2026-08-16

## Context
The Performance Console was reachable by `admin` only, even though the server
read gate (`bu_console_can_read`) already admits `management`, `auditor` and
`hr_pms`. Every console write RPC (`bu_console_apply_kpi_changes`,
`bu_console_bulk_row_overrides`, `bu_goal_upsert`, merge decisions) enforces
`has_role(uid,'admin')`. The console also had no view of where review work is
actually waiting, which was the original reason for building it.

## Decision
1. **Access tiers.** Route and sidebar now admit `admin`, `management`,
   `auditor`, `hr_pms` (plus profile-based menu access via
   `menuKey="admin-bu-console"`). `useBuConsoleCapability()` mirrors the server
   write contract: `canWrite` is admin (or an explicit `update` right on the
   console menu key). Non-writers get an honest read-only surface — the group
   action bar, per-row **Tune**, KRA tree row actions, **New KRA**, the
   duplicate scan and merge decisions are hidden, not merely failing on submit.
2. **Review Pipeline.** New `bu_console_pipeline(period, year, bu/dept/division/
   manager, stage, page, page_size)` SECURITY DEFINER RPC returns per-stage
   pending counts (items + **distinct** people, POLICY §CONSOLE-DISTINCT-PEOPLE)
   and a server-paged employee list. Pending stage is derived from each
   employee's resolved workflow chain (`get_bulk_employee_workflows`, POLICY
   §105 — no hardcoded ladder) applied to `kpis.status` (last COMPLETED stage),
   with the same active-stage exceptions as `src/lib/bottleneckResolver.ts`
   (`audit`, `management_review`, `hr_pms_review`, `skip_level_check`,
   `functional_manager_check` stay with the current reviewer; `kra_set` means
   self review; a terminal reviewer keeps the item until `approved`).
   The tab is read-only for every tier and deep-links into the existing
   scorecard (`/dashboard?employee=&period=&year=`) where the normal RLS and
   stage rules apply.

## Consequences
- No new write path and no RLS change: the widened UI cannot exceed what the
  server already allows.
- Pipeline reads are paged (≤200 rows/page) and scope-bound; nothing loads
  before a scope is applied.
- Rollback: revert the route/sidebar role arrays and drop the tab; the RPC is
  additive and read-only.
