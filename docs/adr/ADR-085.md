# ADR-085 — Add New User: surface real edge-function errors + scrollable dialog

Date: 2026-06-10
Status: Accepted

## Context

Two defects in the Admin → User Management → Add New User flow:

1. **Opaque error toast.** Creating "Brundaban Chandra Das" (`102028`, `brundaban.das@bfclalloys.com`) failed with the generic toast *"Failed to create user — Edge Function returned a non-2xx status code"*. The `create-employee` edge function returns structured `{ error }` JSON (e.g. "A user with this email address has already been registered", "Unknown employee category: 'X'"), but `supabase.functions.invoke()` discards the body on non-2xx responses, so admins cannot self-correct.
2. **Dialog clipping on short laptops.** At 1366×768 / 1280×800 the `DialogContent` (`max-h-[92vh]`) plus header + tabs + footer leaves the final Organization row (Employment Status / Location / Reporting Manager) and the Create User button outside the visible area. The inner Radix `ScrollArea` does not render a visible scrollbar, so users resort to browser zoom-out.

## Decision

1. Route `create-employee` through the existing `invokeAdminEdgeFunction` raw-`fetch` helper. It parses the JSON body and throws `Error(payload.error)` on non-2xx, which the existing `onError` toast already surfaces. Same pattern already used for `password-rollout` and `update-user-email`.
2. Replace the Radix `ScrollArea` wrapper in both the Add User and Edit User dialogs with a native `<div … overflow-y-auto>` so a standard browser scrollbar is always visible.
3. Tighten the dialog height on short viewports: `max-h-[calc(100vh-2rem)] sm:max-h-[92vh]` lets the dialog use the full viewport (minus a 16 px gutter) on ≤768 px-tall screens while keeping the airier 92vh constraint on taller monitors.

## Out of scope

- No change to the `create-employee` edge function itself — its error contract is already correct.
- No change to field layout, ordering, master-data validation, or any other admin flow.

## Consequences

- Admins see actionable error messages (`"A user with this email address has already been registered"`, `"Unknown employee category: 'X'"`, etc.) instead of a generic non-2xx toast.
- Add User / Edit User dialogs are fully usable at 1280×720 and 1366×768 without browser zoom.
- Rollback: revert `src/pages/admin/UserManagement.tsx`. The ADR + test additions are safe to keep.

## Tests

- `src/test/userManagement.createUserError.test.ts` — asserts the real error body is thrown (regression guard for the Brundaban Chandra Das case).
- `src/test/adminEdgeFunction.test.ts` — existing contract for `invokeAdminEdgeFunction` still passes.
