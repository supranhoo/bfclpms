# ADR-233 — KRA sync drift visibility and in-flight coverage

- Status: Accepted (2026-08-03)
- Related: ADR-161 (KRA score rehydrate), ADR-232 (final score write-back), POLICY §88, §AR-KRA-REHYDRATE

## Context
Monthly scorecard corrections (re-scores, rollbacks, late approvals) kept landing after annual
review forms were already finalised. The Carry-KRA system score is a deliberate snapshot, so those
corrections never reached the appraisal. The re-sync tool from ADR-161 existed but was buried at the
bottom of the Access Control tab, had been run exactly once (a dry run on 26 Jul 2026, never
applied), and had no way to tell an admin that a re-sync was due.

Measured on the 2025-26 cycle: 137 of 2,086 completed instances use a KRA template, and **71 of
those 137** no longer matched the latest monthly KPI data.

## Decision
1. **Drift is measurable.** New `annual_review_kra_drift_summary(cycle_id)` returns the KRA instance
   count, drifted count, in-flight count and the timestamp of the last applied sync.
   `annual_review_kra_instance_drift(instance_id)` does the same for one review.
2. **Drift is visible.** The rehydrate card shows an amber/green drift banner; the review form's
   Carry-KRA card shows a per-review hint when the stored snapshot differs from the live value.
3. **In-flight coverage.** `annual_review_rehydrate_kra_for_cycle` gained
   `p_include_in_flight boolean DEFAULT false`. In-flight instances refresh `system_scores` only —
   totals and ratings stay workflow-derived — so reviewers who have not yet submitted see current data.
4. **Discoverability.** The card moved to its own **KRA Sync** tab in Annual Review Admin with an
   explainer of snapshot-vs-live behaviour.

## Consequences
- Apply remains a deliberate, reason-gated, fully reversible admin action; nothing recomputes silently.
- Client and server round to 2 dp via the same rule, so the banner and the RPC cannot disagree.
- Guard: `src/lib/annualReview/__tests__/kraDrift.test.ts`.
