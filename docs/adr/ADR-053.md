# ADR-053: Tiered overwrite policy for Org KPI propagation

- Status: Accepted (May 2026)
- Context: Re-pushing an Org KPI value did nothing once any child KPI had advanced past `kra_set`. Owners hit this whenever Self-Review opened and they wanted to correct a number.
- Decision: `propagate_org_kpi_value` accepts `p_overwrite_policy`:
  - `safe`  — legacy behaviour, only `kra_set` rows.
  - `pre_review_only` (default) — also overwrite `self_review` rows that have NOT been advanced by the employee.
  - `force_pre_terminal` — admin escalation; overwrite anything not in `manager_check / auditor_check / management_review / final / approved`.
- Audit: every overwrite emits `ORG_KPI_VALUE_OVERWRITTEN` to `kpi_audit_logs` with old/new self_score.
- Preview: `preview_org_kpi_propagation` mirrors the same policy and now returns `current_self_score` / `new_self_score` so the dialog can show per-employee Old → New diffs and a `reviewer_locked` count.
- Consequences: a re-push from Org KPI Data Entry now materialises for the typical case (employee not yet acted) without admin escalation. Reviewer-locked rows are visibly listed and skipped, never silently mutated.
