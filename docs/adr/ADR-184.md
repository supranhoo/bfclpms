# ADR-184 — Empty-stage repairs must not rewind past an actioned downstream stage

- Status: Accepted
- Date: 2026-07-27
- Policy: POLICY §AR-REPAIR-NO-DOWNSTREAM-REWIND

## Context

Sunil Ram (101361) and Sumit Kumar (102011) were reported as "pending Dept Head"
while their BU Head review showed complete.

Both run the chain `self → dept_head → bu_head`. Their Dept Head submitted a
**narrative-only** response (`criteria_scores` empty); the BU Head then scored
and locked (315 / 265 raw points) and both instances reached `completed`
(66.00 "Average" / 53.00 "Poor").

On 2026-07-27 04:15:08 the ADR-172 empty-stage repair sweep unlocked every
locked-but-unscored stage response and forced `overall_status = pending_dept`,
nulling `total_score`, `criteria_weighted_score`, `final_rating` and
`finalized_at`. It touched 30 instances (logged in
`annual_review_empty_stage_repair_2026_07`), 8 of which were already Completed.

## Root cause

The sweep evaluated each stage response in isolation. It never asked whether a
**later enabled stage** had already been actioned. ADR-172 is a *submission-time*
rule ("you cannot submit a scoreable stage with zero scores"); applying it
retroactively invalidated reviews whose authoritative score came from a
downstream stage. Same defect class as ADR-183, in a different code path.

## Decision

1. `overall_status` may never move to a `pending_*` stage while an enabled later
   stage holds a locked response. Enforced by trigger
   `trg_ar_no_downstream_rewind` on `annual_review_instances`, bypassable only
   through the `annual_review.bypass_downstream_rewind_guard` session flag.
2. When every enabled stage is actioned the instance is terminal: `completed`
   with aggregates **recomputed** via `annual_review_compute_final_summary`.
3. Repairs run through `public.annual_review_repair_downstream_rewind(uuid, text)`
   (admin / HR PMS, mandatory reason), which re-locks orphaned upstream
   responses at or below the last actioned stage, resolves the status and logs
   before/after into `annual_review_downstream_rewind_repair_2026_07`.
4. `public.annual_review_downstream_rewind_diagnostic()` lists violations and
   must return zero rows.

## Repair

Five instances still stuck were restored to `completed` with their original
scores: 101029 (14.00 Poor), 101230 (11.00 Poor), 101323 (0.00 Poor),
101361 (66.00 Average), 102011 (53.00 Poor). 101199, 101751 and 101982 had
already been re-completed. Post-repair the diagnostic returns 0 rows.

## Consequences

- A narrative-only upstream stage no longer invalidates a scored downstream
  approval.
- ADR-172 still blocks empty submissions at submit time (trigger
  `trg_ar_stage_score_required` unchanged).

## Rollback

`DROP TRIGGER trg_ar_no_downstream_rewind ON public.annual_review_instances;`
plus restore the five rows from
`annual_review_downstream_rewind_repair_2026_07`.
