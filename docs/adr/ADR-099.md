# ADR-099 — Auditor xlsx download fails with "Bucket not found" on private review-evidence bucket

**Date:** 2026-06-29
**Status:** Accepted
**Release:** v2.66.68

## Context
Auditors reported that clicking **Download** on an Office (`.xlsx`) attachment in the review evidence preview opened a Supabase Storage 404 page:

```
{"statusCode":"404","error":"Bucket not found","message":"Bucket not found"}
```

URL pattern:
```
https://<ref>.supabase.co/storage/v1/object/public/review-evidence/<path>
```

`storage.buckets` confirms `review-evidence.public = false` (correct per evidence-access policy). PDFs and images downloaded fine because `openStorageFile()` in `src/lib/storageDownload.ts` always re-downloads them via the authenticated SDK `.download()` call into a `blob:` URL.

The review-side `EvidencePreviewDialog` previewed Office files through a 10-min signed URL (worked), but its **Download** and **Open in new tab** handlers fell back to `detail.url` — i.e. the original `/object/public/<bucket>/<path>` URL constructed elsewhere — when `blobUrl` was either unset or did not start with `blob:` (signed Office URLs start with `https:`). That fallback hit the public endpoint of a private bucket → 404.

## Decision
1. Export a small helper `resolveDownloadableUrl(url)` from `src/components/review/EvidencePreviewDialog.tsx` that mints a fresh 5-min signed URL whenever the input is `/storage/v1/object/public/<bucket>/<path>`, and otherwise returns the URL unchanged.
2. Route both `handleDownload` and `handleOpenNewTab` through it, preferring the existing `blobUrl` when present.
3. Surface sign failures as a `sonner` toast instead of opening a 404 page.
4. Codify the SSOT rule in POLICY §EVIDENCE-DOWNLOAD-PRIVATE-BUCKET: any client surface that downloads from `review-evidence` MUST go through SDK `.download()` or `createSignedUrl()`.

## Alternatives considered
- **Flip the bucket public.** Rejected — evidence files are business artifacts gated by RLS upstream; making the bucket world-readable widens exposure beyond what the workspace policy allows.
- **Stop constructing `/object/public/...` URLs at the upload/read sites.** Useful longer-term, but the upload paths are shared across many surfaces and re-plumbing them is out of scope for this incident; the per-handler resolver is a surgical fix and the policy rule prevents regressions.
- **Always blob-download office files.** Office Online Viewer needs an externally reachable URL for the preview iframe, so we still need the signed URL for preview; reusing it for download is the simplest consistent path.

## Consequences
- Auditors regain ability to download `.xlsx` (and any other Office attachment) from the review preview.
- Each download now incurs one extra `createSignedUrl` round-trip when the preview blob URL is not yet available; cached for the lifetime of the open dialog through `blobUrl` state.
- Future surfaces that show review evidence must follow §EVIDENCE-DOWNLOAD-PRIVATE-BUCKET; CI guard in `src/test/review/evidencePreview.test.ts` pins the resolver behaviour.

## Rollback
Revert `src/components/review/EvidencePreviewDialog.tsx` and the new test block. No DB / RLS / RPC change.
