# ADR-293 — "Pending At Level" is derived from the resolved workflow chain

Status: Accepted · 2026-08

## Context
KPI Status Tracker rendered `pending_at_level` from a hardcoded
`status -> label` map. Since `kpis.status` holds the LAST COMPLETED stage, every
row was labelled one stage behind: a KPI with `status = self_review` (self review
finished, waiting on the manager) displayed "Employee (Self Review)" while the
adjacent "Pending With (Name)" correctly showed the reporting manager
(e.g. 100856 / 101125 -> Gaurav Budhia). The map also ignored per-employee
workflow chains, so it could never say "Functional Manager" and wrongly named
skip-level / HR PMS / Audit for employees whose chain omits them.

## Decision
New pure SSOT `src/lib/reports/pendingAtLevel.ts`:
- `resolvePendingAtLevel({ status, isOrgKpi, stageChain })` returns the label of
  the NEXT stage in the employee's resolved chain
  (`get_bulk_employee_workflows`, POLICY §105).
- `kra_set` -> "Org KPI Data Owner" (org) or "Employee (Self Review)" (individual).
- `approved` / no next stage -> `—`.
`KpiStatusTracker.tsx` drops the hardcoded map and feeds the helper the same
`stageChainMap` the Pending With resolver already uses, so level and name can no
longer disagree; screen and Excel read one value.

## Consequences
Presentation-only; labels shift forward one stage — that is the correction.
Tests: `src/test/pendingAtLevel.test.ts` (8).
