# ADR-224 — Bulk criterion exemption + configurable exemption penalty

Status: Accepted (2026-07-31)

## Context
ADR-221 introduced per-employee eligibility exemptions and ADR-222 clamped exempted
employees out of the top N increment tiers. Two gaps remained: exemptions had to be
granted one employee at a time, and the penalty was a single hardcoded shape.

## Decision
1. **Bulk exemption.** A cycle-scoped run waives one exemptable criterion for every
   employee whose value satisfies an admin threshold, optionally only when that
   criterion is the sole blocking failure. Evaluation is server-side
   (`bulk_exempt_eligibility_criterion`, dry-run capable); the client preview is
   advisory. Runs are recorded in `annual_review_bulk_exemption_runs` and revocable.
2. **Configurable penalty.** `annual_review_bell_curve_config` stores a rule:
   `none`, `top_tiers_excluded` (legacy) or `step_down` by N slabs, with an optional
   `top_slabs_only` scope and a floor %. The rule may only reduce a slab percentage.
3. **Transparency.** Each exemption stores `source`, `bulk_run_id` and the frozen
   `penalty_from_percent` -> `penalty_to_percent`, surfaced in the drill-down popover
   and CSV exports.

## Consequences
- Protected criteria (disciplinary, tenure/month window) remain non-exemptable in
  bulk as well as manually — the server guard is unchanged and authoritative.
- Revoking a run restores the affected employees' original eligibility status.
- Tests: `src/test/annualReview/bulkExemption.test.ts`.
