# ADR-361 — Employee header: contact details + admin Edit shortcut

Status: Accepted (2026-09-05)

## Context
On a team member's scorecard the header (back arrow, avatar, name, code,
designation | department) was inert text. Admins reviewing a person had no way
to read the employee's email/mobile from there, and no shortcut into the
Employee Master edit form — they had to leave the review, open
`/admin/users`, and search for the person.

Both capabilities already existed:
- `src/components/review/EmployeeContactCard.tsx` — contact popover with email,
  mobile, copy buttons and an action slot (already used by the team grid).
- `src/pages/admin/UserManagement.tsx` — the complete edit dialog
  (`openEditDialog`) with every master field and custom fields, and an existing
  deep-link convention (`?manage=<id>&tab=…`).

## Decision
Reuse, do not rebuild.

1. The scorecard header name block becomes a focusable 44px-tall button that
   opens the existing `EmployeeContactCard` popover.
2. `EmployeeContactCard` gains two optional props: `onEdit` (renders an "Edit"
   action) and an optional `onViewKpis` (hidden when omitted — on the scorecard
   the KPIs are already on screen). Existing call sites are unchanged.
3. The Edit action is rendered only when the signed-in user's effective role is
   `admin`; it navigates to `/admin/users?edit=<employee_id>`.
4. `UserManagement` gains an `?edit=<id>` deep link that opens the existing edit
   dialog once per id (guarded by a ref so re-renders do not reopen it).
5. `EmployeeProfile` on `UnifiedScorecard` gains an optional `mobile_number`;
   the team grid already carries it, so it flows through untouched.

## Consequences
- No schema, RPC, RLS, workflow or scoring change. Contact fields were already
  readable by these reviewers; the admin route guard still enforces access.
- Rollback: revert the four touched files.
- Regression: `src/tests/employeeHeaderContactCard.test.tsx` (4) — email/mobile
  rendering, Edit hidden without `onEdit`, Edit fires, View KPIs hidden when no
  handler.
