# ADR-056: Shared Org KPI status helper for tile + propagate dialog

- Status: Accepted (May 2026)
- Context: ADR-055 fixed the immediate "Budget saving shows Entered while Propagate dialog says reviewer-locked" mismatch by making the tile fact-based. But the tile chip and the dialog still derived their verdict in two separate code paths (`getKpiStatus` in `OrgKpiDataEntry.tsx` vs. ad-hoc counters in `PropagationPreviewDialog.tsx`). Any future edit to one path can re-introduce drift.
- Decision: Extract a single pure module `src/lib/orgKpiStatus.ts` exporting:
  - `deriveOrgKpiTileStatus(input)` — returns `'pending' | 'entered' | 'propagated' | 'stuck'` for all three scopes.
  - `summarisePropagationPreview(rows)` — returns `{ total, willAdvance, willSkip, lockedCount, overwriteCount, effectivelyPropagated }`.
  - `isAlreadyAdvancedPastKraSet(mapped, kraSet)` — the shared predicate behind both surfaces' "nothing left to propagate" branch.
  Both `OrgKpiDataEntry.tsx` and `PropagationPreviewDialog.tsx` now consume these helpers; no business logic remains in the components.
- Consequences:
  - Tile chip and Propagate dialog can no longer disagree on whether a KPI is effectively propagated.
  - Dialog shows an explanatory amber line when `effectivelyPropagated` is true, mirroring the tile's tooltip.
  - Page becomes ~70 lines lighter; logic is unit-testable without rendering React.
- Tests: `src/test/orgKpiStatusShared.test.ts` (8 tile cases + 5 verdict cases). Existing `src/test/orgKpiTileStatus.test.ts` is kept as a regression guardrail.
