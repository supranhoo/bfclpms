# ADR-258 — Every edit lock must state its reason

**Status:** Accepted — 2026-08-14
**Policy:** POLICY §REVIEW-EDIT-LOCK-REASON

## Context

Binay Singh (102013) reported that his July 2026 self-review fields were
read-only and Submit was greyed out. The database showed nothing wrong: the
July and August 2026 periods are in `planning`, `is_locked = false`, no rows in
`review_period_locks`, and his nine July KPIs sit at `kra_set` / `self_review`
— all editable states.

The reason triage was impossible from the screenshot is that `SelfReviewSheet`
collapses several independent gates into a single unexplained outcome:

- `isGovernanceLocked` (period governance / view-only permission)
- stage gate (`!isKraSet && !isSelfReview`)
- `isOrgLocked` (organization-level KPI owned by a data owner)
- Submit disabled expression (multi-month cycle, missing sub-period, missing
  achieved value, N/A justification under 50 chars)

The UI showed only a "Read Only" badge or a greyed button, so every such report
required a database session to explain.

## Decision

Introduce `src/lib/review/editLockReason.ts` as the SSOT for lock causes.

- `resolveEditLockReason` returns one cause in fixed precedence — governance →
  stage → org ownership — or `null` when editable.
- `resolveSubmitBlockReason` mirrors the Submit `disabled` expression exactly
  and returns the plain-language cause, so the tooltip can never disagree with
  the button state.
- `SelfReviewSheet` renders the edit reason under the sheet title and wraps a
  disabled Submit in a tooltip carrying the submit reason.
- Mandatory-remarks validation, previously only a toast after clicking, now
  also disables the button with the same message.

## Consequences

- Employees see why a row cannot be edited or submitted; support can triage
  from a screenshot alone.
- Any new gate added to the sheet must be added to the resolver, otherwise the
  regression tests in `src/test/review/editLockReason.test.ts` and the visible
  reason will fall out of sync with the button.
- No schema or data change; rollback is reverting the two UI call sites.

## Open item

Two of Binay's July KPIs carry a `review_submissions` row with null scores
while the KPI is at `kra_set` (the send-back signature). That combination is
legal today and intentionally bypasses the governance lock, so no data was
mutated. If the surfaced reason shows these rows are the cause, the follow-up
is a targeted normalisation, not a UI change.
