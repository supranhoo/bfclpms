# ADR-036: Slab Categories Zero-Hardcoding

## Status
**Accepted**

## Date
2026-03-30

## Context
Incentive slab categories (PMS Score, Production, Availability, etc.) need to be configurable. The question was whether to maintain them as code constants or database-driven master data.

## Decision
Slab categories must be stored in the `incentive_slab_categories` master-data table. No component or hook may define a static array of slab category values. All lists sourced via `useIncentiveSlabCategories` hook. Admins manage categories via `SlabCategorySelector` inline input.

## Alternatives Considered

### Alternative A: Hardcoded category arrays in components
- **Description:** Define categories as TypeScript constants in UI components
- **Rejected because:** Requires code deployments to change categories. Risks drift between environments. Violates the Zero-Hardcoding Rule.

### Alternative B: Environment variable-based configuration
- **Description:** Store categories in env vars or config files
- **Rejected because:** Still requires deployment to change. No admin UI for non-technical users.

## Consequences

### Positive
- Admins can extend categories without developer intervention
- Consistent across environments

### Negative
- Requires database query to load categories (negligible with caching)

### Neutral
- Existing core categories seeded as initial data
