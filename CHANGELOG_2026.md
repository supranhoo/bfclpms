## 2026-06-04 — Safety Phase 9.2 WP-b SHIPPED — backup batch retry/backoff hardening
- **What:** Edge-fn-only change to `create-backup` scheduled path. Adds bounded transient-failure retry with backoff and a global wall-time budget so transient `HTTP 546` (Deno Deploy OOM) and rate-limit failures stop silently dropping batches. Non-transient errors (schema/permission/RLS/validation/other 5xx) are still surfaced immediately. Manual finalize path is **untouched** in this WP.
- **Edge fn (`create-backup`):** new exported `isTransientChunkError(errMsg, rateLimited)` classifier — true ONLY for `HTTP 546`, `HTTP 429`, or `RateLimitError`/`Rate limit` strings. New `retryFailedBatchTransient(...)` helper re-issues the failing chunk in halves of `BATCH_SIZE_RETRY=2` with backoff `[5s, 15s]`, capped by `RETRY_BUDGET_MS=8min` anchored on the orchestrator `startTime`. `runScheduledChunked` now classifies each batch failure; transient + budget-available → retry; otherwise the chunk is recorded as failed with a "non-transient" or "budget exhausted" tag and the post-finalize hard-fail terminal from WP-9.2.a marks the run `failed`.
- **Primary path unchanged:** `BATCH_SIZE=4` in both `handleInit` and `runScheduledChunked` is locked by Phase 9.1 I4 and Phase 8 OOM memory — only the *retry* path uses `BATCH_SIZE_RETRY=2`.
- **Telemetry:** per-chunk retry summary appended to `backup_logs.error_message` ("transient: HTTP 546", "sub k/N recovered on attempt j/2", "sub k/N failed after 2 retries", "sub k/N skipped: budget exhausted", trailing "(budget Xs left)").
- **Hard-fail terminal preserved:** retries never downgrade a failure. If `tablesCount < discoveredCount` and `backup_hard_fail_on_partial=true`, status is still `failed` (WP-9.2.a authority).
- **Tests:** Phase 9 contract grows from 7 to 11 — I8 retry constants exist + primary `BATCH_SIZE=4` count unchanged, I9 classifier exists and gates on 546/429/RateLimit only, I10 hard-fail terminal + "budget exhausted"/"non-transient" branches present, I11 manual `handleFinalize` does not reference the classifier or retry helper. I1–I7 stay green.
- **Test results (re-run 2026-06-04 end of WP-b):** `bunx vitest run src/test/safety/` → 19 files / **103 tests passed (103)**. Phase 9 contract 11/11, Phase 8 SSOT included, no regression elsewhere.
- **Wall-time safety:** worst-case retry latency (every chunk failing twice on 546) ≈ 320s backoff + ≈3–5 min retry work, well under both `RETRY_BUDGET_MS=8min` and the 30-min `reapStuckRunningBackups` ceiling.

## 🛡 Maintenance Protocol

1. **SSOT rule** — every shipped change appends one row to the **current week** here in the same step that you update `DOCUMENTATION.md` Version History (per project Atomic Sync rule).
2. **Status legend** — 🟢 Completed · 🟡 Iterating / partial · 🔵 Planned · 🔴 Blocked.
3. **Week boundaries** — W1 = 1–7 · W2 = 8–14 · W3 = 15–21 · W4 = 22–28 · W5 = 29–end.
4. **Granularity** — group small follow-ups under the parent feature row (sub-bullets); don't multiply rows.
5. **Monthly rollover** — at month end, archive the month section to `docs/changelogs/2026-MM.md` if the file gets too long.
6. **Export** — file lives at repo root → easy to `cat`, paste into email, or convert to PDF/PPT for execs.
