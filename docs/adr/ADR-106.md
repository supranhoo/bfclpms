# ADR-106 — Self Value Snapshot Contract

## Status
Accepted — 17 Jul 2026 (v3)

## Context
`review_submissions.achieved_value` is a shared column that reviewer stages
(auditor, management, etc.) overwrite when they record their own number.
`self_score` and `self_rating` however are frozen at self-submit time, so the
Self card in the KPI Journey could show mismatched Value / Rating and — worse
— render `Value: —` altogether when a downstream reviewer had already edited.

## Decision
1. `self_achieved_value` is the sole source of truth for the Self card's Value.
2. Every writer that sets `self_score` or `achieved_value` on behalf of the
   employee MUST co-write `self_achieved_value`. Reviewer-stage writers MUST
   NOT touch it.
3. A `BEFORE UPDATE` trigger (`enforce_self_snapshot_mirror`) fills the
   snapshot from `achieved_value` on any self-owning update as long as the
   snapshot is still `NULL` and no reviewer column was touched in the same
   update.
4. The UI resolver (`resolveSelfAchievedValue`) reconstructs the value from
   frozen `self_score` + KPI thresholds when the snapshot is missing. When
   reconstruction is ambiguous it falls back to the latest Org KPI Data Owner
   value for the period (tagged `source: 'org_owner'`). Only when neither is
   available does the UI show `—`.

## Version history
- **v1 (Jun 2026)** — Added `self_achieved_value` column + initial backfill.
- **v2 (17 Jul 2026)** — Added `enforce_self_snapshot_mirror` trigger.
- **v3 (17 Jul 2026)** — Trigger tightened to fire on value-preserving updates,
  a reverse-derivation backfill (`SELF_SNAPSHOT_BACKFILL_V2`) repaired historic
  rows, `repair_org_kpi_*` RPCs now co-write the snapshot, and the resolver
  gained an `orgAchievedValue` fallback.
