# ADR-297 — Performance Console: de-clutter and unified KPI creation

**Status:** Accepted · **Date:** 2026-08

## Context
ADR-294 put configuration and review on one surface by *stacking* two panels inside the open KRA:
the KPI definition list, then the review worksheet. Both printed the same KPI names, so every KPI
appeared twice on one screen. There was also no way to add a KPI to many people from the console —
the surface built to run the group could not create work for the group.

## Decision
1. **One row per KPI.** The KRA disclosure renders a single KPI list. Expanding a KPI row opens its
   employee cells *inside that row* (`KpiPeopleStrip`), so a KPI is never listed twice.
   `BuConsoleTree` swaps `renderKraPanel` for `renderKraSummary` (a slim counter line) plus
   `renderKpiPanel`. Only one KPI panel is open at a time; it closes when the KRA changes.
2. **`KraWorksheet.tsx` deleted.** Its grid, selection model and audited batch advance move into
   `KpiPeopleStrip` unchanged; the per-KRA `bu_console_run_snapshot` read is shared through the
   react-query cache, so opening a second KPI under the same KRA costs no round-trip.
3. **New KPI from the console.** `bu_console_kpi_create(p_kpi, p_period, p_year, scope…, p_dry_run)`
   — SECURITY DEFINER, admin-only, dry-run first — issues one definition to every active employee in
   the applied scope. Three kinds map to existing columns, no new table:
   | Kind | `kpi_group_type` | `is_org_level` | `org_level_scope` |
   |---|---|---|---|
   | Individual | `individual` | false | organization |
   | Shared value | `org` | true | organization |
   | Department event | `departmental` | true | department |
   Rows already carrying the same KRA+KPI for that month come back as `duplicate_kpi` skips; a run
   never partially fails on them.

## Consequences
- Presentation change plus one additive RPC. No schema change, no scoring change; §88
  immutability and §CONSOLE-WRITE-TIERS are untouched (creation is admin-only, new rows start in
  `kra_set`).
- The worksheet now loads per KRA and renders per KPI, which is strictly smaller than before.
- Tests: `consoleLayout.test.tsx` asserts the KPI title renders exactly once and that the people
  panel opens inside the row.

## Rollback
Revert the tree props and restore `KraWorksheet.tsx`; drop `bu_console_kpi_create`. Created KPIs are
ordinary `kpis` rows and are removed the normal way.
