# ADR-292 — "Days in Stage" is anchored to the audit trail, not `kpis.updated_at`

Status: Accepted · 2026-08

## Context
The KPI Status Tracker computed its Days column as `today − kpis.updated_at`.
`updated_at` moves on ANY write to the row (score edits, org-KPI propagation,
bulk maintenance, migrations). A system-wide write on 2026-08-15 collapsed every
July-2026 KPI to `updated_at = 15/16 Aug`, so the report showed 1–2 days for KPIs
that had genuinely been pending with a reviewer since 4 Aug (and `kra_set` rows
untouched since 1 Jul). The amber (≥4d) / red (≥7d) ageing thresholds therefore
almost never fired, on screen and in the Excel export.

Secondary defects: terminal records kept accruing days in the export, and KPIs
with no audit history fell back to `0`, reading as "just touched".

## Decision
Resolve the ageing clock from the append-only `kpi_audit_logs` trail.

- New pure SSOT `src/lib/review/daysInStage.ts`:
  - `isStageMovingAction()` — allow-list of stage transitions (forwards, submits,
    send-backs, step-backs, rollback approvals, `STATUS_TRANSITION`). Score/value,
    org-KPI propagation, query and weightage rows never reset the clock.
  - `buildStageEntryMap(logs)` — latest stage-moving event per KPI.
  - `resolveDaysInStage()` — fallback chain: stage-moving event → first audit
    event → `kpis.created_at`. Returns `null` for terminal (`approved`) records
    and when nothing can anchor the clock. Never silently `0`.
- `KpiStatusTracker.tsx` batch-fetches `kpi_audit_logs` for the period's KPI ids
  (300-id chunks, 1000-row pages) and maps `daysPending` through the helper.
  `null` renders `—` on screen and exports blank. `days_in_stage` keeps its
  `field_key`, so Report Field Sequence overrides are unaffected.
- Column relabelled "Days in Stage" / "Days in Current Stage" (export) with a
  tooltip stating it counts from stage entry, not last edit.

## Consequences
Displayed counts jump upward — that is the correction. One extra batched read on
this report; no schema or write changes. Bottleneck Report keeps its own
`bottleneckResolver` day count (unchanged, out of scope).

Tests: `src/test/daysInStage.test.ts` (8).
