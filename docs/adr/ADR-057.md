# ADR-057 — Normalised RLS join for Org-KPI ownership

**Date:** 2026-05-06  
**Status:** Accepted  
**Trigger:** Ankan Kumar Chakraborty (data owner) saw a blank `/admin/org-kpi-data` screen for April 2026 while admins saw 1 pending KPI assigned to him.

## Context
ADR-053/054 normalised the org-KPI triple `(category_id, kra_name, kpi_name)` on the React client (`normalizeKpiKey`) and inside SECURITY-DEFINER propagation RPCs, but the raw `SELECT … FROM kpis` issued by `useOrgLevelKpisWithEmployees` is still subject to RLS. The relevant policies still used **strict `=`** on `kra_name` / `kpi_name`. Because owner-table rows and `kpis` rows can drift by case, embedded `\r`, or collapsed whitespace, owners' rows were filtered out — for Ankan, exact-equal join returned 0; normalized join returned 69.

## Decision
1. Reuse `public.normalize_kpi_text(p text)` (immutable, parallel-safe; mirrors JS `normalizeText`).
2. Add expression indexes on `org_kpi_data_owners`, `kpis (where is_org_level)`, `org_kpi_values` over the normalized triple.
3. One-shot, lossless canonicalization of `org_kpi_data_owners.kra_name` / `kpi_name` (strip `\r`, collapse whitespace; preserve case). Originals snapshotted to `org_kpi_owner_key_backup_2026_05`.
4. Replace these RLS predicates with `normalize_kpi_text(o.x) = normalize_kpi_text(target.x)`:
   - `kpis` → "Data owners can view assigned org-level KPIs"
   - `org_kpi_values` → "Data owners can insert their assigned org_kpi_values"
   - `org_kpi_values` → "Data owners can update their assigned org_kpi_values"
5. Frontend safety net: when `useIsAnyOrgKpiDataOwner=true` but query returns 0 rows for a non-admin, show a louder explainer instead of the generic "No Org KPIs found" empty state.

## Consequences
- Data owners regain visibility they were always intended to have.
- New predicate is a strict superset of the old (anything matching exact-equal still matches).
- Future RLS policies joining the org-KPI triple **must** wrap both sides in `normalize_kpi_text()` — codified in `mem/features/admin/org-kpi-key-normalization`.
- Tests: `src/test/orgKpiOwnerNormalization.test.ts` locks JS↔SQL parity.
