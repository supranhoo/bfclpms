# ADR-075 — Org KPI Data Entry: explicit Save replaces 2s autosave

Status: Accepted (2026-06-06)

## Context
`/admin/org-kpi-data` (OrgKpiEntryCard + OrgKpiScopedEntryTable) used a 2-second
debounced autosave for every field change (Achieved, Remark, N/A toggle,
Evidence URL, scoped per-row values). A user reported (screenshot, June 2026)
that the Remark field "feels like Live Save mode" and asked for an explicit
Save button. Autosave also caused race conditions with Propagate: clicking
Propagate immediately after typing could race the still-pending autosave
write.

## Decision
Replace autosave with explicit Save controls on this surface only:

1. **Per scoped row** — a Save icon-button in the Actions column, ahead of
   the existing Propagate icon. Enabled only when that row is dirty.
2. **Card level (org-scope)** — a Save button under the inputs (and under the
   N/A reason textarea when N/A is active). Enabled only when the card is
   dirty.
3. **Propagate buttons** (card-level + per-row) are **disabled while dirty**
   with tooltip "Save unsaved changes first" / "Save row before propagating".
4. **`saveStatus` pill** gains `unsaved` (amber "Unsaved changes") and
   `error` ("Save failed") states alongside the existing `saving` / `saved`.
5. **`useUnsavedChanges` hook** registers a `beforeunload` warning while any
   card has pending edits.

No backend/RPC/RLS/schema changes. The `onSave` contract is unchanged — only
its trigger changed from a `setTimeout` to user click.

## Consequences
- One extra click per edited row before Propagate. Acceptable: the user
  explicitly chose "Whole row — disable autosave entirely" when presented
  with three options.
- Strictly fewer DB writes; no more debounce timers running per card.
- Risk of data loss is mitigated by the persistent "Unsaved" pill,
  amber card ring, and `beforeunload` confirm.
- Other data-entry surfaces (Self-review, Daily entry, Incentive grids,
  Safety) are out of scope and keep their current behavior.
