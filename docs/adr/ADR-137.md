# ADR-137 — Duplicate-reviewer collapse mirrors lock onto surviving terminal stage

Status: Accepted (2026-07-23)

## Context

When two consecutive annual-review stages resolve to the SAME reviewer
(commonly Dept Head + BU Head held by one person), `annual_review_effective_chain_details`
dedupes the lower stage in favour of the higher one (seniority wins). If the
instance was seeded before that dedupe was in force, `enabled_stages` still
contains the lower stage and `overall_status` sits at the lower `pending_*`.

Submitting the lower stage produced:

> ADR-127b: cannot complete instance … — terminal stage bu_head has no locked
> response (reviewer likely inactive; admin remap required)

because `advance_annual_review_status` locked only the submitted role's
response, then `annual_review_next_status(effective_chain, pending_dept)`
returned `completed` (dept_head not in the effective chain), and the
ADR-127b guard correctly refused completion — the surviving terminal
`bu_head` had no locked response.

## Decision

`advance_annual_review_status` now mirrors the locked response onto the
surviving terminal role whenever:

- `v_next = 'completed'`, AND
- the effective terminal role differs from the submitted role, AND
- the terminal role's reviewer_id equals the caller.

The mirror UPSERTs an `annual_review_responses` row for the terminal role
with `is_locked = true`, copying `criteria_scores`, `weighted_score`, and
`comments` from the just-locked lower-stage row. Audit event
`annual_review.duplicate_reviewer_mirror` records the collapse. If the
terminal reviewer differs from the caller (data inconsistency), the RPC
raises rather than silently attributing a submission to the wrong person.

A one-shot repair in the same migration normalises currently-stuck rows
(dept=bu, skip=dept, manager=skip, bu=hr) by stripping the redundant lower
stage from `enabled_stages` and forwarding `overall_status` to the winning
role. Audit event `annual_review.bu_terminal_normalized`.

## Consequences

- ADR-127b remains an inviolable completion guard.
- Reviewers holding two consecutive stages submit once; the RPC ships the
  lock to the terminal role automatically. No admin remap required.
- ADR-124 terminal-summary persistence continues to run unchanged.
- Rollback path (ADR-129 / ADR-136) already handles collapse via
  evidence-based terminal-stage resolution.
