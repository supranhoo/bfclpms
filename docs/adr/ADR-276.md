# ADR-276 — Objective Tree: one KRA/KPI cascade (Org → BU → Dept → Employee)

Status: Accepted · Related: ADR-263, ADR-267 · Policy: §KRA-TREE-SINGLE-CASCADE

## Context
The Goals tab rendered a flat, wide table of `bu_goals` rows modelled as library
objects. It could not express "one KRA with plant-level children", used the word
"goal" (which the business does not use), and had no notion of alignment,
health, or ownership. The table was empty, so a reshape lost nothing.

## Decision
- `public.bu_goals` gains `aligns_to_id`, `status` (+ `status_reason`,
  `status_is_manual`), `start_date`, `end_date`. Additive only.
- `kra_progress_pct` and `kra_derive_status` are the SQL SSOT for progress and
  health; a hand-set status always wins and is labelled as manual.
- `kra_tree_list` is a server-paged, per-level reader returning title,
  alignment, owner, badges, progress, status and mapped employee count.
  `bu_goal_upsert` enforces four-level nesting with a recursive loop guard.
- Structure (`parent_goal_id`) and alignment (`aligns_to_id`) are separate;
  alignment never changes roll-up.
- UI: `KraTree.tsx` renders one indented cascade with lazy per-level loading.
  Each level uses a single growing window (`pageSize = 100 × pages`) so
  "Load more" can never skip an intermediate page (§BU-CONSOLE-NO-SILENT-TRUNCATION).
- Vocabulary: a row is a **KRA** when it aggregates children, a **KPI** when it
  is the measurable leaf. "Goal" is gone from the UI.

## Consequences
- No scoring, workflow or review data is read-modified; roll-up stays read-only
  against `kpis` and remains weightage-weighted, never a plain average.
- Feature-flag gated behind `feature_bu_console`.
- Rollback: drop the added columns and restore the previous RPC bodies.
- Regression guard: `src/components/admin/bu-console/kraTree.test.ts`.
