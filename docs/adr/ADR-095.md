# ADR-095 — Excel export must mirror grid SSOT for grand totals

Status: Accepted (2026-06-29)

## Context
Upendra reported the Incentive Data Entry Excel export summed to
₹3,98,139 while the on-screen PMS Grand Total showed ₹3,98,134 — a
₹5 mismatch over 280 employees for the same program/month.

## Root cause
Two rounding strategies for the same total:
- Grid (SSOT, `ProductionDailyGrid.tsx:295`):
  `Math.round(Σ total × rate)` — sum first, round once.
- Export (`IncentiveDataExport.tsx:194`):
  per-row `Math.round(total × rate)`; Excel `SUM` then aggregates the
  pre-rounded values → half-up bias accumulates.

Same defect class as ADR-094: display layer re-implementing math
instead of mirroring the SSOT.

## Decision
- Export writes the raw per-row `total * rate` (number). Excel cell
  formatting still renders an integer rupee.
- Export appends a `Grand Total` row computed with the exact grid
  expression `Math.round(Σ total × rate)`. The bottom-line cell in the
  spreadsheet equals the PMS Grand Total by construction.
- Test (`src/test/incentiveExportData.test.ts`) pins both: raw per-row
  amount + sum-then-round Grand Total.

## Consequences
- Payroll spreadsheets reconcile to the PMS Grand Total to the rupee.
- No DB, RLS, or compute changes.
- Any future export of grid-backed money MUST follow the same pattern
  (POLICY §INC-EXPORT-PARITY).

## Rollback
Revert `src/components/incentive/IncentiveDataExport.tsx`.
