# ADR-108 — Annual Review Reviewer Slot Resolution & Cascade

Status: Accepted — 2026-07-17

## Context

On 17-Jul-2026 the "ghost reviewer" CAPA (migration `20260717062346_…`) nulled
`manager_id / skip_id / dept_head_id / bu_head_id / hr_id` on
`annual_review_instances` for any stage NOT in `enabled_stages`. This exposed a
pre-existing gap: several reviewer id columns had drifted from the org
master data (`departments.head_user_id`, `business_units.head_user_id`,
`org_head_config.hr_head_user_id`) — either NULL where a head exists, or set
to an outdated person. Result: department / BU heads saw shrunken review
queues (Prabhat Kumar Singh 120 → 39, others similar).

## Decision

1. **Master data is SSOT** for who reviews at each enabled stage.
2. **`enabled_stages` gates presence** — a disabled stage's id column stays NULL.
3. Provide an **idempotent resync RPC** (`resync_annual_review_reviewer_slots`)
   and a matching **diagnostic RPC** (`annual_review_reviewer_slot_diagnostic`).
4. Wire **AFTER UPDATE cascade triggers** on `departments`, `business_units`,
   and `org_head_config` so future head changes flow into open instances
   automatically (past-stage rows are skipped).
5. All writes append to `annual_review_reviewer_resync_audit`.

## Consequences

- Reviewer queues are recomputable at any time; no more silent drift.
- Business owners fix "missing team members" by updating master data
  (Departments / Business Units / Org Heads) — the change cascades on save.
- Historical instances past the affected stage are NOT rewritten (no impact
  on finalized scores).
- Manual reviewer overrides still take precedence within a single instance
  (`set_annual_review_reviewer_slot`); those rows are not touched by the
  cascade because their status has already advanced past that stage.

## Non-goals

- Rolling back the 17-Jul ghost-slot null-out.
- Auto-enabling stages that HR intentionally disabled.
- Retroactively rewriting `completed` instances.
