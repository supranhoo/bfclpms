# ADR-116 — System Score key stability on template swap

Status: Accepted (2026-07-18) · POLICY §AR-SYSTEM-SCORES-KEY-STABILITY

## Context
Annual Review templates carry per-template `sys_XXX` IDs on each System Score
item, but the item's *identity* is its `library_key` (`s5`, `training_attended`,
`lti_count`, …). When Admin/HR force-resets an instance to a different
template, `force_reset_annual_review_instance` swapped `template_id` but
never rewrote `system_scores` / `system_scores_raw`. Values were still keyed
by the *old* template's `sys_XXX` IDs — orphaned relative to the new
template's items — so the Employee page rendered `0.00 / N` for every raw
System Score item (5S, Training, LTI, …).

Reported case: Nikunj Poddar (100357), instance `422f7062…`, reset
`a6e88cd5 → 0a815c39` on 2026-07-18. System-wide scan found 235 instances
whose current template needs HR raw entry but has an empty
`system_scores_raw` map.

## Decision
1. Introduce `public.remap_system_scores_by_library_key(old_tpl, new_tpl,
   old_scaled, old_raw)`. Matches each new item to an old item by
   `library_key`; carries `system_scores` and `system_scores_raw` values
   under the new item IDs; skips `source = carry_kra` (computed live).
2. `force_reset_annual_review_instance` now calls the remapper immediately
   before the `UPDATE annual_review_instances` swap and writes the returned
   maps back to the row.
3. Every reset emits an `annual_review.system_scores_remapped` audit log
   with the carried count and `missing_library_keys` array so HR knows
   which items still need raw entry.
4. Front-end: `missingRawSystemScoreItems` helper + amber banner on the
   Employee Annual Review page listing items that still need HR entry.

## Non-goals
- We deliberately do NOT retroactively populate the 235 empty-raw instances;
  the underlying HR values were never entered. The banner surfaces the gap
  instead of silently rendering `0.00`.

## Consequences
- Future template swaps preserve System Score values whenever the
  `library_key` matches on both sides.
- Orphaned keys under the old `sys_XXX` IDs remain on the row (harmless,
  audit-preserved) and are ignored by the SystemScoresPanel.
- No RLS/schema changes; the remap RPC is additive.
