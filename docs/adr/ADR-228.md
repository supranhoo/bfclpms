# ADR-228 — Exemption-aware band placement in the Bell Curve

- Status: Accepted (2026-08-01)
- Related: ADR-212 (rating slabs), ADR-218/218b/218c (Bell Curve), ADR-220 (calibration),
  ADR-221 (eligibility & exemptions), ADR-222/224 (exemption penalty)

## Context
Once an exemption is processed the employee's increment percentage is penalised, and an
ineligible employee displays 0%. The Bell Curve still placed everyone by their raw rating
(`makeBanding(...).keyOf(rating)`), so a penalised employee stayed in the 20% heat map column
while the report row said 12%.

## Decision
1. **Placement layer.** `placementRatingOf(row, rating, cap)` in `lib/annualReview/bellCurve.ts`
   converts the actual rating to the raw slab %, applies the existing SSOT
   `effectiveSlabPercent()` (ineligible -> 0%, exempted -> penalty rule), and clamps the row
   into the effective slab's `[rating_from, rating_to)` window. The percentage can only fall,
   so placement can only move down.
2. **Both dashboards.** `Banding.keyOfRow(row, rating)` is used by `computeBands`,
   `groupBands`, `heatmapBands`, `summarize` and `employeesInBand`, so the move applies in
   Slab % mode AND in Rating bands (1–5) mode.
3. **Display unchanged.** The actual rating still drives the Rating (/5) column, the
   calibration dialog and the average-rating KPI. Only the bucket moves.
4. **Transparency.** The drill-down shows "moved from <original band>" next to the name and a
   matching CSV column; the Excel export carries `... Band (actual)` and `... Band (effective)`.
5. **Reversible.** `makeBanding(mode, config, slabs)` without the cap argument reproduces the
   pre-ADR-228 output byte-for-byte.

## Consequences
- Distribution counts, variance/compliance, group summaries and both exports now report the
  post-exemption position — one number everywhere.
- Guard: `src/test/annualReview/bellCurve.test.ts` (ADR-228 block).
