# ADR-037: Employee Mapping — Resolved List

## Status
**Accepted**

## Date
2026-03-30

## Context
The incentive program employee mapping UI needed a way for admins to see and manage which employees are enrolled in a program. The interface design choice was between abstract entity pickers and a resolved employee list.

## Decision
The UI must display a unified, sortable table of all active employees with organizational attributes. `ProgramEmployeeMapping` renders a flat employee table with checkboxes. Bulk operations use `useBulkAddProgramMappings` / `useBulkRemoveProgramMappings` hooks.

## Alternatives Considered

### Alternative A: Abstract entity pickers (tabs for divisions, departments, grades)
- **Description:** Separate tabs where admins select organizational entities, with employees implicitly included
- **Rejected because:** Obscures which individual employees are actually enrolled. Admins cannot verify enrollment without mentally resolving entity-to-employee mappings. Risks accidental over-enrollment.

### Alternative B: Individual employee search and add
- **Description:** One-by-one employee search and enrollment
- **Rejected because:** Impractical for programs with hundreds of employees. No bulk operations support.

## Consequences

### Positive
- Immediate visibility into who is mapped
- Multi-select with filters supports efficient bulk operations

### Negative
- Large employee lists may require pagination (handled via filters)

### Neutral
- Mapping data stored in `incentive_program_mappings` table
