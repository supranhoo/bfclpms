# ADR-229 — Multi-select, searchable, cascading filters (project-wide standard)

- Status: Accepted (2026-08-01)
- Related: ADR-218i (interdependent Bell Curve filters), ADR-199 (employee status filter)

## Context

Filter rows across the app were single-select `Select` dropdowns. Users repeatedly need
combinations ("Exempted **and** Ineligible", two departments, three managers) and long
option lists (managers, departments) are unusable without a search box. ADR-218i already
made the Bell Curve filters interdependent but kept them single-valued.

## Decision

1. **Standard.** Every filter control in the app is multi-select and has a search field.
   When a screen exposes more than one filter, the filters are cascading: each axis's
   option list is computed with every OTHER active filter applied.
2. **Component.** Reuse `src/components/ui/multi-select-id.tsx` (id value + display label,
   search, select-all-filtered, count badge, clear, `h-10` trigger, `ariaLabel`). Do not
   build per-screen dropdown variants.
3. **Semantics.** An empty selection array means *All*. Within an axis the values OR;
   across axes they AND.
4. **Reconciliation.** When another axis changes, impossible selections are **pruned**
   individually (`reconcileFilters`) — never a blanket reset to All.
5. **Exports.** Any export produced from a filtered view records the selected values per
   axis in its header (`axisSummary`: label list up to 2 values, otherwise "N selected").

## Scope of this change

Applied to the Bell Curve Analysis tab (7 axes). `BellCurveFilters` is now
`Record<FilterAxis, string[]>`. Other existing filter rows keep their current behaviour
until retrofitted; all NEW filters must follow this ADR.

## Consequences

- Presentation/filter layer only — no schema, RPC, RLS or scoring change. Placement,
  calibration and exemption logic (ADR-220/222/224/228) untouched.
- Default view is unchanged: all axes start empty === All.
- Guard: `src/test/annualReview/bellCurveFilters.test.ts` (13 cases, 7 new).
