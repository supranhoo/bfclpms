# ADR-325 — Safe variance normalisation: wording vs the individual bar

Date: 2026-08-26
Status: Accepted

## Context

The Performance Console "Make this one" action (ADR-315) wrote all four
variant-key fields — description, formula, scoring logic **and target**. For
"SOP/SMP Creation & Implementation" the six variants mixed two unrelated things:
wording drift (formula written as `(Number of SOPs...)` vs `Number of SOPs...`)
and deliberate per-person bars (target 5 / 7 / 10 with matching rating text).
Applying the action would have pushed one target onto everyone, destroying the
differentiation the KPI was designed around.

## Decision

1. Variance splits into two classes in `variantNormalise.ts`:
   `WORDING_FIELDS` (`kpi_description`, `kpi_formula`, `kpi_scoring_logic`) and
   `SCORING_FIELDS` (`target_value`).
2. `changeSetFor` / `buildNormalisePlan` take a mode. In `wording` mode a scoring
   field is never emitted, whatever the admin typed. `predictedVariantCount`
   becomes target-aware: after a wording run the count is the number of distinct
   targets, not 1.
3. The dialog is two tabs: **Standardise wording** (default, no target written,
   states the targets left untouched) and **Targets & bands** (off by default,
   per-variant before/after table, typed `APPLY` confirmation).
4. `classifyVariance` drives the tree badge: amber `N variants · M wording` for
   text drift, neutral `N targets` for deliberate bars.
5. `seedTiersFromVariants` hands target variance to the ADR-324 scoring ladder —
   one tier per distinct target, highest bar first, single-person variants pinned
   to that employee — so differentiation becomes governed configuration.

Weightage is still never written. Server behaviour is unchanged: wording runs are
descriptive-only and take the ADR-323 automatic bypass; target runs stay under the
§88 lock guards.

## Consequences and rollback

Strictly reduces what the action writes; the destructive path is opt-in and
confirmed. Rollback = revert the client modules; no schema or RLS change.

## Tests

`variantNormalise.test.ts` (mode split, classification, predicted count),
`scoringLadderModel.test.ts` (`seedTiersFromVariants`), `consoleLayout.test.tsx`.
