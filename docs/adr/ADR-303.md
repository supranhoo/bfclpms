# ADR-303 — Evidence preview authorization must be singular and bounded

**Status:** Accepted — 2026-08-20  
**Policy:** POLICY §EVIDENCE-PREVIEW-TRANSPORT-FALLBACK

## Context

Satyam Agarwal could not open Kanha Modi's 1.06 MB XLSX evidence after ADR-300. The exact `storage.objects` lookup took 12,177 ms. Four permissive read policies matched the private `review-evidence` bucket and PostgreSQL OR-combined them; the obsolete owner/reporting-chain policy pulled profile and annual-review RLS subplans into a one-object lookup. The authenticated role's statement timeout is 8 seconds.

The client also allowed three six-second signing attempts plus backoff to consume 19.6 seconds of a 20-second budget, leaving no time for fallback. When fallback did return an XLSX Blob, the UI passed its browser-local `blob:` URL to the remote Office viewer, which can never fetch it.

## Decision

1. Remove the two superseded overlapping read policies and retain the canonical KPI-participant policy plus the distinct Org KPI path policy.
2. Reorder `can_read_kpi_evidence` from cheap/indexed checks to expensive resolution, add an `owner_id`-first data-owner index, and revoke anonymous execution.
3. Reserve eight seconds for fallback; signing receives only the remaining budget.
4. A downloaded XLSX/XLS/XLSM/CSV is rendered locally with bounded rows and columns. Other downloaded Office formats show an explicit Download state. A `blob:` URL is never sent to Office Online.

## Consequences

- Permission semantics and evidence rows are unchanged; only authorization planning and rendering change.
- Spreadsheet fallback is bounded to 200 rows and 50 columns; Download retains the full file.
- Rollback restores the captured policies/function/grants, removes the index, and reverts the frontend files. No business-data rollback is required.
