# ADR-299 — Audit action vocabulary must match the CHECK allowlist

**Status:** Accepted — 2026-08-18
**Policy:** POLICY §AUDIT-ACTION-VOCABULARY

## Context

Deactivating employee Biswajit Sahoo (100426) failed with:

`new row for relation "annual_review_access_audit" violates check constraint
"annual_review_access_audit_action_check"`

RCA (verified against the live database):

- `profiles` carries `trg_alert_on_reviewer_deactivation` (AFTER UPDATE OF `is_active`).
  When a deactivated user still owns pending annual-review stages, or heads a business
  unit / department, the trigger inserts an audit row with
  `action = 'reviewer_deactivated_orphan_risk'`.
- `annual_review_access_audit_action_check` listed 17 actions; that value was not one of
  them. The audit insert therefore aborted the whole profile UPDATE.

Only reviewers/heads were affected, which is why most deactivations worked and the defect
stayed latent.

### 5 Why

1. Update fails → the audit insert violates the CHECK.
2. Insert violates CHECK → the trigger writes an action outside the allowlist.
3. Outside the allowlist → the alert trigger shipped after the constraint and the allowlist
   was not extended in the same migration.
4. Not extended → nothing bound trigger action literals to the constraint.
5. Nothing bound them → the audit action vocabulary had no single source of truth.

## Decision

1. Widen `annual_review_access_audit_action_check` to include
   `reviewer_deactivated_orphan_risk` (additive only; no data change).
2. Treat the action vocabulary as an SSOT: `src/tests/annualReviewAuditActionAllowlist.test.ts`
   asserts every producer-written literal is a member of the allowlist.
3. Any new audit action MUST be added to the constraint and the guard test in the same change.

## Consequences

- Deactivating a reviewer/head now succeeds and correctly records the orphan-risk alert,
  which Admin → Orphaned Reviews consumes.
- Rollback: recreate the constraint with the previous 17-value list.
