# ADR-328 — Group KPI editor respects the UOM type

## Decision

The "Edit definition for the whole group" dialog exposes the KPI type — Numeric, Binary (Yes/No), Tiered — with the same selector used by the Admin KPI editor, and the unit of measure becomes a controlled list instead of free text.

- The type and its qualitative options are group-owned (ADR-282) and structural: changing them requires the typed confirmation.
- A Binary or Tiered KPI carries no unit and no R0–R5 ladder; both are blanked by `ladderForType` so stale numeric values never travel in the change set.
- The unit list keeps any legacy stored value selectable so no existing unit is lost.

The client descriptive-field allowlist is realigned with `public.bu_console_descriptive_fields()`: `kpi_scoring_logic` is not descriptive (ADR-327), so a scoring-test edit is honestly reported as a protected-path change instead of promising a text-only run and then skipping rows.

## Why

Without a type control the console could only ever edit a KPI as numeric, so binary and tiered group KPIs showed an irrelevant rating ladder and an empty unit box, and the type could not be corrected at group level at all.

## Data and security

No schema change. `uom_type`, `qualitative_options` and `threshold_mode` were already console-editable and are validated server-side by `bu_console_validate_changes`; per-employee tuning stays barred from them. Historical scores are never recomputed — only rows in the selected span are written, and approved final scores stay immutable.

## Rollback

The dialog controls revert independently; the allowlist alignment is a one-line revert. Nothing in this change rewrites stored scores.
