# ADR-288 — Tiered target rules for a shared KPI

**Status:** Accepted · **Date:** 2026-08

## Context
A shared KPI is the same *measure* for everyone but not the same *bar*: for
"SOP creation" a manager may owe 10 and their team 5. Until now the only way
to express that was per-employee tuning, which forks the group and cannot be
maintained at scale.

## Decision
`public.bu_console_target_rules` holds a small rule set per KPI group
(`kpi_key = category|kra|kpi`, normalised), matched on one dimension:
`default | level | designation | department | is_manager`, ordered by
`priority` with `default` always last.

`bu_console_target_rules_apply(..., p_reset_overrides, p_dry_run)` fans the
resolved target out across the scope. It:
- skips rows with `final_score IS NOT NULL` (POLICY §88),
- skips hand-tuned targets unless "replace tuned targets" is ticked,
- reports every skip with a reason rather than aborting the run,
- writes one audited run row, mirroring the group-edit contract (ADR-274).

The scoring model stays group-owned (ADR-282) — rules move the target only,
never the ladder, type or options.

Client mirror + precedence tests: `src/components/admin/bu-console/targetRuleModel.ts`
and `targetRuleModel.test.ts`.
