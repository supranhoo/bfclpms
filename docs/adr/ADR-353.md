# ADR-353 — Rollback of accidental Performance Console edits to "Power generation from 8 MWh"

Date: 2026-09-03 · Status: Accepted · Related: ADR-334, ADR-337, ADR-351

## Context

On 3 Sep 2026 an admin (employee 101785) made three group-definition edits from
the Performance Console against the KPI *Power generation from 8 MWh* (KRA
*Achieve organization's production target*) while intending to edit the
neighbouring *Achieve 1050 TPD Power Generation target* KPI. Each edit fanned
out as one `bu_console_edit_runs` row per month (Jul 2026 – Jun 2027):

| Time (UTC) | Field | Rows written |
|---|---|---|
| 16:06 | `kpi_description` — added a space before "May - June" | 65 (Jul–Oct 2026) |
| 16:10 | `category_id` — long "(incentive %)(Aug-Sep,…)" variant moved to another category | 6 (Aug–Oct 2026) |
| 16:16 | `kpi_scoring_logic` — original "20% incentive = 5, 15% = 4 … (pro-rata Kiln shutdown exemption)" replaced with a "Rating 5: ≥ 15% Incentive … (5% Incentive Target)" ladder | 65 (Jul–Oct 2026) |

A fourth action at 16:10 (`rename_kpis_range` on the legacy `kpi_name`) matched
no rows and needed no reversal.

## Decision

Revert all three edits using the before-images already stored in
`bu_console_edit_items`, mirroring `bu_console_undo_edit_run` semantics exactly:

- a field is restored only when the current value still equals the value the run
  wrote (no later edit is silently overwritten),
- each restored row gets a `kpi_audit_logs` entry with
  `action = 'BU_CONSOLE_EDIT_UNDO'` and `performed_by = NULL` (system-performed
  correction, per the system-attribution rule),
- every affected run is stamped `undone_at`, and every item `reverted_at`.

The reversal was executed as data statements rather than through the RPC because
the maintenance session has no `auth.uid()`; the semantics, guards and audit
trail are identical to the UI Undo action.

Note for future reversals: three `UPDATE` CTEs inside one statement cannot all
touch the same row — Postgres applies only the first. The description restore
therefore had to run as a second statement.

## Consequences

- All 136 edit items across the 11 affected runs are reverted; Jul–Oct 2026 rows
  again show the original description, the original scoring logic, and the two
  long-variant rows are back in category `bcb2ebfa-…`.
- No scores, ratings, targets, weightages, evidence or workflow statuses were
  written — the rollback touched `kpi_description`, `kpi_scoring_logic` and
  `category_id` only.
- Rollback of the rollback: the run payloads still hold the 16:06/16:10/16:16
  values, so any of them can be re-applied deliberately from the Console.
