# ADR-235 — Final score has a single sanctioned writer

Status: Accepted — 2026-08-03
Related: ADR-187 (score scale invariant), ADR-212 (Final Rating /5), ADR-225/225a (bulk
system-score upload), ADR-232 (write-back), ADR-234 (template-scoped system scores)

## Context

A full audit of cycle "Annual Review - 2025-2026" (2,580 instances; 2,086 completed,
493 excluded) recomputed `annual_review_compute_final_summary()` for every completed,
non-excluded instance and compared it against the stored values.

Findings:

- 104 completed reviews stored a final score **lower** than the SSOT recomputation
  (avg −1.65 pts, max −17.00 — 102011 stored 53.00 vs 70.00). 6 of them were banded
  one band too low, which also understates the increment slab.
- All 104 carried a `system_scores.admin_override` audit entry from the bulk
  system-score upload (30 Jul: 79, 01 Aug: 25).
- `admin_apply_system_scores_upgrade` wrote `system_scores` but took `total_score`
  from a **client-supplied** `p_total_score` under a monotonic "only if greater"
  guard, and never called `annual_review_apply_final_summary`. The upgraded system
  points therefore never reached the stored total.
- Clean: 0 missing scores, 0 out-of-range scores, 0 blank bands, 0 orphan slots,
  0 duplicate instances, 27 valid calibrations.
- Anomalies: 2 completed instances without `finalized_at`, 1 excluded and 1
  non-completed instance carrying a score, 1 NULL `criteria_weighted_score`.

## Decision

`public.annual_review_apply_final_summary` is the ONLY writer of `total_score` /
`final_rating`. Every admin system-score edit path now calls it with
`allow_overwrite := true` after persisting the score cells:

- `admin_apply_system_scores_upgrade` — `p_total_score` / `p_final_rating` are kept
  for signature compatibility and **ignored**.
- `admin_apply_system_scores_correction` — always recomputes (the caller-supplied
  branch is removed).
- `admin_update_system_scores_raw` — already recomputed; unchanged.

New read-only RPC `public.annual_review_final_score_drift(p_cycle_id)` returns every
completed, non-excluded instance whose stored score/band differs from the recomputation.

## Consequences

- One-off repair re-ran the sanctioned writer for the 104 drifted instances; each
  change is captured in `annual_review_final_score_recompute_audit`
  (`source = 'adr235_audit_repair'`) with before/after values, so it is reversible.
- Anomaly cleanup: `finalized_at` backfilled from the terminal stage submission;
  scores cleared on the excluded / non-completed instances (audited);
  `criteria_weighted_score` normalised.
- Post-repair verification: drift 0, missing scores 0, out-of-range 0, orphan slots 0.
- `FinalScoreDriftCard` (Annual Review → Admin → Orphaned Reviews) surfaces future
  drift with an admin recompute action.
- Guards: `src/lib/annualReview/finalScoreDrift.ts` + `src/test/annualReview/finalScoreDrift.test.ts`.
