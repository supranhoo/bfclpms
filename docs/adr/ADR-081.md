# ADR-081 — Per-row Save preserves sibling unsaved edits (Org KPI Data Entry)

Status: Accepted (2026-06)

## Context
On `/admin/org-kpi-data`, scoped KPI cards expose a per-row Save button (ADR-080
narrows the payload to that single row). Reported by Vivek Dansena: typing
Achieved/Remarks into several rows and then clicking Save on one row blanked
the typed values in the other rows.

Root cause in `src/components/admin/OrgKpiEntryCard.tsx`:
1. `performSave(scopeId)` unconditionally called `clearAllDirty()`, dropping
   `isDirtyRef.current` to `false` even though only one row was flushed.
2. The subsequent refetch fired the primary merge effect; with the dirty flag
   cleared, the reset branch ran `setScopedValues(data.scopedRows!)`, which
   only preserved `evidenceUrl` (via `touchedEvidenceScopeIdsRef`) and threw
   away the user's local `achievedValue` / `remarks` on other touched rows.

## Decision
- Row Save clears dirty state only for the saved `scopeId` (removed from
  `dirtyScopeIds`, `touchedScopeIdsRef`, `touchedEvidenceScopeIdsRef`); card
  dirty + sibling row dirtiness are preserved.
- `isDirtyRef.current` is recomputed as `cardDirty || dirtyScopeIds.size > 0`
  after the row Save.
- The primary merge effect's reset branch preserves local
  `achievedValue` / `remarks` / `isNa` / `subFactors` for any scopeId still in
  `touchedScopeIdsRef`, mirroring evidence-URL preservation.
- `saveStatus` stays `'unsaved'` while siblings remain dirty after a row
  Save; only flips to `'saved'` when nothing dirty remains.

## Consequences
- Per-row Save no longer causes silent data loss in sibling rows.
- Card-level Save semantics unchanged.
- No schema / RPC / RLS changes.
