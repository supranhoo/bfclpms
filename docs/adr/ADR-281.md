# ADR-281 — Scope-level people counts are DISTINCT, never row sums

Status: Accepted — 2026-08-16

## Context
The Performance Console stat band showed "Employees impacted: 2744" for August 2026.
`computeConsoleStats` summed `employee_count` across every KPI node, so an employee
mapped to N KPIs was counted N times. The true distinct employee count for that scope
was 181 (`select count(distinct employee_id) from kpis where review_period='August' and review_year=2026`).

## Decision
- `public.bu_console_tree` now returns `employee_total` = `count(DISTINCT employee_id)`
  over the same filtered KPI set used to build the tree (period/year + division, BU,
  department, manager filters).
- `computeConsoleStats(categories, employeeTotal)` takes the distinct total from the
  RPC. It no longer derives the people figure from per-KPI counts.
- The tile carries the sub-label "distinct employees in scope".
- Per-KRA / per-KPI "N employees mapped" figures stay as-is — those are correctly
  scoped to a single node.

## Policy
POLICY §CONSOLE-DISTINCT-PEOPLE: any scope-level "employees" figure must come from a
server-side `count(DISTINCT employee_id)` over the same filter set as the surface it
labels. Client-side summation of per-node counts is forbidden.

## Verification
- `src/components/admin/bu-console/consoleLayout.test.tsx` asserts the distinct total
  is passed through and not summed (4+2+1 rows → 5 people).
- All 60 console tests pass.
