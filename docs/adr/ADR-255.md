# ADR-255 — TNI secure qualification parity and action-record clarity

## Status
Accepted — 2026-08-12

## Context
For April–June 2026 at threshold 2 and minimum 3 scored months, the database
qualification returned 252 employee/KPI identities across 98 employees, while
the report screenshot still showed zero and obsolete 1,000-row exclusion text.
ADR-254 removed persistence gating, but `tni_qualified_kpis` remained security
invoker over RLS-protected KPI/submission tables, so a viewer session could
silently receive a different set from the verified report result. The visible
“Backfill Range” action also implied that writing detection rows was required.

## Decision
- `tni_qualified_kpis` is SECURITY DEFINER with a fixed search path, explicit
  authentication, TNI report-access authorization, and KPI-row scope checks.
- Admin/Management/HR PMS/Auditor report viewers receive broad reporting scope;
  other authorized viewers remain limited by `can_view_kpi_row`.
- Anonymous execution is revoked. The continuity formula is unchanged.
- KPI weightage is returned by the qualification RPC, so unactioned rows do not
  depend on a persisted detection join for the requested report column.
- `detect_training_needs_for_period` is Admin-only. The UI calls these writes
  “Create Action Record(s)” and explains that they persist workflow enrichment;
  they never determine report eligibility.
- All settings, qualification, detection enrichment, and profile errors are
  surfaced instead of being rendered as valid zeros.

## Consequences
Report qualification is stable for authorized broad-report users and remains
least-privilege for managers. No existing score, KPI, submission, or TNI row is
rewritten. Rollback restores the ADR-252b function body and previous labels;
no data rollback is required.
