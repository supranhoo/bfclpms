# ADR-038: Dashboard Observation Visibility

## Status
**Accepted**

## Date
2026-03-30

## Context
Observations (positive, concern, neutral feedback) attached to KPIs were only visible inside the review panel. Stakeholders needed surface-level visibility on the dashboard.

## Decision
Every dashboard KPI row (desktop table and mobile card) must display the observation count when observations exist. The indicator is a compact Eye icon with count in amber, rendered after the query badge. Scorecard containers fetch observations via `useObservationsByKpis`.

## Alternatives Considered

### Alternative A: Show observations only inside the review panel
- **Description:** Keep observation data hidden until the user opens a specific KPI
- **Rejected because:** Reduces visibility and delays action. Managers reviewing many KPIs would miss critical feedback.

### Alternative B: Separate observations dashboard page
- **Description:** Dedicated page listing all observations across KPIs
- **Rejected because:** Adds navigation overhead. Observations are most actionable in the context of the KPI they reference.

## Consequences

### Positive
- All stakeholders see observation activity at a glance
- No additional navigation required

### Negative
- Additional query per scorecard view (mitigated by batch fetch)

### Neutral
- Uses existing `kpi_observations` table data
