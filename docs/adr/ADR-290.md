# ADR-290 — Performance Console: a higher stage supersedes the lower ones

Status: Accepted · Supersedes the strict one-step rule in ADR-286.

## Context
`bu_console_kpi_advance` accepted a move only when the target stage was exactly the next
stage of the employee's resolved workflow; anything else came back as `stage_mismatch`.
The Bulk Review dashboard has always worked the other way (POLICY §111.7.a): a reviewer
standing higher in the chain can sign off and the stages below are closed with the score
carried forward. Two rules for the same act is the duplicity we are removing.

## Decision
The console worksheet uses the bulk-review semantics.

- Forward leaps allowed: any target stage later than the current status in that employee's
  own resolved workflow (`get_employee_workflow` — never a hardcoded ladder, POLICY §105).
- Backwards is still refused (`stage_mismatch`) — that is what Rollback Requests are for.
- Carry-forward: the last available score (management → HR PMS → skip → audit → functional →
  manager → self). The target stage is written outright; superseded stages are filled only
  when empty, so an existing lower decision is preserved.
- Guards kept: `final_score_locked` (POLICY §88), `kra_set_admin_only` (ADR-285),
  `no_submission`, `not_scored`, `final_approval_not_supported`.
- Guards added: `self_not_submitted` (a leap never invents the employee's own input) and
  `auditor_takes_precedence` (HR PMS never overwrites an auditor decision).
- Audit: the batch writes `BU_CONSOLE_RUN_ADVANCE` plus one `BU_CONSOLE_STAGE_SUPERSEDED`
  row per closed stage, so the timeline never collapses silently.

## Implementation
- Migration: `bu_console_kpi_advance` rewritten (stage path, inheritance, per-stage audit,
  `will_supersede` / `superseded` counters).
- `src/lib/review/supersedeChain.ts` — pure planner + captions, 6 unit tests.
- `src/hooks/useBuConsoleRun.ts` — new skip labels and counters.
- `src/components/admin/bu-console/KraWorksheet.tsx` — states what a leap will close.

## Rollback
Single revert of the migration restores the strict check; no data migration involved.
