# ADR-300 — An evidence preview must never fail while a working transport exists

**Status:** Accepted — 2026-08-19
**Policy:** POLICY §EVIDENCE-PREVIEW-TRANSPORT-FALLBACK

## Context

Ashish Kataria (200226) could not open
`200083_Quotation_Collection...jpg`. Diagnostics (added by ADR-298):

`status=none name=Error msg=The file server is busy right now… elapsed=20009ms attempts=1 bucket=review-evidence kpi=331c01ff-8b7a-4a5e-90af-a41f2fda33ad class=other`

Verified before changing anything:

- The object exists — a 16 KB JPEG (plus a 19 KB XLSX) in `review-evidence`.
- Access is fine: 200083 → Somnath Roy (200296) → Ashish, so
  `can_read_kpi_evidence()` returns true on its cheap manager-of-manager branch.
  A 20 s server-side RLS stall on that path is not credible.
- The authenticated object GET (`/storage/v1/object/review-evidence/…`) used by
  Download succeeds in the logs; the preview instead uses
  `POST /storage/v1/object/sign/…`, which never answered.
- `EvidencePreviewDialog` raced ONE 20 s timeout against the whole ADR-298 retry
  loop, so the first hung sign call rejected everything — hence `attempts=1` —
  and the rejection carried the *busy* message, classified `other`.

### 5 Why

1. Preview fails → the 20 s guard fires.
2. Guard fires → the signed-URL POST never returns.
3. Never returns → the request stalls between browser and Storage, while the
   plain authenticated GET for the same object succeeds.
4. The stall is fatal → the timeout raced the entire loop, so no retry and no
   alternative transport ran.
5. No alternative → the preview had exactly one transport and no vocabulary for
   "hung", so it told the user to retry something that could not succeed.

## Decision

1. Transport policy moves out of the component into
   `src/lib/review/evidencePreviewLoader.ts` (UI stays rendering-only).
2. **Per-attempt timeout** (`SIGN_ATTEMPT_TIMEOUT_MS = 6 s`) inside the same
   20 s overall budget, so the `[400, 1200] ms` backoff retries actually run.
3. **Download fallback**: when signing hangs or the server is under pressure,
   fetch via `storage.download()` and render from an object URL, capped at
   `FALLBACK_MAX_BYTES = 8 MB` so ADR-250's no-buffering rule still holds for
   large files. Network-blocked failures skip both retry and fallback.
4. **New failure class `hang`**: `EvidenceTimeoutError` /
   `isHungEvidenceError()` / `EVIDENCE_HUNG_MESSAGE`. A status-less timeout is
   never reported as "server busy" again. Diagnostics now carry
   `transport=` and `fallback=` (`not-tried` / `failed` / `too-large`).

## Consequences

- The reported file opens through the fallback even while signing is stuck.
- Diagnostics distinguish hang, network-blocked, busy and denial.
- No RLS, schema or storage change; access rules untouched.
- Rollback: revert the frontend commit.
