# ADR-271 — KPI type-aware review surfaces & console filter honesty

Status: Accepted · Supersedes nothing · Related: ADR-268, ADR-270

## Context
1. BU Performance Console filters are held in local state and only committed on
   "Load console". Changing a filter left the category strip and counts looking
   current while they described the previously loaded scope.
2. The console drawer, and `RatingScaleDisplay` across review surfaces, rendered
   a hardcoded R0–R5 grid. Binary (2,977 KPIs) and tiered (458 KPIs) definitions
   for 2026 were shown as if they were value-based, or hidden entirely
   (`RatingScaleDisplay` returned `null` when `r1..r5` were blank).
3. Group value entry accepted a free numeric field even for Yes/No KPIs.

## Decision
- `src/lib/kpiScoringModel.ts` is the SSOT resolver: every KPI resolves to
  `numeric | binary | tiered | unconfigured`, with options sorted high → low and
  blank thresholds dropped. Stored `qualitative_options` always win, so inverted
  safety binaries (No = 5) survive.
- `src/components/review/KpiScoringScale.tsx` is the only scoring-scale renderer
  for new surfaces; it states "no scoring logic configured" instead of drawing
  empty boxes.
- `RatingScaleDisplay` renders qualitative options for binary/tiered KPIs.
- Group value entry uses an option picker for qualitative KPIs and stores the
  option's 0–5 rating (never `parseFloat(label)`).
- A title whose rows carry more than one `uom_type` disables group value entry
  and shows the conflict; one value cannot mean a number and a Yes/No answer.
- `ScopeToolbar` exposes an `isDirty` state: the apply button relabels and the
  tree dims while the shown data is stale.

## Consequences
- Display-only + input-shape change. No scoring formula, RPC signature or
  historical value is altered; `bu_console_tree` / `bu_console_kpi_detail` now
  carry `uom_type`, `qualitative_options` and `uom_types` (additive).
- Regression guard: `src/test/kpiScoringModel.test.ts`.
