

# Document and Test RLS Policies

## Current State
- RLS policies exist in 53+ migration files and are applied to the live database
- `DOCUMENTATION.md` (lines 311-370) describes general patterns but lacks a complete per-table inventory
- No tests verify that policies behave correctly (e.g., employee can't read another employee's KPIs)

## Changes

### 1. Create `docs/rls-policies.md` -- Consolidated RLS Reference
A dedicated file listing every table, its RLS status, and each policy with its name, operation, role, and condition. Organized by domain (auth, KPI workflow, admin, etc.). This will be generated by querying the live database for the current policy set, then formatted into a readable reference.

### 2. Update `DOCUMENTATION.md` -- Cross-reference
Add a pointer from the existing RLS section to the new dedicated file, keeping the pattern summary but directing readers to the full inventory.

### 3. Create `src/test/rls-policies.test.ts` -- RLS Policy Verification Tests
Write Vitest tests that use the Supabase client to verify key access control behaviors:
- Employee cannot read another employee's KPIs
- Manager can read direct reports' KPIs but not others'
- Admin can read all KPIs
- Unauthenticated users cannot access protected tables
- Auditor/Management can only update KPIs at their designated workflow stages

These tests will use the existing Supabase test infrastructure and document expected behavior as executable specifications.

### 4. Create a migration audit script: `docs/rls-audit.sql`
A SQL query that can be run against the database to list all tables, their RLS status, and all policies. This gives admins a way to verify the live state matches the documented state at any time.

```sql
-- Example audit query
SELECT schemaname, tablename, policyname, permissive, roles, cmd, qual
FROM pg_policies
WHERE schemaname = 'public'
ORDER BY tablename, policyname;
```

## Technical Details

| File | Change |
|---|---|
| `docs/rls-policies.md` | New file: complete per-table RLS policy inventory |
| `docs/rls-audit.sql` | New file: SQL query to audit live RLS state |
| `src/test/rls-policies.test.ts` | New file: behavioral tests for key RLS rules |
| `DOCUMENTATION.md` | Add cross-reference to `docs/rls-policies.md` |

## Approach
1. Query the live database (`pg_policies` view) to extract the current complete policy set
2. Format into the `docs/rls-policies.md` reference document
3. Write behavioral tests for the most critical access control rules
4. Update documentation with cross-references
