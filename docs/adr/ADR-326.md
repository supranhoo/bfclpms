# ADR-326 — Mixed group edits: partition by field class, no phantom changes

Date: 2026-08-26
Status: Accepted

## Context

*Ensure target availability of Kiln and all associated equipment* (Jul 2026)
previewed as "0 rows will change · 3 skipped". All three employees
(Biswanatha Mahanta, Devendra Kumar Yadav, K Srinivasa Rao) carry an approved
final score, so they are immutable under POLICY §88.

Two defects made the edit impossible and unexplainable:

1. The change set was not descriptive-only, so ADR-323's automatic bypass never
   engaged — even though the admin had only retyped wording. The editor was
   emitting `org_level_scope: ''` (and the scope-target columns) because the row
   carried a stale scope value while `is_org_level` was false. A phantom change
   dragged the whole run onto the protected path.
2. Locking is row-wide: one protected field poisoned the entire row, so nothing
   was written and the preview said only "protected rows skipped" with no reason
   and no names.

## Five Whys

1. Nothing was written → the run took the protected path.
2. It took the protected path → the change set contained a scoring field.
3. It contained one → the editor emitted a scope clear the admin never typed.
4. It emitted it → the diff compares a stale DB value against a UI default
   without asking whether scope is even meaningful for this KPI.
5. That was invisible → the preview reported a row count, not a cause.

Root cause: the edit was treated as one indivisible unit, and the diff had no
notion of a field being inert for the row it targets.

## Decision

1. **Field-level partitioning.** `bu_console_group_edit_definition` applies the
   wording slice of a mixed change set to locked rows and withholds the protected
   slice, reporting those rows as `partially_applied` with the withheld field
   list. A row is skipped only when nothing can be written.
2. **No phantom scope changes.** The editor omits `org_level_scope` and the
   scope-target columns whenever the KPI is not organisation-level and was not
   organisation-level before.
3. **Honest preview.** Per-month rows state the real reason
   ("Final score approved — immutable (POLICY §88)"), a `wording only` count, and
   a note naming the fields that stay unchanged on locked rows.

Weightage, targets, bands, frequency/cycle and scope remain the scoring source of
truth and are never written to a locked row by this path.

## Consequences and rollback

Strictly widens what a wording correction can reach while strictly preserving
score immutability. Rollback is function/UI restoration; committed runs stay
individually undoable per month.

Stale `org_level_scope` values on non-org rows were left in place: the review
period lock rejects a bulk data rewrite, and the client-side gate makes them
inert. They will clear the next time the row is edited through the console.
