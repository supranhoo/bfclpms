# ADR-104 — Restore employee SELECT on Org-KPI evidence prefix

**Date:** 2026-07-01
**Status:** Accepted

## Context
After the 2026-06 storage hardening (ADR-096 write path, ADR-099 private-bucket
download), employees viewing an Organization KPI could no longer preview or
download its supporting file. The `EvidencePreviewDialog` surfaced
"Preview failed: Object not found" — Supabase Storage's response when RLS
hides the object.

### 5-Why
1. Object 404 → RLS hides it from the caller.
2. Only SELECT policy on `review-evidence` (`Users can view authorized evidence`,
   migration `20260622103745`) keys `foldername[1]` to a profile UUID or grants
   admin/auditor/hr_pms.
3. Org-KPI files live under a shared prefix `org-kpi-evidence/<file>`, so the
   first folder segment is the literal string, never a UUID.
4. Migration `20260626112752` added INSERT / UPDATE / DELETE for that prefix
   but omitted the SELECT counterpart, assuming the per-employee SELECT policy
   would cover it.
5. No regression test asserted "authenticated user can SELECT
   `org-kpi-evidence/*`", and the security review focused on write paths and
   signed downloads, not read visibility of the shared org prefix.

## Decision
Add a scoped SELECT policy on `storage.objects` that mirrors the existing
write-side policies for the same prefix:

```sql
CREATE POLICY "Org KPI evidence select"
ON storage.objects FOR SELECT TO authenticated
USING (
  bucket_id = 'review-evidence'
  AND (storage.foldername(name))[1] = 'org-kpi-evidence'
);
```

Org-KPI evidence is a company-wide artifact already surfaced through the
Org-KPI cards; authenticated SELECT on the shared prefix matches its intended
visibility and does not widen per-employee folder access.

## Alternatives considered
- **Rewrite paths to per-employee folders.** Rejected — Org-KPI files are a
  single company-wide artifact; per-employee copies would explode storage and
  break resync semantics (`resync_org_kpi_evidence`).
- **Make the bucket public.** Rejected — per-employee evidence must stay
  RLS-gated (ADR-099 rationale).

## Consequences
- Employees, managers, skip-level managers, HR PMS, auditors, admins can all
  read Org-KPI attachments again.
- Preview + download flows in `EvidencePreviewDialog` and `OrgKpiFileUpload`
  work without code changes — signing/blob paths already handled RLS success
  cases correctly.
- Per-employee folder policy `Users can view authorized evidence` is
  untouched.

## Invariant introduced
Every prefix in the `review-evidence` bucket MUST have matching SELECT +
INSERT + UPDATE + DELETE policies. Write-only or read-only prefixes are
prohibited. Enforced by `src/test/orgKpiEvidenceSelectPolicy.test.ts` for the
`org-kpi-evidence/` prefix; extend the pattern for any new prefix.

## Rollback
```sql
DROP POLICY IF EXISTS "Org KPI evidence select" ON storage.objects;
```
