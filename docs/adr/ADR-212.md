# ADR-212 — Annual Review Report: Final Rating (out of 5) and Increment Slab

Date: 2026-07-31
Status: Accepted

## Context
HR needs the Annual Review Report to express the Final Score on the familiar 5-point
appraisal scale and to show the increment percentage that the rating attracts. The
percentages are business policy and change between cycles, so they cannot be hardcoded.

## Decision
1. Final Rating (/5) = `annual_review_instances.total_score / 20`, rounded to 2 dp.
   `total_score` is already normalised 0–100 (ADR-187), so no other rescaling is needed.
   A null score yields a null rating and a null slab — never 0%.
2. Increment slabs are master data in `public.annual_review_rating_slabs`
   (`rating_from`, `rating_to`, `increment_percent`, `sort_order`, `is_active`).
   Read: any authenticated user. Write: Admin / HR PMS via `has_role`.
   Seeded bands: <2 = 0%, 2–2.5 = 4%, 2.5–3 = 6%, 3–3.5 = 8%, 3.5–4 = 12%,
   4–4.5 = 16%, ≥4.5 = 20%.
3. Matching is half-open `[rating_from, rating_to)` — an exact boundary falls into the
   higher band. The highest band is open-ended (`rating_to IS NULL`).
4. `src/lib/annualReview/ratingSlab.ts` is the single implementation
   (`toRatingOutOf5`, `resolveSlab`, `resolveSlabPercent`, `validateSlabBands`),
   consumed by the Detail tab, Comprehensive tab, both Excel exports and the admin editor.

## Consequences
- Two additive columns in the report and exports; no existing data is mutated.
- Band edits take effect immediately (React Query cache, 5 min stale time).
- Band sets are validated for gaps/overlaps before save.
- Rollback: drop the table and revert the column additions.
