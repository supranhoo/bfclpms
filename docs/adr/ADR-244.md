# ADR-244 — Calibration context must be cycle-scoped

- Status: Accepted (2026-08-04)
- Related: ADR-220 (calibration), ADR-230 (report-wide effective outcome)

## Context
All 27 calibrations on the 2025-2026 cycle were intact and honoured by the Bell
Curve (its RPC LEFT JOINs `annual_review_calibrations`), yet the Annual Review
Report showed none of them:

- Detail tab passed only the current page of instance ids (25 of 2,589) to
  `useAnnualReviewCalibrations`, so a page containing a calibrated employee was
  a near-impossibility and the columns read as permanently empty.
- Comprehensive tab passed all 2,589 ids into the same `.in(...)`, producing a
  request URL of ~100 KB. The query failed and the hook's `data ?? {}` default
  rendered the failure as "no calibrations exist" — grid, drill-down, rating
  distribution and the main workbook all showed raw ratings.

## Decision
1. `useAnnualReviewCycleCalibrations(cycleId)` is the loader for every report
   surface: one query filtered on `annual_review_instances!inner(cycle_id)`,
   keyed by `instance_id`.
2. `useAnnualReviewCalibrations(ids)` remains only for genuinely small sets
   (a single instance detail page). Report surfaces must never build the filter
   from a per-row id list.
3. A failed calibration fetch renders an explicit inline warning
   ("Calibration data could not be loaded — ratings shown are uncalibrated")
   instead of degrading silently to `{}`.

## Consequences
- Bell Curve, Detail tab, Comprehensive tab and both exports agree again.
- Presentation only — no schema, RPC, RLS or stored-score change.
- Guard: `src/test/annualReview/calibrationContextScope.test.ts`.
