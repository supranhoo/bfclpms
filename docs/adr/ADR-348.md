# ADR-348 — Team Reviews defaults to "Pending action only" queue

- Status: Accepted
- Date: 2026-09-03
- Policy: POLICY.md §129

## Context

Reviewers landing on Team Reviews saw their entire mapped downline (direct +
skip-level + functional reports), most of whom had nothing awaiting the
reviewer. The actionable employees were buried among fully-reviewed and
no-KPI cards.

## Decision

1. `src/lib/review/actionableQueueFilter.ts` is the SSOT: a member is
   *actionable* when `getEmployeeKpiStats(...).badge1 > 0` — the existing
   relationship-aware pending count (direct → `self_review`, indirect →
   skip-reviewable statuses, functional → FM-reviewable statuses).
2. `EmployeeSelectorGrid` (viewLevel `team` only) applies the filter after the
   status-tile pipeline and before the urgency sort. State lives in the URL as
   `?queue=all`; the default `actionable` never writes to the URL and Clear All
   restores it (`queue` added to `FILTER_PARAM_NAMES`).
3. UI: a "Pending action only" switch under the filter row with an
   "X of Y members have items pending" caption; when the queue is empty a
   dedicated "All caught up" empty state offers "Show all team members".
4. Top tile counters are untouched — they always reflect the full roster.

## Consequences

- Reviewers see only their actionable queue by default; one switch reveals the
  full downline. No data, RLS, or workflow change.
- Other reviewer panels (HR PMS, Audit, Management) unchanged.

## Addendum 348b — Structured KPI header duplication fix

`KpiHeaderSection.displayKpi` preferred the canonical registry `kpi_name` over
the structured title. For structured rows that canonical name is the full
composed blob (title + description + formula + scoring), so the View KPI
Details dialog printed the raw blob above the structured Formula/Scoring Logic
blocks — a structured KPI looked unstructured. Precedence corrected: structured
rows render their title; the canonical override applies to legacy rows only.
