# ADR-334 — Opt-in legacy display-name rename from the group definition editor

**Status:** Implemented  
**Date:** 2026-09-01

## Context

Editing a KPI group in the Performance Console rewrites the structured definition fields (Title, Description, Formula, Scoring logic). Those changes surface immediately on the Employee Dashboard, the scorecard and the console. The legacy `kpi_name` (and its KRA name) is deliberately not touched (ADR-269) because it is the join key for Org KPI matching and historical report alignment. The consequence: Org KPI Data Entry, the KPI Status Tracker and Excel exports keep showing the old wording after a group edit, so the same KPI reads two different ways.

## Five Whys

1. Reports show the old wording after a group edit — because `kpi_name` was not rewritten.
2. It was not rewritten — because the group editor intentionally excludes it (ADR-269).
3. It is excluded — because renaming the join key can break Org KPI matching and history.
4. That risk was never mitigated in this surface — because the safe rename engine (ADR-330) lives only in the KPI Standardization tool.
5. Admins did not bridge the two — because nothing in the editor pointed at, or offered, the rename.

## Decision

- Add an opt-in rename block to **Edit definition for the whole group**, off by default.
- Reuse the existing reversible engine: `correct_kpis_range_dry_run` for a per-month preview and `correct_kpis_range` for one undoable apply. No new database objects.
- New KRA / KPI names are pre-filled from the current KRA and the structured Title.
- The rename range defaults to the console month through the end of that fiscal year, and month options below the May 2026 forward-only floor are not offered.
- The rename runs only after the definition edit commits successfully. If the rename fails, the definition changes stay, the failure is surfaced, and the dialog stays open for a retry.
- The Apply button and the dialog description both state, before commit, that a rename is included and how many rows it will touch.

## Consequences

- One rename is one reversible action, visible and undoable in KPI Standardization.
- Renames stay text + definition binding only; targets, weightages, scores, ratings and workflow status are never written.
- Admins who do not opt in keep the previous behaviour exactly.

## Tests
