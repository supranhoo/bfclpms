# ADR-101 — Chunked backup download must iterate manifest.files[]

## Status

Accepted — 2026-06-29.

## Context

ADR-082 introduced streaming chunked exports in `create-backup`: large tables
are split into `<table>.part-NNNNNN.json` chunks (5000 rows each) and the
manifest records both `file` (first part, back-compat) and `files: string[]`
(authoritative full part list) per table.

`restore-backup` was updated to iterate `entry.files` and upsert every part.
The client-side download path in `src/hooks/useBackups.ts` (`useDownloadBackup`,
chunked branch) was not. It read `entry.file` only and silently dropped every
subsequent part — for a backup with ~250 MB across many part files the merged
download came out at ~60 MB (first 5000 rows per large table). Re-uploading
that artifact through `useUploadAndRestore` would silently restore a fraction
of the affected tables.

## Decision

`useDownloadBackup` now resolves
`parts = entry.files?.length ? entry.files : (entry.file ? [entry.file] : [])`
for each manifest entry, downloads every part, parses each as a JSON array,
and concatenates rows into `combinedData[table]`. A `console.warn` is emitted
when the assembled row count diverges from `entry.rows` so QA can spot silent
failures. Per-part `try/catch` preserves the prior "skip-and-continue"
resilience. Legacy single-file backups (non-manifest branch) and legacy
chunked manifests without `files[]` continue to work via fallback.

Policy §BACKUP-DOWNLOAD-COMPLETENESS pins this contract.

## Consequences

- Downloaded artifact size now matches `backup_logs.file_size_bytes`.
- Browser holds the full merged JSON in memory once during concatenation.
  Acceptable on admin-only desktops; if backups exceed ~500 MB we should
  switch to a streamed ZIP via `fflate` (out of scope here).
- Previously-downloaded "60 MB" artifacts are permanently truncated — admins
  must re-download after this release.

## Rollback

Revert `useDownloadBackup` body in `src/hooks/useBackups.ts` and delete
`src/test/backupDownloadChunkedParts.test.ts`. No DB, RLS, edge-function, or
storage changes.
