# ADR-247 — Employee Master column parity (grid + import/export)

Status: Accepted (2026-08)

## Context
Two gaps were confirmed against the implemented Employee Master requirements:
1. The User Management grid rendered a fixed 10-column set. Functional Manager (F1),
   Location, Employee Category, Employment Status, GDOJ/DOJ/Confirmation Date,
   Portal Access, Dummy flag and every admin-defined custom field were invisible.
2. Bulk import/export omitted `mobileNumber`, `isDummyEmployee` and all custom
   fields, so a full round-trip silently dropped data.

## Decision
- `src/lib/employeeMasterColumns.ts` is the SSOT for optional grid columns,
  localStorage persistence and import documentation mapping.
- `useEmployeeMasterRowExtras` hydrates non-roster columns for the **current page
  only** (bounded cost; the slim roster RPC stays slim).
- `UserManagement.tsx` renders a "Columns" chooser; selected columns render
  dynamically in header and body via `renderOptionalCell`.
- `ImportData.tsx` parses `mobileNumber` / `isDummyEmployee` and one column per
  active custom field (matched on `field_key` or label), writes them on both the
  create and update paths, and merges custom values into the existing JSONB row
  so a partial sheet never wipes untouched fields.
- Template, export and on-screen documentation are generated from the same list,
  so import ↔ export headers round-trip.

## Consequences
- Additive only; default visible columns are unchanged. Rollback = clear the
  saved column selection (no schema change was made).
- Regression: `src/test/employeeMasterColumnParity.test.ts`.
