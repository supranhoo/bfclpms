# ADR-310 — Org KPI Data Entry must list every definition the employee scorecard lists

Status: Accepted — 2026-08-22
Policy: POLICY §ORG-KPI-ENTRY-WINDOW-VISIBILITY
Related: ADR-061 (scoped entry table), POLICY §98 (empty-state classification), POLICY §128 (frequency cycle anchors)

## Symptom

Md Humayun (100078), July 2026: the employee scorecard listed 11 org-level KPIs at
`kra_set` with blank values and a 0% score, while Org KPI Data Entry reported
"10 of 10 KPIs entered — 100%" and several of those KPI names could not be found
anywhere on the entry page.

## Investigation (July 2026, verified in the database)

| Fact | Value |
| --- | --- |
| Org-level `kpis` rows for July 2026 | 1,171 across 174 employees |
| Distinct org-level definitions | 199 |
| Definitions the entry page rendered | 166 |
| Monthly (window open in July) | 166 |
| Bi-Monthly `Jul-Aug` (window opens August) | 19 |
| Quarterly `Jul-Sep` (window opens September) | 2 |
| Bi-Monthly with NULL `frequency_cycle_start` | 1 |
| Definitions with no mapped employees | 5 |

So the missing names were not a propagation failure. Every definition existed, was
mapped, and was correctly `kra_set` on the employee side. The entry page simply did
not draw 22 of them.

## Root cause (5 Why)

1. KPI names missing from Org KPI Data Entry → the page filtered them out.
2. Why? `frequencyFilteredKpis` dropped any KPI where `isKpiLockedForPeriod` was true.
3. Why is that wrong? A multi-month KPI is *entered* in the last month of its cycle but
   *exists* in every month of it. The lock was used as a visibility rule when it is only
   an editability rule.
4. Why did nobody notice? The employee scorecard derives its list from `kpis` rows
   directly and therefore always showed them — the two surfaces used different rules.
5. Why did the two rules diverge? No policy stated that the admin entry list and the
   employee scorecard must enumerate the same definitions for a period.

A secondary defect: one Bi-Monthly definition ("Power generation from 45 MWh/WHRB")
carried no `frequency_cycle_start`, so its lock month was inferred from a default cycle
rather than its real one.

The "100%" reading was a consequence, not a separate bug: the denominator counted only
the definitions that survived the filter.

## Decision

**Show, don't hide.** Locking controls *editing*, never *existence*.

- `describeEntryWindow(frequency, period, year, cycleStart)` (in
  `src/lib/frequencyUtils.ts`) returns `{ status: 'open' | 'not_due', dueMonth,
  cycleLabel, label }`. It calls the existing lock helper and only *describes* the
  result — the lock rule is byte-for-byte unchanged.
- `OrgKpiDataEntry` no longer removes locked definitions. Not-due ones render as
  read-only amber cards labelled "Not yet due — entry opens in <month>", reachable
  through a new "Not yet due" filter chip.
- Progress, the Pending / Entered / Propagated / Stuck chips and the per-category
  badges are scoped to open windows, so the completion figure means "of the KPIs you
  can actually enter this month".
- `OrgKpiEntryCard` accepts `notDueLabel` and hard-locks its inputs when set.
- `deriveOrgKpiEmptyState` gains `all-not-yet-due` for periods where every definition
  opens later.
- Admin diagnostics print `unmapped / not yet due / enterable / grouped` counts.

## Data repair

- The NULL Bi-Monthly anchor was set to `Jul-Aug`, audited as `cycle_anchor_repaired`
  with `performed_by = NULL` (automated action). July 2026 now holds zero anchorless
  multi-month definitions.
- July `org_kpi_values` placeholders materialise through the existing per-card
  `ensure_org_kpi_scope_rows` call, which now fires for the previously hidden cards
  as well.

## Consequences

- The two surfaces can no longer disagree about which KPIs exist for a period.
- Users see *why* a value cannot be entered instead of the KPI vanishing.
- No schema, RLS, scoring, propagation or workflow change. Rollback = revert the four
  frontend files.

## Verification

- `src/test/orgKpiEntryWindow.test.ts` — 10 tests: monthly always open, Bi-Monthly
  Jul-Aug not due in July / open in August, Quarterly Jul-Sep, Jan-Feb cycle viewed in
  July, year-boundary wrap, and the exact July 2026 shape (166 open / 22 not due).
- `src/test/orgKpiEmptyState.test.ts` — 10 tests including the new `all-not-yet-due`
  classification.
