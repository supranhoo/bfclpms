# ADR-298 — Evidence preview failures must name the real failure class

## Date
2026-08-18

## Status
Accepted

## Context
Ashish Kataria (200226) repeatedly hit "The file server is busy right now —
please retry in a moment." when opening
`200083_Post_Auction_Negotiation_Compliance_Self_Evidence.png`, and Retry never
helped.

Verified before changing anything:
- The object is not missing: 0 of 11,943 self-evidence URLs lack a matching
  object in `review-evidence`.
- The message is not a permission message. In `src/lib/review/evidenceError.ts`
  only `isTransientEvidenceError()` produces it — 5xx/408/429, statement
  timeout, the 20 s preview guard, **or a fetch-level failure**
  (`Failed to fetch`, `network error`, `aborted`).
- The preview path only calls `storage.createSignedUrl()`.

So two very different causes collapsed into one message: (1) the request never
reached the server (extension / ad-blocker / corporate proxy / offline), where
retry can never succeed; (2) genuine server pressure, where retry may succeed.

## Decision
1. `isNetworkBlockedEvidenceError()` classifies status-less fetch failures
   separately and renders "We couldn't reach the file server… try another
   browser, or use Download instead." Server-answered failures (5xx / 408 /
   429 / 57014 / timeout) keep the retryable busy message.
2. The signing call retries with backoff (400 ms, 1200 ms) inside the existing
   20 s guard, and short-circuits immediately on a network-blocked failure.
3. `describeEvidenceFailure()` emits a copyable one-line diagnostic
   (status, error name, message, elapsed ms, attempts, bucket, KPI id, class),
   shown under the error state and logged to the console, so support can tell
   the two causes apart from a single screenshot.
4. The safety-side preview normalises its error through the same helper.

## Consequences
- Users blocked by a local extension/proxy get an actionable instruction
  instead of an infinite retry loop.
- Single transient blips self-heal without user action.
- No RLS, schema or storage change; access rules are untouched.
- Rollback: revert the frontend commit; nothing to undo in the database.
