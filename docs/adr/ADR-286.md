# ADR-286 — Performance Console: Review Run worksheet

**Status:** Accepted · **Date:** 2026-08

## Context
The console could only *inspect* groups; running the review still meant opening
the dashboard one employee at a time. For a shared KPI ("Dust emission") one
org value lands on 50+ people, so employee-by-employee processing is pure
overhead.

## Decision
A **Review Run** tab: a KPI x employee worksheet for the loaded scope.
- KPIs are rows, employees are columns (shared values fan out along a row).
- Server SSOT `bu_console_run_snapshot(period, year, stage, filters, page)` —
  SECURITY DEFINER, paged at 100 employees, refuses scopes over 25,000 cells
  (`capped: true`) instead of degrading.
- Selection by cell, row (click the KPI) or column (double-click the person).
- Moves go through `bu_console_kpi_advance(kpi_ids[], stage, remarks, dry_run)`:
  workflow-aware, audited as one batch, dry-run first.
- Approved rows (`final_score IS NOT NULL`) are never selectable — POLICY §88.
- Tier gating is unchanged (ADR-284/285): management and audit may act only on
  KPIs that have left KRA Set; `hr_pms` stays read-only.
- Column header opens `EmployeeScorecardDrawer` — the person-first view that
  closes out one whole scorecard in a single audited batch.

## Consequences
- Reviews for shared KPIs collapse from N employee visits to one worksheet pass.
- No client-side writes to `kpis` / `review_submissions`; every path is an RPC.
- The grid never auto-loads: scope or stage change resets it to "Load worksheet".
