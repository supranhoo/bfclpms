# ADR-054: Canonical Org KPI key normalisation

- Status: Accepted (May 2026)
- Context: Three independent code paths normalised KRA/KPI strings differently (lowercase only / lowercase + collapse / lowercase + collapse + CR-strip). Whitespace drift accumulated across migrations (KPI Standardization Registry, KRA Library Master, Copy-KRAs) and silently broke every join keyed on `(category_id, kra_name, kpi_name)`. Symptom: admins saw "No org-level KPIs found" and propagation appeared to do nothing for ~30 owner rows.
- Decision: One helper, `src/lib/orgKpiKey.ts`, exposes `normalizeText` and `normalizeKpiKey`. Contract: strip `\r`, lowercase, collapse `\s+` to a single space, trim. All four call sites (useOrgLevelKpis, useOrgKpiDataOwner, OrgKpiDataEntry page, getOwnerNamesForKpi) delegate to it. Unit tests in `src/test/orgKpiKeyNormalization.test.ts` lock the contract.
- Database side: a one-shot migration normalised existing `org_kpi_data_owners` rows (228 updated, 5 duplicate rows removed) and snapshotted every change into `org_kpi_owner_key_backup` for reversibility. KPI rows themselves are NOT rewritten because their text contains intentional multi-line descriptions.
- Consequences: client-side joins remain whitespace-tolerant even if future migrations reintroduce drift; the cleanup migration is the floor, not the ceiling.
