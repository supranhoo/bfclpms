# ADR-067 — Bulk Override Propagates to Org KPI Master + entered_by Resolution

Date: 2026-05-31
Status: Accepted

## Context
`bulk_management_approve` (override mode) corrects the achievement on
`review_submissions.achieved_value`, but the per-stage scorecard reads
the Org-KPI achievement from `public.org_kpi_values`. The master row was
never updated, so corrected values stayed invisible at every stage. The
`kpi_cell_detail` RPC also returned the raw `entered_by` UUID, which the
Bulk Review cell drawer rendered as `Data entered by: <uuid>`.

## Decision
1. `kpi_cell_detail` joins `profiles` and exposes `org_kpi.entered_by_name`.
2. `bulk_management_approve` (override branch) back-writes the corrected
   achievement into the matching `org_kpi_values` row (scope: organization
   / department / employee — department resolved from the employee's
   profile). Stamps `entered_by = auth.uid()`. Emits an
   `ORG_KPI_VALUE_OVERWRITTEN` audit row (`source =
   bulk_management_approve_override`).
3. Existing review_submissions snapshots are NOT mutated — POLICY §88
   (Submission Snapshot Immutability) is preserved. Re-propagation across
   peer submissions remains an explicit Admin/Data Owner action.
4. One-off repair migration backfills `org_kpi_values` for already-overridden
   Org KPIs (`source = data_repair_2026_05_31_adr067`).

## Consequences
- Per-stage Self/Manager/Skip/HR-PMS panels for Org KPIs now reflect the
  corrected achievement after bulk override.
- The Bulk Review cell drawer's "Data entered by" badge shows the user's
  full name.
- Frozen final scores and submission snapshots are untouched.
