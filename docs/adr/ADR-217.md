# ADR-217 — Admin correction of Annual Review System Scores

Status: Accepted (2026-07-31) · POLICY §AR-SYSTEM-SCORE-ADMIN-CORRECTION

## Context
System Score raw values (LTI, STI, UA/UC NM, 5S, Trainings…) reach an instance
only through the cycle bulk upload. When a measurement is later restated, the
only available write path was `admin_apply_system_scores_upgrade` (ADR-171),
which is deliberately **monotonic** — it silently blocks downgrades — and is
driven from the bulk dialog, not from the employee's review page. There was no
supported way to correct a single wrong value, in either direction, from the
review page an admin is already looking at.

## Decision
1. New audit table `public.annual_review_system_score_edits` — one row per
   corrected slot with old/new raw, old/new points, old/new total score and
   final rating, mandatory reason and actor. Admin-read only; RLS enabled.
2. New `SECURITY DEFINER` RPC
   `admin_update_system_scores_raw(p_instance_id, p_system_scores,
   p_system_scores_raw, p_slot_names, p_reason)`:
   - requires `has_role(auth.uid(),'admin')` and a non-blank reason;
   - merges the supplied slots into `system_scores` / `system_scores_raw`
     **bidirectionally** and regardless of `overall_status` (including
     `completed`);
   - recomputes `total_score` / `final_rating` via
     `annual_review_compute_final_summary` so the Annual Review Report,
     Final Rating (/5) and increment slab (ADR-212) stay consistent;
   - writes per-slot audit rows plus a
     `system_scores.admin_edit` entry in `annual_review_access_audit`.
   ADR-171's monotonic RPC is untouched and remains the bulk-upload path.
3. Front-end: `src/services/annualReview/adminSystemScores.ts` (payload SSOT,
   raw→points via `scoreFromRaw`) and
   `src/components/annual-review/AdminSystemScoresDialog.tsx`, opened from an
   admin-only "Update system scores" button next to "Fill eligibility inputs"
   on the review detail page.

## Non-goals
- `carry_kra` slots are excluded — they are computed live from monthly KRA data.
- No bulk correction UI; the bulk upload path is unchanged.

## Consequences
- Admins can fix a wrong measurement in place, up or down, on any status.
- Every correction is reason-bound and reconstructable from the audit table.
- Editing a completed review changes the final score; the dialog warns explicitly.

## Regression coverage
- `src/test/annualReview/adminSystemScores.test.ts` — carry_kra exclusion,
  band-derived points, changed-only payload, bidirectional corrections,
  blank/non-numeric handling.
