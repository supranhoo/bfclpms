# ADR-270 — BU Console: KPI layer rebuilt on the text split

- **Status:** Accepted
- **Date:** 15 August 2026
- **Related:** ADR-259, ADR-264, ADR-268, ADR-269, ADR-269b, POLICY §BU-CONSOLE-KPI-NODE

## Context
`bu_console_kpi_detail` raised `column reference "business_unit_id" is
ambiguous`, and the tree keyed KPI nodes on the raw `kpi_name` blob, so one
metric appeared as several nodes and per-employee definition differences were
invisible.

## Decision
Key console KPI nodes on the normalised structured title, and make definition
differences explicit as *variants* derived from
`bu_console_variant_key(description, formula, scoring_logic, target)`. The
detail, group-write and group-advance RPCs take optional `p_title_key` /
`p_variant_key`; without them behaviour is unchanged.

## Consequences
- Aug 2026: 2,760 rows → 883 title nodes / 1,002 variants; 77 titles have >1
  definition variant, 181 have >1 weightage.
- Group actions can be scoped per variant; previews declare the variant span.
- Name-based grouping remains looser than an ID link — the standardization
  registry stays the long-term fix.

## Rollback
Re-deploy the previous function bodies and revert the three components.
