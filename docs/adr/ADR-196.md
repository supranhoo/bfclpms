# ADR-196: Functional Manager stage column completeness

- Status: Accepted (July 2026)

## Context
Approving a KPI at the Functional Manager (F1) stage failed with
`Could not find the 'functional_manager_achieved_value' column of 'review_submissions' in the schema cache`.
`UnifiedScorecard` writes `<prefix>_achieved_value` / `<prefix>_evidence_url` for every stage, but the F1 stage
had only 4 of the 6 standard reviewer columns; `functional_manager_evidence_urls` was additionally `NOT NULL`
while every peer stage was nullable.

## Decision
1. Add `functional_manager_achieved_value` (numeric) and `functional_manager_evidence_url` (text); make
   `functional_manager_evidence_urls` nullable.
2. Re-create `enforce_self_snapshot_mirror()` and `tg_review_submissions_self_column_guard()` enumerating the FM columns.
3. `bulk_write_stage_scores` mirrors `v_mirror_achieved` into `functional_manager_achieved_value` on score writes and
   NULLs it on N/A writes — peer parity with manager / skip_level / hr_pms / auditor. Applied as an assertion-guarded
   rewrite of the live definition so no unrelated logic drifted.
4. Generalised as POLICY §WF-STAGE-COLUMN-COMPLETENESS.

## Consequences
- F1 approvals (single and bulk) complete end-to-end; achieved values persist and carry into reports.
- Additive schema change only; rollback = drop the two columns (no data loss for existing stages).
- Regression: `src/test/reviewSubmissionsStageColumnParity.test.ts` (39) + `functionalManagerWorkflow.e2e.test.tsx` (27) + `reportStageParity.test.ts` (15) = 81 green.
