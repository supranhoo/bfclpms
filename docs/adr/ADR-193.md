# ADR-193 — Functional Manager as a first-class reviewer + rating-safe workflow edits

Status: Accepted

## Context
Employees mapped via `profiles.functional_manager_id` were invisible to their
Functional Manager (FM): roster RPCs keyed only on `reporting_manager_id`, and
`workflow_change_step_back()` used a hardcoded stage array without
`functional_manager_check`, nulling `final_score` with no snapshot when a
workflow was edited mid-flight.

## Decision
- DB: `get_manager_team_roster` / `get_reviewer_roster_slim` union
  `functional_manager_id` reports tagged `relationship = 'functional'`;
  `canonical_stage_order(_stage)` is the SQL SSOT for stage ordering;
  `workflow_change_step_back()` is additive-only and snapshots
  `prior_final_score` / `prior_final_rating`.
- UI: Dashboard unlocks Team view via `useIsFunctionalManager` (relationship,
  not role); `EmployeeSelectorGrid` renders a "Functional" badge and resolves
  pending/reviewed counts through `resolveReviewableStatuses('functional_manager')`;
  `kpiPendingWith` / `pendingWithResolver` attribute `functional_manager_check`
  to the named FM (fallback label "Functional Manager").

## Consequences
No hardcoded chain may omit FM. Ratings survive mid-flight workflow edits.
Regression: `src/test/review/functionalManagerPendingWith.test.ts`.
