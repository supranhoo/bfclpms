# ADR-093 — Incentive Dry-Run Preview must be programme-type aware

Status: Accepted (2026-06-29)

## Context

Upendra reported that the Incentive Computation Preview for "Metal Sizing"
(June 2026, Period 11–20) rendered N/A in PMS Score, Base %, DQ Reason,
LTI Penalty, Pro-rata and Final % columns for every employee while the
Amount column and Total Amount tile (₹68,687) were correct.

## Root cause

`compute-monthly-incentives` deliberately writes `pms_score: null` for
production-programme records (`supabase/functions/compute-monthly-incentives/
index.ts:708`). Production incentive is `tons × rate`, not a PMS-driven
percentage — PMS Score, Base % and Final % are not applicable.

`IncentiveDryRunDialog.tsx` rendered the same PMS-centric table for every
programme type and gated those columns on `r.pms_score != null`, so every
production row produced *N/A* visually, even though the underlying record
was correct and the amount was right.

## Decision

The dry-run preview is now programme-type aware via
`result.diagnostics.detected_program_type`:

- **production** → columns: Employee, Period, Production (tons),
  Rate (₹/ton, derived as `amount ÷ tons`), DQ Reason, LTI Penalty,
  Pro-rata, Amount (₹). A footnote clarifies that PMS does not apply.
- **support / vessel** → existing PMS-centric layout (unchanged).

The compute function, schema, totals tiles, and Confirm & Compute flow
are unchanged. This is a presentation contract only.

## Consequences

- Production reviewers no longer see a misleading wall of N/A.
- Future programme types must explicitly opt into the appropriate layout.
- Tests pin the production vs support presentation contract.
