# ADR-356 — Reviewer KPI card presentation pass (tablet / mobile)

Status: Accepted (2026-09-03)

## Context
A UI assessment of the reviewer KPI card list (screenshot at ~834px) found
eleven presentation defects in `src/components/review/MobileKpiCard.tsx`:
duplicated state signalling ("Approved" header badge plus a "Fwd" pill in the
action row), 9–10px labels and a 10px KPI description, an inverted hierarchy
where the KRA eyebrow outranked the KPI title, unaligned Target/Weight/Score
values with unit artefacts ("0 Date", "16 Number"), hardcoded palette
utilities instead of semantic tokens, several sub-44px touch targets, and a
single-column layout that wasted tablet width.

## Decision
Presentation-only rework of the card. No props, permissions, workflow,
scoring, RPC, RLS or schema changes — every caller (my-kpis, dashboard,
team-review, functional-manager-review, audit, management, skip-level,
hr-pms) inherits the fix.

1. **One badge, one place.** Workflow state is expressed only by the header
   status badge. The action row carries controls only: `View`, or
   `Review` + `Send back`. N/A, Locked and Draft (Mgmt) render as header
   badges next to the status badge.
2. **Hierarchy.** KPI title becomes the primary line (14px medium, 2-line
   clamp); KRA name is a 12px muted eyebrow. No text below 11px.
3. **Metric grid.** `Target / Weight / Score` render as a fixed three-column
   `dl` with `tabular-nums`, so values align across cards. Score shows
   `n / 5` (`MAX_RATING_SCORE`, matching `ratingOptions`). Type-descriptor
   units (`Number`, `Date`, `Count`, `Nos`) are suppressed via
   `NON_PRINTABLE_UOMS`.
4. **Semantic tokens.** All literal `amber-*/green-*/blue-*` utilities in the
   card are replaced by new `success` / `warning` / `info` badge variants
   backed by CSS variables; `--info` was added to both themes and to the
   Tailwind palette.
5. **Touch and a11y.** Every interactive element (View, Review, Send back,
   title button, org-scope tooltip trigger, daily expand) has a >=44px hit
   area, an `aria-label` where icon-only, and a visible focus ring.
6. **Layout.** Card padding 16px on a 4/8 rhythm; the card list in
   `UnifiedScorecard` becomes `grid-cols-1 md:grid-cols-2`, with the empty
   state spanning both columns.

## Consequences
- The tablet list reads at roughly double the density with larger type.
- Card state can no longer drift between the header badge and the action row.
- New `info` token is available system-wide for future state colours.

## Rollback
Revert `MobileKpiCard.tsx`, the `UnifiedScorecard` grid hunk, the badge
variants and the `--info` token. No data involved.

## Tests
`src/tests/mobileKpiCardPresentation.test.ts` (9 cases) plus the existing
`src/tests/reviewerReopenAffordance.test.tsx` (ADR-355) as the regression
guard for the labelled View control.
