# ADR-031: Sent-Back Indicator Detection

## Status
**Accepted**

## Date
2026-03-30

## Context
The Org KPI scoped table needs to show which employee KPIs have been sent back by a reviewer. The detection logic must correctly identify sent-back state.

## Decision
Sent-back state is detected by: (1) finding employee KPIs at `kra_set` status, and (2) cross-referencing with `kpi_queries` records of type `send_back` (any status — not just `'open'`).

## Alternatives Considered

### Alternative A: Filter by `kpi_queries.status = 'open'` only
- **Description:** Only show sent-back indicator when the send-back query is still open
- **Rejected because:** Send-back query records are auto-resolved when KPI status changes, so filtering by `status = 'open'` always returns empty results. The indicator would never appear.

### Alternative B: Add a `was_sent_back` boolean flag to KPIs table
- **Description:** Set a persistent flag on the KPI record when sent back
- **Rejected because:** Adds schema complexity and requires clearing logic. The existing data (KPI status + query history) already contains sufficient signal.

## Consequences

### Positive
- Sent-back indicators display correctly in the scoped table
- No schema changes required

### Negative
- Requires a join between KPIs and kpi_queries tables

### Neutral
- Detection relies on the combination of two existing data points
