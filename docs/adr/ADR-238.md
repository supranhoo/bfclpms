# ADR-238 — Admin Final Outcome panel on the Annual Review detail page

Status: Accepted · Date: 2026-08-03

## Context
Admins had no single place on an employee's Annual Review page showing the final
score together with the calibration, the exemption position and *what changed and
by whom*. The facts existed but were spread across `annual_review_calibration_audit`,
`annual_review_final_score_recompute_audit`, `annual_review_system_score_edits`,
`annual_review_eligibility_exemptions` and `annual_review_responses`.

## Decision
1. `public.annual_review_instance_change_log(p_instance_id, p_limit, p_offset)` —
   SECURITY DEFINER, server-paginated, unions the five audit sources for one
   instance. Access restricted to `admin` and `hr_pms`; the client `enabled` flag
   is UX only, never the security boundary.
2. `AdminFinalOutcomeCard` renders, for admin / HR PMS only: final score, computed
   vs calibrated vs **effective** rating (ADR-220/230), the increment slab with any
   cap (ADR-222/228), the eligibility status with every exemption and slab penalty,
   and the paginated change timeline.
3. All numbers come from existing SSOT helpers (`effectiveRating`,
   `resolveEligibility`, `ratingSlab`). The card is presentation-only — it performs
   no scoring and writes nothing.
4. Automated rows carry `performed_by = NULL` and must read as "System".

## Consequences
- No schema change beyond the new read-only function; nothing is mutated.
- Pagination is server-side (default 50/page), so instances with long histories
  cannot degrade the page.
- Rollback: drop the function and remove the card; no data migration involved.
