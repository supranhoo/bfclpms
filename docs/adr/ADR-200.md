# ADR-200: Annual review status may never point at a disabled stage

- Status: Accepted (July 2026)
- Policy: §AR-STAGE-REVERT-NO-DEAD-END (extended)

## Context
Amit Kumar Sharma (102050) could not submit reviews: the form opened normally and
the submit returned `stage dept_head is not enabled for this instance`
(raised by `advance_annual_review_status`).

RCA — 5 Why:
1. Why the error? `advance_annual_review_status('dept_head')` rejects stages absent
   from `annual_review_instances.enabled_stages`.
2. Why did he reach the Dept Head form? `overall_status = 'pending_dept'` routes the UI there.
3. Why is the status `pending_dept` when `enabled_stages = ['self','bu_head']`?
   The BU-terminal dedup sweep (`annual_review.bu_terminal_normalized`, 2026-07-23)
   stripped `dept_head` because `dept_head_id = bu_head_id`. Three instances were
   later pushed back to `pending_dept` by the ADR-127b inactive-reviewer reversal,
   which re-anchored on the *old* chain; one (100010) came from an earlier
   hierarchy-snapshot repair.
4. Why did nothing catch it? No invariant tied `overall_status` to `enabled_stages`;
   the coupling was re-implemented ad hoc in each repair script.
5. Why ad hoc? `annual_review_first_pending_status` — the only re-anchor helper —
   omitted `dept_head` and `management`, so repairs could not rely on it.

Blast radius (verified): exactly 4 instances — 101851, 101769, 101149, 100010.

## Decision
1. **`annual_review_first_pending_status` fixed** to include `dept_head` and `management`.
2. **New SSOT `annual_review_reanchor_status(enabled jsonb, status)`** — nearest ENABLED
   stage at or after the current one, else nearest enabled stage before it, else NULL.
   TypeScript mirror: `src/lib/annualReview/reanchorStatus.ts`.
3. **Invariant trigger `tg_ar_status_within_enabled_stages`** (BEFORE INSERT OR UPDATE OF
   `overall_status`, `enabled_stages`): self-heals a dead-end status by re-anchoring and
   writing `annual_review.deadend_reanchor` to `system_audit_logs`. It raises only when
   no enabled stage can host the review. Self-heal (not raise) was chosen so that legitimate
   contraction paths — `annual_review_edit_workflow`, `set_annual_review_enabled_stages`,
   dedup sweeps — cannot regress into a hard failure.
4. **Data repair** — snapshot in `annual_review_dept_deadend_repair_2026_07`; the four
   instances advanced to `pending_bu`; 100010's 10 already-entered Dept Head criteria
   scores re-labelled to `bu_head` (same reviewer, so ADR-142 rebind stays satisfied).

## Consequences
- `overall_status` outside `enabled_stages` is now structurally impossible.
- Rollback: `DROP TRIGGER tg_ar_status_within_enabled_stages ON public.annual_review_instances;`
  and restore statuses from `annual_review_dept_deadend_repair_2026_07`.

## Verification
- Dead-end query returns 0 rows across the whole cycle.
- All four instances read `pending_bu` with Amit Kumar Sharma as active reviewer; 100010's
  bu_head response retains 10 criteria scores.
- `src/lib/annualReview/reanchorStatus.test.ts` — 9 tests (forward, backward, terminal, empty).
