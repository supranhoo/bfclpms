# ADR-333 — Scheduled rollover invocation contract and September repair

**Status:** Implemented  
**Date:** 2026-09-01

## Context

The monthly scheduler invoked `auto-rollover-kpis` with `triggered_by: "cron"`, while the function treated only `"system"` as scheduled. The live job therefore bypassed the ADR-248 issuance and target-month guards and added KPIs to employees whose September 2026 KRA sets were already prepared.

## Five Whys

1. Additional KPIs appeared because the scheduled run processed already-prepared employees.
2. It processed them because scheduled-only issuance and existing-target guards did not execute.
3. The guards did not execute because the scheduler sent `cron` but the function checked only `system`.
4. This mismatch survived because tests modelled the implementation label, not the production scheduler payload.
5. The incident expanded because guard-query failures were permissive and projected target weightage was not checked before insertion.

## Decision

- Resolve invocation mode in one pure module: authenticated scheduler requests labelled `cron` or `system` become `scheduled`; all others are `manual`.
- Scheduled runs fail closed if issuance or existing-target checks fail.
- Scheduled runs skip any employee already issued, already carrying target-month KPIs, or projected to exceed 100.5% target-month weightage.
- Preserve manual/admin top-up behavior; only authenticated scheduler execution receives automated safeguards.
- Repair the September incident through an immutable before-image archive and a one-time backend-only function with exact count and dependency assertions.

## Incident repair

- 347 generated KPI rows across 30 employees were identified from the 1 September scheduler window.
- 99 linked KPI audit rows and every complete KPI row were archived in `kra_rollover_incident_repair_archive`.
- Zero submissions, observations, queries, or auditor assignments referenced the candidates.
- The 347 rows were then removed transactionally. Any baseline or dependency mismatch aborts the entire operation.

## Consequences and rollback

Scheduled rollover now preserves deliberately prepared target months and cannot silently inflate weightage. The archive is included automatically by the dynamic backup engine. Restoration can reinsert `kpi_row` and the nested `audit_rows` from the incident archive in one controlled transaction; no historical employee scores were modified.

## Verification

- 28 rollover regression tests pass, including the real `triggered_by: "cron"` payload, issuance skip, existing-target skip, fail-closed behavior, multi-month targets, and projected weightage.
- The deployed function is the hardened implementation.
- Post-repair verification confirms 347 archived KPIs, 99 archived audit rows, and 30 affected employees.
