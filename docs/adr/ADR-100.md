# ADR-100 — Daily Submission Summary must be workflow-template aware

- **Status:** Accepted (2026-06-29)
- **Release:** v2.66.69
- **Related:** POLICY §DAILY-SUBMISSION-WORKFLOW-AWARENESS, POLICY §105,
  `mem/architecture/database/per-employee-workflow-resolution`,
  `mem/features/review/dynamic-workflow-columns`.

## Context

`src/components/review/DailySubmissionSummary` is the inline daily/sub-period
grid inside the review sheet. It used a linear 8-stage `STATUS_ORDER` to gate
reviewer columns (Manager / Skip-Lvl / HR PMS / Auditor / Mgmt) by KPI
`status` alone. Once status reached `approved`, all six reviewer columns
rendered — including stages that are **not part of the employee's resolved
workflow template** (e.g. `self_l1_audit` has no HR PMS / Skip / Mgmt).
Empty cells (`—`) in those columns falsely signalled "not yet reviewed by
that role" when the role simply doesn't exist in that workflow.

This is the same defect class fixed in BUG-033 for per-employee workflow
reports, where the maximal stage array was hardcoded instead of resolving
per employee.

## Decision

1. `DailySubmissionSummary` accepts an optional
   `workflowStages?: string[]` prop containing the employee's resolved
   template stages.
2. Reviewer columns require BOTH of:
   - Status has reached/passed the stage (legacy `STATUS_ORDER` check), AND
   - The corresponding workflow stage is present in `workflowStages`.
3. When `workflowStages` is omitted, the component falls back to legacy
   status-only gating for back-compat. New call sites must pass the prop.
4. Mapping from reviewer column → template stage:
   - `manager_achieved_value` → `manager_check`
   - `skip_level_achieved_value` → `skip_level_check`
   - `hr_pms_achieved_value` → `hr_pms_review`
   - `auditor_achieved_value` → `audit`
   - `management_achieved_value` → `management_review`
5. All five existing call sites thread the existing `effectiveStages`
   value (already resolved via `useEmployeeWorkflowStages`).
   `InlineDailySubmissionRow` resolves it independently from
   `kpi.employee_id`.

## Consequences

- `self_l1_audit` employee + `status=approved` → grid shows Self / Manager
  / Auditor only (no Skip-Lvl / HR PMS / Mgmt).
- Header chip "N review levels" automatically shrinks (e.g. "3 review
  levels" instead of "6 review levels") because it derives from the
  visible column count.
- No DB / RLS / scoring change. Pure presentation fix.
- Pinned by `src/test/dailySubmissionSummaryWorkflowAware.test.tsx` (4
  tests covering 3 templates + the omitted-prop back-compat case).

## Rollback

Revert `DailySubmissionSummary.tsx` — caller prop is optional so build
still compiles if call-site reverts are skipped.
