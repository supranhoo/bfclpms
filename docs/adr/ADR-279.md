# ADR-279 — Performance Console visual language


- **Status:** Accepted
- **Date:** 16 August 2026
- **Related:** ADR-259, ADR-264, ADR-271, ADR-277, ADR-278

## Context
After ADR-277/278 the console was structurally correct but still read as a
wireframe: numbers with no meaning attached, a wide dead canvas next to a short
KRA list, and no sense of overall health for the loaded scope.

## Decision
Presentation-only pass, no data, RPC, scoring or filter-logic change:
- New `ConsoleStatBand` (Categories / KRAs / KPIs / Employees / Average score),
  derived from the already-fetched tree via `computeConsoleStats`. A muted
  placeholder variant keeps the page structured before a scope is loaded.
- New `ScorePill` bands a score against its scale (`low` / `mid` / `high`) using
  the new semantic `--success` and `--warning` tokens, with an optional micro bar.
- `ConsoleMetricRow`: heavier 15px title, primary index chip and tinted surface
  when expanded, hover/focus-revealed "Open" affordance.
- `BuConsoleTree`: pill category strip with overflow-aware scroll arrows and
  fades, a tree rail plus inner shadow on the expanded KPI panel, an Avg score
  column on KRA rows, and a `xl+` "Category at a glance" side panel.
- Loading skeletons mirror the stat band and 56px row heights.

## Consequences
- `--success` / `--warning` HSL tokens added to `src/index.css` (light + dark)
  and mapped in `tailwind.config.ts`; components use tokens only.
- No change to `useBuConsole`, RPC signatures, ADR-229 cascading filters,
  ADR-264 virtualization thresholds, ADR-271 dirty scope or ADR-278 expansion.
- Regression guard: `src/components/admin/bu-console/consoleLayout.test.tsx`.

## Rollback
Revert the touched presentation files and the two colour tokens; no migration.
