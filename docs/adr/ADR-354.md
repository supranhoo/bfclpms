# ADR-354 — One KPI, three legacy names across two categories ("Power generation from 8 MWh")

Date: 2026-09-03 · Status: Accepted · Related: ADR-330, ADR-334, ADR-337, ADR-351, ADR-352a, ADR-353

## Context

Reported 3 Sep 2026: *Achieve organization's production target → Power generation
from 8 MWh* rendered as two visually identical cards on `/admin/org-kpi-data`
(12 employees and 3 employees for Jul-Aug), immediately after the Performance
Console definition edits were rolled back (ADR-353).

Verified in the database — for Sep 2026 the KPI existed as three open
(`kra_set`) groups, all carrying the same structured `kpi_title`:

| category | legacy `kpi_name` | employees |
|---|---|---|
| Production & Operations | `Power generation from 8 MWh` (27 chars) | 14 |
| Production & Operations | `Power generation from 8 MWh (incentive %)(Aug-Sep,…)` (225 chars) | 3 |
| Production | same text, 232 chars | 2 |

Same shape for Jul (12+3), Aug (16+3+2) and Oct (14+3+2). Root cause is the
known split described in ADR-352a: Org KPI Data Entry groups on
`category_id + kra_name + kpi_name`, while the Performance Console rewrites only
the structured columns (ADR-334/337). Since ADR-351 the cards render the
structured text, so the groups became indistinguishable. New here: one slice of
rows also sat under a *second category*, which the ADR-352a detector (grouped
per category) could not see.

## Decision

1. **Correction (data, reversible).** The 18 open Jul–Oct 2026 rows were renamed
   to the canonical `Power generation from 8 MWh` and moved to
   `Production & Operations`, with a `rename_kpis_range` row in
   `kpi_standardization_actions` carrying every row's previous name and
   category. Approved months (Sep 2025 – Jun 2026) were untouched (POLICY §88I).
2. **Detector.** New read-only `public.list_cross_category_kpi_title_splits()`
   lists every May-2026+ KPI title whose open rows span more than one category,
   surfaced as the "Same KPI, Two Categories" card on KPI Standardization →
   Health. Informational only — merging categories moves rows between cards and
   stays an explicit admin action in the Performance Console; the ADR-352a
   Normalise button continues to handle the name-only case.

## Consequences

- Jul–Oct 2026 now render as one card (15 / 21 / 19 / 19 employees).
- Cross-category splits are visible instead of silently producing twin cards.
- No schema change, no RLS change, no score, target, weightage or workflow write.

Rollback: the standardization action stores each row's previous `kpi_name` and
`category_id`; re-applying it in reverse restores the split. The new function can
be dropped without side effects.

Tests: `src/test/splitKpiNameVariants.test.ts` (5).
