# ADR-201 — Password rollout history is visible per user (paginated)

- **Status:** Accepted
- **Date:** 2026-07-29
- **Version:** v2.66.189
- **Policy:** POLICY §113.1

## Context

The Password tab of `UserAccessSheet` rendered a single "Last rollout" card sourced from
`password_rollout_logs … limit(1)`. Admins investigating credential issues (was a password
re-issued? did the email bounce last time? who triggered it?) had no way to see prior attempts
even though every attempt is already persisted.

## Decision

1. Replace "Last rollout" with **Rollout history** — all log rows for the selected user, newest
   first, the first row on page 1 badged **Latest**.
2. Reads are **server-side paginated**: `.range(page*10, page*10+9)` with `count: 'exact'`.
   Unbounded log reads are forbidden (POLICY §94).
3. Each row shows timestamp, status badge, email outcome, error message (when present) and the
   acting admin resolved from `generated_by` via one batched `profiles` `in()` lookup limited to
   the current page. Unresolvable ids render as `System`.
4. `password_rollout_logs` remains append-only — this is a read-only surface. No schema, RLS,
   RPC or edge-function change.

## Implementation

- `src/hooks/usePasswordRollout.ts` — `usePasswordRolloutHistory`, `rolloutHistoryRange`,
  `performerLabel`, `ROLLOUT_HISTORY_PAGE_SIZE`.
- `src/components/admin/UserAccessSheet.tsx` — `PasswordPanel` history section + pagination;
  post-generate invalidation moved to `['password-rollout-history', userId]` with page reset.
- Tests: `src/hooks/__tests__/passwordRolloutHistory.test.ts` (6).

## Rollback

Revert the `PasswordPanel` section and the hook additions. No data migration.
