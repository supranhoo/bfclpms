# ADR-360 — Team Reviews tile counts and list share one predicate

Status: Accepted · 2026-09-05 · Amends ADR-348 / ADR-359 · POLICY §129

## Context
A manager saw "Total Employees 28 · KRA Set 23" while the grid rendered
"No employees match the current filters" with the KRA Set tile selected.

`EmployeeSelectorGrid.stats` counted tiles with inline rules, while the grid
filtered with `matchesTeamTile`. The two disagreed:
- the counter counted any `kra_set` KPI for a direct report or a full-access viewer;
- `matchesTeamTile('pending_kra_set')` additionally required `isDirect`, or
  full-access **plus** a `self_review` stage in the resolved workflow, and rejected
  skip-level and functional reports outright.

Employees counted by the first rule and rejected by the second inflated the tile and
vanished from the list. On top of that, the ADR-359 queue mode was applied after the
tile filter and could subtract further.

## Decision
1. `src/lib/teamReviewTileFilter.ts` is the single predicate for team tiles. The
   `stats` counter now calls `matchesTeamTile` for all five tiles, so counts and list
   membership can never drift.
2. `pending_kra_set` no longer requires a `self_review` stage and accepts
   direct, skip-level, functional and full-access viewers — KRA Set is the universal
   first state and means "waiting on the employee".
3. The queue mode (`assigned` / `actionable` / `all`) is skipped whenever a team tile
   or status filter is active; the tile already defines the subset.
4. An empty tile result renders a dedicated empty state with "Show all team members".

## Consequences
Presentation and counting only — no schema, RPC, RLS, workflow or scoring change. The
KRA Set count may shift for full-access viewers whose employees lack a `self_review`
stage; that value is now the truthful one.

Rollback: restore the previous inline counter branch and the old
`pending_kra_set` case.

Tests: `src/tests/teamReviewTileFilter.test.ts` (6 cases).
