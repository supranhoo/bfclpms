# ADR-190 — Review evidence read access follows KPI participation, not the upload folder

**Date:** 2026-07-28
**Status:** Accepted

## Context
Employee Dippendu Das (101773) could not open auditor-uploaded supporting evidence from KPI Details; the preview modal rendered `Preview failed: {}`.

Findings:
- `review-evidence` is a private bucket.
- The general read policy **"Users can view authorized evidence"** authorises on `storage.foldername(name)[1]` — the viewer must be that UUID, its reporting/skip manager, or hold `admin` / `auditor` / `hr_pms`.
- `src/components/ui/EvidenceUpload.tsx` builds paths as `${userId}/${kpiId}/...` where `userId` is **the uploader**. Reviewer/auditor uploads therefore live under the reviewer's folder, e.g.
  `f9556e9b-…(Auditor03)/e7f2a92f-…/reviewer-evidence/1784723216401_101773_Timely_Resolution_of_Customer_rel.png`.
- The KPI owner is not that folder's UUID and is not the auditor's manager → storage denies SELECT. The SDK returns an error with an empty body, which the dialog stringified as `{}`.

Only `observation-evidence` had a participation-based policy; the other evidence folders did not.

## Decision
1. Add an **additive** SELECT policy `Review evidence readable by KPI participants` on `storage.objects`, scoped to `review-evidence`, keyed on the **KPI id in path segment 2**. Readers: KPI owner, reporting manager, skip-level manager, assigned auditor (`audit_kpi_assignments` / `audit_kpi_level_assignments`), or a user with `kpi_mention_access` on that KPI. Applies to segment-3 folders `self-evidence | reviewer-evidence | auditor-evidence | management-evidence | observation-evidence | observation-replies`, and to two-segment legacy paths.
2. No existing policy dropped or narrowed — admins, auditors, HR and managers keep today's access.
3. Normalise storage errors client-side via `src/lib/review/evidenceError.ts` so denials never render as `{}`.

## Alternatives considered
- **Make the bucket public.** Rejected — evidence is RLS-gated business data (see ADR-099).
- **Backfill/move historical objects into the employee's folder.** Rejected for now: a bulk storage move breaks stored URLs across `review_submissions`.
- **Widen the folder-owner policy.** Rejected — it would grant cross-employee reads, not KPI-scoped reads.

## Consequences
- KPI participants can read reviewer/auditor evidence for their own KPI regardless of who uploaded it.
- Non-participants remain denied; the bucket stays private.
- Uploads still land under the uploader's folder (hardening tracked separately).

## Rollback
`DROP POLICY "Review evidence readable by KPI participants" ON storage.objects;` and revert the client error helper. No schema change.
