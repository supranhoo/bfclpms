# ADR-227 — Child-truth Org KPI bulk rollback

- Date: 2026-08-01
- Status: Accepted

## Context
A data owner uploaded July 2026 values for the Training-Hours Org KPIs in error
and asked for a revert. "Rollback All Scopes" failed with *"No propagated scopes
to bulk-roll-back for this period"*.

Verified state at the time:
- `org_kpi_values` for those KPIs: 11 department rows, all `draft`, value cleared.
- Child scorecards still carried the wrong value: 17 self-review + 9 manager-check
  ("Completion of Mandated Average Training Hours"); 47 self-review + 10
  manager-check + 2 kra_set ("Completion of Mandated Training Hours").

`useBulkRollbackOrgKpiPropagation` derived its work list from
`org_kpi_values.status IN ('propagated','approved')`. With the master rows
already reset, it aborted before touching a single scorecard, while the card
badge (ADR-055 fact-based inference) still read "Propagated" because it is
derived from the children. Master truth and child truth had diverged.

## 5 Why
1. Rollback failed → no master rows in propagated/approved state.
2. A prior partial action reset the master rows without clearing the children.
3. The bulk rollback read the master table, not the child KPIs.
4. The original design assumed master and child always move together.
5. Propagation, single-scope rollback, repair-gap and reviewer advancement can
   each move one side independently — no invariant enforced the pair.

## Decision
1. New RPC `public.rollback_org_kpi_propagation_by_children(p_kra_name,
   p_kpi_name, p_review_period, p_review_year, p_reason)` — SECURITY DEFINER,
   `search_path = public`, admin **or** data-owner gated, reason ≥ 3 chars.
   - Work list derived from `kpis` (`is_org_level = true` + KRA/KPI/period/year),
     independent of master status.
   - Clears `review_submissions` for all reviewer stages and steps the cells back
     to `kra_set`, **including admin-forced rollback of `manager_check` and later
     stages** (reviewer scores on those cells are cleared).
   - `approved` and `management_review` cells are never touched (POLICY §88
     immutability); they are counted and returned as `skipped_approved`.
   - Resets matching `org_kpi_values` rows to `pending` with a null value.
   - Writes an `org_kpi_data_entry_logs` summary row
     (`action = 'bulk_rollback_children'`) with the counters, and notifies the
     data owners. Single transaction — a partial state cannot recur.
2. `useBulkRollbackOrgKpiPropagation` now calls that RPC instead of the
   multi-step client writes; the toast reports scopes reset, scorecards cleared,
   manager-stage force-resets and approved skips.
3. `hasBulkRollbackTarget` documented as child-truth aligned — the derived row
   status already folds in `isPastKraSet`, so button and action agree.
4. New read-only diagnostic `public.org_kpi_master_child_drift(period, year)`
   plus `useOrgKpiMasterChildDrift`, surfaced as an admin-only reconciliation
   banner on `/admin/org-kpi-data`.

## Consequences
- The erroneous July upload can be fully reverted, including cells a manager had
  already scored (explicitly chosen by the requester).
- Those employees and their managers must re-enter and re-review the KPI.
- Frozen/approved scores remain immutable.
- Single-scope rollback and propagation paths are unchanged.
- Rollback of this change: drop the two functions and revert the hook; no schema
  change was made.
