# ADR-048: Auto-Advance KPI Scoring Policy

## Status
**Accepted**

## Date
2026-04-01

## Context
Overdue self-reviews need to be auto-scored to prevent indefinite workflow stalls. The scoring strategy for auto-advanced KPIs needed definition.

## Decision
Auto-scored KPIs are set to `approved` with ALL review stage scores set to 0 with `red` rating. The `auto_advance_reason` field distinguishes system-auto-scored KPIs from N/A KPIs. Audit action: `SYSTEM_AUTO_SCORED`.

## Alternatives Considered

### Alternative A: Set only self_score to 0, leave other stages as N/A
- **Description:** Only populate the self-review score and leave downstream stages empty
- **Rejected because:** Journey tiles would display "N/A" for skipped stages, reports would show gaps, and weighted average calculations would handle them inconsistently.

### Alternative B: Mark auto-advanced KPIs as N/A
- **Description:** Use the existing N/A mechanism instead of zero-scoring
- **Rejected because:** N/A KPIs are excluded from weighted averages entirely. Auto-advanced KPIs should penalize the overall score (included at 0), not be excluded.

## Consequences

### Positive
- Consistent zero scores across all report columns
- KPIs included in weighted average calculations (penalizing non-compliance)

### Negative
- All-zero scores may seem harsh (mitigated by clear `auto_advance_reason` labeling)

### Neutral
- Journey tile UI checks `auto_advance_reason` to prevent false N/A badges
