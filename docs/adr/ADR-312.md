# ADR-312 — PIP employee prefill confirmation

Date: 2026-08-25
Status: Accepted

## Context

Create PIP is reached with the employee already decided (`?employee=<id>`), yet the Employee
field showed an empty dropdown. The control was a `<Select>` whose trigger rendered a custom
`<SelectValue>` child computed from a separately fetched list of active profiles. Radix renders
the supplied child instead of the placeholder, so until the list resolved — and permanently when
the id was absent from it — the trigger painted nothing. The form value was set, so the screen
looked broken and the plan could be submitted against an invisible selection.

## Decision

Resolve the preselected employee by id with a dedicated single-row query and render a confirmed
employee card (name, employee code, designation, department) plus a "Change employee" action.
Manual selection and "Change employee" use the shared searchable `EmployeePickerCombobox`.
Loading shows a skeleton; an unresolvable id shows an inline destructive message.

## Consequences

- No re-selection in the normal prefilled flow; the choice is visible and auditable on screen.
- State logic is a pure resolver (`resolvePipEmployeeFieldState`) covered by unit tests.
- No schema, RLS, validation or payload change; `employee_id` and POLICY §15.7 are untouched.
- Rollback: revert `PipEmployeeField.tsx` and restore the prior `<Select>` block.
