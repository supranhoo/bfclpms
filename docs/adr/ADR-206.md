# ADR-206 — Functional Manager Review Action Path

**Status:** Accepted · **Policy:** §WF-FM-RELATIONSHIP-SSOT

## Context
Ganapathi Varma (200271), mapped as Functional Manager of Brundaban Chandra Das (102028), saw all 20 June-2026 KPIs as read-only. The KPIs sat at `status = 'manager_check'` — i.e. the L1 Manager stage was complete and the KPI was pending with the FM.

## Root causes
- **RC-1 (client):** `UnifiedScorecard` had no `functional_manager` view level; FMs fell back to the read-only Manager view.
- **RC-2 (server):** `kpis` / `review_submissions` RLS gated on `status = 'functional_manager_check'` — the *completed* FM stage — instead of the stage the FM acts on.
- **RC-3 (routing):** `EmployeeSelectorGrid`'s full-access branch never tagged `functional`, so admins/HR assisting an FM landed on the manager view.
- **RC-4 (deep links):** `Dashboard` derived the relationship from profile fields that are absent in several roster payloads and defaulted to `direct`.

## Decision
- **Server:** `is_fm_actionable_kpi(uuid)` security-definer helper resolves the stage preceding `functional_manager_check`; `kpis` and `review_submissions` UPDATE/INSERT policies use it.
- **Client:** `functional_manager` view level in `UnifiedScorecard` (viewType `functional-manager-review`); FM branches added to `KpiDetailsTable` / `MobileKpiCard`.
- **SSOT:** `src/lib/review/resolveReviewerRelationship.ts` is the single relationship resolver, consumed by `Dashboard` and `EmployeeSelectorGrid`.
- **Tiles:** stage-true `pending_functional` tile in `src/lib/teamReviewTileFilter.ts` + "Functional Pending" stat card.
- **Guardrail:** mis-routing notice in `UnifiedScorecard` when the viewer is the mapped FM but the view level is not `functional_manager`.

## Consequences
Workflows without `functional_manager_check` are unaffected — the tile stays hidden and the resolver returns the pre-existing relationship. Rollback = revert the client modules; the RLS helper is additive.
