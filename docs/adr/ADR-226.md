# ADR-226 — Structured recommendation tracking (Annual Review)

**Status:** Accepted (Phase 1 — capture + governance) · 2026-08-01

## Context
Dept Head / BU Head / Management recommendations were free prose stored under the
reserved key `__overall_recommendation` in `annual_review_responses.qualitative_responses`
(1,376 records; ~450 with clear promotion or monetary intent). Prose cannot be
filtered, costed, approved or audited, so monetary asks were invisible to HR and
never linked to the increment cycle.

## Decision
Capture the ask **structurally** next to (not instead of) the narrative.

- `annual_review_recommendation_types` — master data (`promotion`, `special_hike`,
  `one_time_reward`, `grade_change`, `role_change`, `training`, `none`), each with
  `is_monetary`, `requires_amount`, `requires_target_role`, `is_active`, `sort_order`.
  Admin/HR may edit; **no type is hardcoded in the UI** (zero-hardcoding rule).
- `annual_review_recommendations` — one row per `(instance_id, reviewer_role)` with
  amount kind/value, proposed designation & grade, effective date, narrative copy,
  `source` (`stage_form` | `legacy_import`) and a decision (`status`, approved amount,
  `decided_by/at`, `decision_reason`).
- `annual_review_recommendation_items` — many-to-many to types.

### Write paths (RPC-only, SECURITY DEFINER)
- `ar_save_recommendation` — the caller must be the named reviewer for that stage
  (or a decider); blocked once the instance is `completed`.
- `ar_decide_recommendation` / `ar_bulk_decide_recommendations` — Admin / HR PMS /
  Management only, reason mandatory, audited as
  `recommendation.saved | recommendation.decided | recommendation.bulk_decided`
  in `annual_review_access_audit`.
- `ar_recommendation_queue` — server-side paginated, filterable read for the queue.

### RLS
`ar_can_view_recommendation(instance_id)` (SECURITY DEFINER, avoids profile RLS
recursion) grants read to the employee, every named reviewer on the instance and
Admin / HR PMS / Management. Writes are limited to the owning reviewer or a decider.

## UI
- `StructuredRecommendationFields` mounts inside `OverallRecommendationCard` for the
  editing reviewer (type chips, conditional amount, designation/grade, effective date).
- `RecommendationsTab` (Annual Review Admin → **Recommendations**) — paginated queue
  (25/page, server-side), status/type/monetary/search filters, per-row and bulk
  decisions with mandatory reason, CSV export of the current page.

## Consequences
- Monetary asks become reportable and costable; Phase 2 will add the legacy prose
  classifier (`source = legacy_import`, `status = needs_classification`), Bell Curve
  badges, a registered report and the increment-run handoff.
- Narrative remains the SSOT for wording; the structured row never overwrites it.

## Rollback
Additive only. Dropping the three tables and four functions restores prior behaviour;
no existing column or row is modified.
