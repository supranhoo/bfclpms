# ADR-033: Rollback Cascade-Clear

## Status
**Accepted**

## Date
2026-03-30

## Context
When a KPI is rolled back to a previous stage, review data from subsequent stages must be cleared. The question was whether to clear data for the target stage itself or only stages after it.

## Decision
ALL review fields for the **target stage AND all subsequent stages** must be cleared using `>=` (not `>`) for stage index comparison. This includes score, rating, remarks, evidence_url, achieved_value, plus final_score and final_rating.

## Alternatives Considered

### Alternative A: Clear only stages after target using `>`
- **Description:** Preserve the target stage's existing data and only clear downstream stages
- **Rejected because:** Stale scores from the previous approval cycle would remain visible at the target stage, creating a false impression that the stage has already been re-reviewed.

### Alternative B: Clear all stages regardless of target
- **Description:** Always clear everything back to initial state
- **Rejected because:** Overly destructive — stages before the target may have valid, current data that should be preserved.

## Consequences

### Positive
- No stale data remains at or after the rollback target
- Clean slate for re-review from the target stage

### Negative
- Any valid data at the target stage is also cleared (acceptable trade-off for data integrity)

### Neutral
- Applies to both user-initiated rollback requests and admin step-back
