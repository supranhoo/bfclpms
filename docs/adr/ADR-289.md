# ADR-289 — Performance Console consolidation: one surface, no tabs

**Status:** Accepted · **Date:** 2026-08

## Context
The console had grown to five tabs (Console, Review Run, Pipeline, KRA Tree, KPI Library). Each
re-stated the same scope and, in three cases, its own copy of the tree. The stated goal was a single
console to run the show, not a set of parallel surfaces.

## Decision
One drilldown tree with a **Configure / Review** mode switch.

- Configure: the KRA disclosure shows the KPI definition list (ADR-278) unchanged.
- Review: a `StageRail` above the tree shows per-stage pending counts (`bu_console_pipeline`) and
  selects the working stage; the KRA disclosure renders `KraWorksheet` — the KPI x employee grid
  scoped to that KRA (`bu_console_run_snapshot` with `p_kra_name`).
- `BuConsoleTree` gains `renderKraPanel`; the panel is replaced, never stacked.
- KRA alignment and KPI library/duplicates become header-overflow dialogs.
- `PipelineTab.tsx` and `ReviewRunTab.tsx` deleted; stage labelling extracted to `pipelineStages.ts`.

## Consequences
- No RPC, scoring, access-tier or write-path change — composition only, so the server contract and
  §CONSOLE-REVIEW-RUN caps still hold.
- The worksheet loads per KRA, so it is smaller than the old full-scope run and still never
  auto-loads.
- POLICY §CONSOLE-SINGLE-SURFACE governs future additions.
- Tests: `consoleLayout.test.tsx`, `pipelineStages.test.ts`.

## Rollback
Restore the two deleted tab components and the `Tabs` wrapper in `BuConsole.tsx`; `renderKraPanel`
is optional and can stay.
