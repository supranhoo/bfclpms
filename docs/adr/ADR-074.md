# ADR-074: Inverted fail-open for `view_only` in `useReviewPeriodPermissions`

- Status: Accepted
- Date: 2026-06-05
- Related: ADR-073 (iOS Safari `history.replaceState` throttle)

## Context

On 2026-06-05 a screenshot from `pms.bfclalloys.com` (iPhone Safari) showed a
"View Only" badge on a May 2026 KPI with the tooltip "Governance lock active
for this period (planning)". Users assumed an admin had governance-locked
May 2026.

Database evidence:
- `review_periods` row for May 2026 — `is_locked=false`, `current_stage='planning'`.
- `review_period_locks` for that period — **0 rows** (no global/role/dept/employee locks).
- `check_review_period_permission(...)` evaluated for both the viewing
  auditor (`Auditor001`) and the KPI owner (`200493 / Y R V S Murthy`) returns
  `edit_kpi=true, edit_scores=true, view_only=false, submit_self_review=true`.

There is no governance lock. The badge was a client-side artefact.

## Root cause

`src/hooks/useReviewPeriodPermissions.ts` fired 7 parallel RPCs and used a
single uniform fail-open:

```ts
if (error) return { action, allowed: true }; // Fail-open
```

The `view_only` action has INVERTED semantics: `true` means "user IS
view-only" (i.e. restrictive). Returning `allowed: true` on RPC error therefore
flipped the consumer's `hasRestrictions = view_only || !edit_kpi ||
!edit_scores` to `true`, and the tooltip pulled `periodStage` from the
(successful) `review_periods` fetch — producing the exact "Governance lock
active for this period (planning)" string.

iOS Safari is the most common trigger because transient network blips
during auth refresh / tab resume cause a partial RPC failure rather than a
full reject of the `Promise.all`.

## Decision

Fail-open per action:

```ts
function permissiveDefault(action: string): boolean {
  return action === 'view_only' ? false : true;
}
```

Applied both in the RPC error branch and as a defensive fallback when the
success payload is not a strict boolean.

## Consequences

- No phantom governance-lock badge on transient RPC errors.
- Real governance locks (closed stage, real `review_period_locks` rows) are
  unaffected — the DB RPC is the source of truth and is not changed.
- A `setLastRpc('check_review_period_permission', null)` breadcrumb is
  written in the error path so future iOS telemetry (ADR-073 sink) can
  correlate the failing RPC.
- Diagnostic only; trivially revertible.

## Scope guardrails

- No DB / RLS / RPC change.
- No Menu Setting / Custom Tabs change.
- `menu_overrides_enabled` kill switch unchanged.
- No scoring / enforcement / role-grant change.
