# ADR-059 — Fix `propagate_org_kpi_value` enum cast (`workflow_status` → `review_status`)

**Date:** 2026-05-06
**Status:** Accepted
**Trigger:** Ankan saw a red toast "Failed to propagate values — type \"workflow_status\" does not exist" when clicking Propagate on the IT Awareness KPI.

## Context
Migration `20260506065308_..._policy_aware_propagation.sql` (ADR-054 follow-up) introduced the 4-arg `public.propagate_org_kpi_value(jsonb, boolean, text, text)` and used the cast `v_target_status::workflow_status` inside the `UPDATE kpis SET status = ...` statement. There is no enum named `workflow_status` in the database — the canonical enum on `public.kpis.status` is `public.review_status` (verified via `information_schema.columns.udt_name`). The cast fired only when an admin/data-owner actually clicked Propagate on a `kra_set`/`self_review` row, so the typo never surfaced in any other code path.

## Decision
`CREATE OR REPLACE` the 4-arg function with `v_target_status::public.review_status`. Function signature, policy gating, audit-log writes, and the `review_submissions` upsert are unchanged — ADR-058's single-overload contract is preserved.

## Consequences
- Propagate dialog works again for all data owners and admins.
- Future migrations MUST NOT reference `workflow_status` — it does not exist.
- Source-level guard `src/test/orgKpiPropagateEnumGuard.test.ts` asserts no `workflow_status` cast survives in `supabase/migrations/**` and that the propagate RPC keeps casting to `review_status`.

Reference: ADR-053, ADR-054, ADR-058.
