# ADR-103 — Web Speech API Read-Aloud for Blue-Collar Self Review

- **Status:** Accepted
- **Date:** 2026-06-30
- **Author:** Lovable Agent
- **Supersedes:** —
- **Related:** Annual Review Multilingual (`enable_multilingual`), Blue-Collar Preset (`src/lib/annualReview/blueCollarPreset.ts`)

## Context

Blue-collar self-review forms are already available in the worker's native
language via `enable_multilingual` + `available_languages`. Field testing on
shop-floor Android phones surfaced a literacy gap: some operators can speak
and understand Hindi fluently but read it slowly. We need an audible read of
the translated criteria and option labels without adding server load, latency,
or per-character spend.

## Decision

Adopt the browser-native **Web Speech API** (`window.speechSynthesis`) for
Phase 1. The speaker icon (`<SpeakButton>`) is rendered next to translated
text only, gated by a per-template flag `template.settings.enable_audio`.

## Rejected alternatives

| Option | Why not (now) |
| --- | --- |
| **Lovable AI Gateway TTS (`openai/gpt-4o-mini-tts`)** | Higher quality, but introduces per-character cost, network dependency, and IndexedDB cache complexity. **Deferred to Phase 2** as a fallback when no OS voice is installed. |
| **Pre-generated MP3 bundle (build-time)** | Zero runtime cost, but every template edit triggers re-bake; cannot read dynamic / free-text content. Over-engineering for v1. |
| **Third-party TTS SDK (Google / Azure / ElevenLabs)** | Vendor lock-in, API keys, billing. Violates Zero-Hardcoding & SSOT principles for marginal gain over OS voices. |

## Graceful-fallback contract

`<SpeakButton>` returns `null` (silent — no UI shift) when **any** of:

1. `template.settings.enable_audio !== true`
2. Active language equals the template default (nothing to translate-read)
3. `window.speechSynthesis` is undefined (unsupported browser)
4. `speechSynthesis.getVoices()` reports no voice for the active BCP-47 lang

No audio ≠ broken form. The written translation remains the source of truth.

## Browser support matrix (verified)

| Platform | Hindi voice ships | Notes |
| --- | --- | --- |
| Android 8+ (Chrome / WebView) | Yes (Google TTS) | Voice pack auto-installed on most OEMs. |
| iOS 14+ (Safari / Chrome WebView) | Yes (Siri Hindi) | Pre-installed. |
| Windows 10+ (Edge / Chrome) | Optional | "Hindi (India)" available in `Settings → Speech`. Button hides if absent. |
| macOS (Safari / Chrome) | Yes | "Lekha" voice ships by default. |
| Linux desktop (Chrome / Firefox) | Often **no** | Button hides — Phase-2 AI Gateway fallback will cover this. |

## Consequences

- **+** Zero server cost, zero new dependencies, zero migration, zero RLS impact.
- **+** Feature-flagged per template; rollback = toggle off in admin UI.
- **+** Works offline once OS voice pack is installed.
- **−** Voice quality varies per device (acceptable for short labels).
- **−** Linux desktops without a voice pack get no audio (covered by Phase 2).

## Future work (Phase 2)

Add Lovable AI Gateway TTS (`openai/gpt-4o-mini-tts`) as a graceful fallback
invoked only when `hasVoiceFor(lang) === false`. Cache returned audio in
IndexedDB keyed by `sha256(text + lang)` for offline reuse.

## Known gaps fixed

- **v1.0.1 (2026-06-30)** — `<SpeakButton>` now also renders on the team /
  auditor / manager / skip / BU annual-review detail routes. Previously the
  `TeamReviewDetailContent` wrapper omitted the `enableAudio` prop on its
  `AnnualReviewI18nProvider`, so the context fell back to `false` and every
  speaker icon silently returned `null`. One-line fix; no schema or policy
  change.
