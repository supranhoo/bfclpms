# ADR-320 — Grouped KPI scopes (Business Unit & Location first)

Status: Accepted · 2026-08-26 · v2.66.320

## Context

Five scope words — Division, Business Unit, Location, PMS Grade, Level — were
listed in the create dialog and in the "Edit Scope" menu as **Soon**. They
existed in the data model (`org_level_scope` accepts them, `profiles` carries
every key) but nothing could create a KPI on them and nothing could re-scope a
KPI onto them, so the labels promised a capability that did not exist.

The three shipped scopes each answer their targeting question differently:
Organization needs no target, Department resolves through `department_id`,
Employee through `employee_id`. Adding five more the same way would mean five
more bespoke pickers and five more branches in the migration path.

## Decision

One reusable **"which one?"** step, driven by the server.

1. **Scope options come from the database, not the client.**
   `kpi_scope_options(scope)` returns the selectable targets for any grouped
   scope with a live employee count; `kpi_scope_population_summary(scope,
   target)` returns the reach and how many people are missing the key. No
   surface hardcodes how a scope resolves to people.
2. **One picker component.** `ScopeTargetPicker` renders the prompt, the
   options and the reach for whichever scope it is handed, and is used by both
   the create dialog and the re-scope dialog.
3. **One generic re-key.** `migrate_okv_scope_generic` moves recorded values
   between any two scope dimensions with the same audit trail the legacy path
   writes. `change_org_kpi_scope_cascading` keeps the legacy three-scope path
   byte-for-byte and routes only to the generic function when either side of
   the move is a grouped scope.
4. **A grouped scope cannot reach nobody.** The cascade RPC refuses a move
   with no target, and refuses a target whose resolved population is empty.
5. **Two scopes go live, three stay labelled.** Business Unit and Location have
   the highest master-data fill (99.9% for location) and ship enabled. Division,
   PMS Grade and Level keep the **Soon** marker until their master data is
   audited — the labels now describe the truth.

## Consequences

- Adding the remaining three scopes is a data-readiness decision, not new
  code: the picker, the options RPC and the migration are already generic.
- Re-scoping onto a grouped scope stamps the target column on every affected
  KPI row and clears the other scope columns, so a KPI never carries two keys.
- Locked periods are still skipped by the cascade, unchanged.
- Tests: `src/lib/review/kpiScope.test.ts` covers the 9-scope vocabulary, the
  target column map and `scopeNeedsTarget`.
