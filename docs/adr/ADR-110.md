# ADR-110 — Reporting / Skip-Level Manager access to the assisted-submission directory

- Status: Accepted (2026-07-17)
- Supersedes: extends the matrix in ADR describing §AR-DIRECTORY-ACCESS-MATRIX (v2.66.101).

## Context
The Annual Review "Find employee" entry point on `/annual-review/team` (button label
"All employees" / "BU employees") drives the assisted-submission flow. It was gated
by `public.annual_review_directory_access(uid)`, which only granted access to
Admin, HR PMS, HR-BU members, BU Heads, and HODs.

A plain Reporting Manager (e.g. employee `101187`, `manager` role, 11 active
direct reports, not a BU Head or HOD) was denied by the resolver
(`{can_access:false}`) and therefore never saw the button, even though they own
the review queues for their team and are the natural person to assist a
non-login employee with self-submission.

## Decision
Add rule 6 to the resolver: **scope `team`** for any user who has at least one
active direct report, at least one active skip report (two-hop chain), OR who
already appears as `manager_id` / `skip_id` on an `annual_review_instances`
row.

- `search_active_employees_for_review` restricts results for `scope='team'` to
  the caller's direct + skip reports (or employees already assigned to them in
  the active cycle).
- `create_or_get_annual_review_instance` re-verifies the same predicate on
  writes and rejects out-of-team employees with `42501`.
- `annual_review.instance.auto_created` audit rows record
  `actor_scope = 'reporting_manager'` for these callers.
- First-match order is preserved so any Admin/HR/BU-Head/HOD who is *also* a
  manager keeps their existing (broader) scope.

## UI
`useDirectoryAccess` widens `DirectoryAccessScope` to `'all' | 'bu' | 'team'`.
`TeamAnnualReview.tsx` renders the same button with label **"Team employees"**
and a tooltip clarifying the scope. The global feature flag
`app_settings.annual_review_directory_search_enabled` still gates the button.

## Alternatives considered
- **Static role check (`role='manager'`)** — rejected. Bypasses the server SSOT
  (§AR-DIRECTORY-ACCESS-MATRIX) and would leak into RLS drift.
- **Widen `scope='all'` for managers** — rejected. Would let a line manager
  seed reviews for arbitrary employees outside their subtree.

## Rollback
Additive migration. Reverting restores the previous resolver body; the
`'team'` label branch becomes dead code. No data cleanup required — instances
created by managers are indistinguishable from other AR instances.
