# ADR-311 — Workflow mapping change blocked by rating type drift

Status: Accepted (2026-08-25)
Related: ADR-193 §WF-CHANGE-NO-RATING-LOSS

## Context

Assigning a period-specific workflow to employee 101643 (Rajkiran Kumar) for December 2025
failed. The UI only rendered "Failed to assign workflow."; the Postgres log carried the real
cause, four times, at the exact minutes of the attempts:

```text
ERROR: COALESCE types text and rating_level cannot be matched
```

## 5-Why

1. The write to `workflow_config` aborted.
2. The `trg_workflow_change_step_back` trigger raised an error.
3. `workflow_change_step_back()` evaluated `COALESCE(rs.prior_final_rating, rs.final_rating)`.
4. `review_submissions.prior_final_rating` is `text`, `final_rating` is the `rating_level`
   enum — Postgres refuses to resolve a common type for the two.
5. The branch only runs when the affected employee has approved, rated KPIs in the target
   period, so most workflow changes never hit it and the drift stayed latent since ADR-193.

## Decision

1. Cast explicitly inside the trigger: `COALESCE(rs.prior_final_rating, rs.final_rating::text)`
   in both the terminal and the sibling snapshot branches, and
   `prior_final_rating::rating_level` in the restore branch. No schema or behaviour change.
2. `WorkflowConfig.tsx` must surface the backend message in assign/remove error toasts instead
   of a fixed string.
3. Guard test `src/tests/workflowStepBackRatingCast.test.ts` asserts the shipped migration never
   re-introduces an uncast `COALESCE(..., rs.final_rating)`.

## Consequences

Workflow mapping changes work again for employees with approved, rated KPIs. Rating snapshots
continue to be stored as text; no historic data was rewritten.
