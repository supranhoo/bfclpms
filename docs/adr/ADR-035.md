# ADR-035: Admin N/A Toggle Role-Scoped Clearing

## Status
**Accepted**

## Date
2026-03-30

## Context
When an admin marks a KPI as N/A via the Admin Data Entry dialog, scoring fields need to be cleared. The question was whether to clear all role levels or only the currently selected role.

## Decision
Only clear scoring fields (achieved_value, rating, score, remarks) for the **currently selected role level** and `final_score`/`final_rating`. Other review levels remain untouched. The dialog tracks original `is_na` state and only includes `is_na` in the mutation payload when the value differs.

## Alternatives Considered

### Alternative A: Clear all role levels when N/A is toggled
- **Description:** Nullify scores across self, manager, skip-level, HR PMS, auditor, and management
- **Rejected because:** Causes data loss for already-completed reviews. A manager may have scored the KPI before it was marked N/A at a later stage.

### Alternative B: Always send `is_na` in the mutation payload
- **Description:** Include the `is_na` flag regardless of whether it changed
- **Rejected because:** Triggers unnecessary re-clears on subsequent edits, potentially wiping scores that were entered after a prior N/A toggle.

## Consequences

### Positive
- Preserves already-completed review data for unaffected roles
- Prevents accidental re-clears

### Negative
- More complex tracking of original vs. current `is_na` state

### Neutral
- The `is_na` flag remains a KPI-level marker
