# ADR-169 — Reusable "Transfer stage response" for Annual Review

Date: 2026-07-25
Status: Accepted

## Context

Org reshuffles mid-cycle (a BU Head demoted to Dept Head, a new BU Head
appointed) leave already-locked responses attributed to a role the reviewer
no longer holds. Existing options are unsatisfactory:

- **`safe` edit** cannot remove a stage with locked responses.
- **`supersede` edit** archives the locked response and rewinds status, forcing
  the incoming reviewer to re-score from scratch — the score work is lost.

Business need: preserve the score, but re-attribute it to the stage the
outgoing reviewer now occupies (e.g. BU Head → Dept Head), so the review can
remain completed and the new BU Head takes over from the next cycle onward.

## Decision (POLICY §AR-STAGE-RESPONSE-TRANSFER)

Introduce a governed, audit-logged, reversible transfer:

`public.transfer_annual_review_stage_response(instance, from_role, to_role,
 new_reviewer_id?, drop_from_stage?, reason)`

- Admin / HR PMS only.
- Re-labels the locked response's `reviewer_role` from source to destination;
  keeps `scores_json`, `comments`, `submitted_at`, `is_locked`.
- Optionally drops `from_role` from `enabled_stages` and repoints the source
  slot to the incoming reviewer (`new_reviewer_id`).
- Advances `overall_status` when the instance was still waiting on the
  source stage.
- Idempotent — no source response → audited no-op.
- Every call snapshots the full before-state into
  `annual_review_stage_transfer_audit_2026_07`, from which
  `revert_stage_transfer(audit_id)` restores the instance atomically.

Reused surface: **Edit workflow & reviewers → "Transfer response to another
stage…"** button opens `TransferStageResponseDialog`.

## Consequences

- Final scores are preserved (POLICY §88 invariant unchanged — the response
  payload is untouched).
- Reversible per audit row; no destructive path.
- Reusable for any future BU/Dept/HR reviewer swap mid-cycle.
