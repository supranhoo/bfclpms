# ADR-283 — Performance Console information density

Status: Accepted — 2026-08-16

## Context
At 1280x772 the console spent roughly 460px above the first KRA row: a title card,
a separate tab strip, the filter card, a five-tile stat band, a breadcrumb that
repeated the scope already printed in the stat band, and only then the category
strip. Less than a third of the viewport was left for the work itself.

## Decision
Chrome is compacted and de-duplicated; nothing is removed without an affordance.

- Title, Beta badge and the three tabs share one ~56px bar. The descriptive
  sentence moves to a tooltip on the Beta badge.
- `ConsoleStatBand` gains `variant="strip"` (now the default for a loaded scope):
  one line of `glyph label value` chips instead of five 90px tiles. The
  "distinct employees in scope" caption becomes a tooltip. The tile grid remains
  for the pre-scope placeholder via `variant="tiles"`.
- The drill breadcrumb moves into the category strip row (`BuConsoleTree`
  `breadcrumb` slot) instead of occupying its own line.
- `ScopeToolbar` drops the stacked field captions (labels live in the
  placeholders plus a `title` tooltip) and collapses to a summary chip once the
  user scrolls. It never collapses while `isDirty` — the "Apply filters" call to
  action must stay on screen. Collapse is driven by an IntersectionObserver
  sentinel, never a timer.
- Page padding `p-4 sm:p-6` -> `p-3 sm:p-4`, block gap `space-y-4` -> `space-y-2`.
  Data-row heights are unchanged: readability wins over density inside the tree.

Result: about 210px of chrome, roughly 250px returned to the work area.

## Policy
POLICY §CONSOLE-CHROME-BUDGET.

## Verification
- `consoleLayout.test.tsx` — strip variant renders all five metrics and still
  uses the server distinct total (ADR-281 guard intact).
- `scopeToolbar.test.tsx` — collapses when scrolled, refuses to collapse while
  dirty, stays expanded at the top of the page.

## Rollback
Revert the four presentation files. No data, RPC or state-shape change.
