# ADR-039: Notification KPI Name Truncation

## Status
**Accepted**

## Date
2026-03-30

## Context
KPI names in the database often contain multi-line text with description, formula, and scoring logic appended. These lengthy names were appearing in full in notification messages.

## Decision
All notification messages must use the first line of the KPI name only, truncated to 100 characters (client-side: `.split('\n')[0].substring(0, 100)`; DB trigger: `LEFT(SPLIT_PART(..., E'\n', 1), 80)`).

## Alternatives Considered

### Alternative A: Use full KPI name in notifications
- **Description:** Include the complete KPI name text as-is
- **Rejected because:** Makes notifications unreadable. Clutters notification panels and email inboxes with formula text and scoring criteria.

### Alternative B: Maintain a separate `display_name` column
- **Description:** Add a short display name field to KPIs table
- **Rejected because:** Adds schema complexity, requires backfilling existing data, and creates a maintenance burden to keep display names in sync.

## Consequences

### Positive
- Clean, readable notification messages
- Works for both in-app and email notifications

### Negative
- First-line truncation may occasionally cut off meaningful context

### Neutral
- Applied at both client-side insert and DB trigger levels for consistency
