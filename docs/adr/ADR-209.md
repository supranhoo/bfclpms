# ADR-209 — Admin-only first-action date on Review Journey stage cards

- Status: Accepted
- Date: 2026-07-31
- Policy: §AR-STAGE-FIRST-ACTION-DATE

## Context

Admins need to know when each Review Journey stage was FIRST actioned (e.g. the employee's first self-submission), independent of later resubmissions after send-backs. `review_submissions.submitted_at` is upserted on every submit and so only reflects the latest action.

## Decision

1. `src/lib/review/stageFirstActionDate.ts` is the SSOT: it maps qualifying `kpi_audit_logs.action` values to journey stages (`self`, `manager`, `functional_manager`, `skip_level`, `hr_pms`, `auditor`, `management`) and returns the earliest `created_at` per stage. Generic status/score rows and send-backs are excluded.
2. `ReviewStageCard` accepts optional `firstActionAt` + `showFirstActionDate` and renders `1st: DD MMM YYYY` in muted text in the card header, with a tooltip carrying the full timestamp.
3. `KpiJourneySection` reuses its existing `['kpi-journey-audit-logs', kpi.id]` query (no additional network calls), memoizes the resolution, and gates visibility on `effectiveRole === 'admin'`.

## Out of scope

No schema changes, no writes, no workflow logic. Previous-month mini cards keep their compact renderer.

## Verification

- `src/test/stageFirstActionDate.test.ts` (7 tests) — earliest-wins across resubmits, generic-action exclusion, per-stage parity, null-safety, no duplicate action mapping.
- `src/test/reviewStageCardFirstActionDate.test.tsx` (3 tests) — admin renders, non-admin hidden, unknown date hidden.

## Rollback

Pure frontend. Revert the three files; no data migration.
