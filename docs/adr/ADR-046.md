# ADR-046: Daily KPI Rating Calculation

## Status
**Accepted**

## Date
2026-04-01

## Context
Daily/Weekly KPIs using `missed_days_penalty` aggregation produce a 0–5 score. The question was whether this score should be re-mapped through threshold-based rating functions.

## Decision
The missed_days_penalty aggregated score (0–5) IS the final rating. It must NOT be re-mapped through `calculateScoreFromAchieved`. Expected days must use `useExpectedDays` (respecting `day_count_type` and employee-specific working days).

## Alternatives Considered

### Alternative A: Re-map penalty score through threshold function
- **Description:** Pass the 0–5 penalty score through `calculateScoreFromAchieved` like other KPI types
- **Rejected because:** Causes double-conversion errors. A penalty score of 0 would be incorrectly mapped to "Outstanding" for Lower-is-Better KPIs. The penalty score is already on the final 0–5 scale.

### Alternative B: Use raw calendar days for expected days
- **Description:** Calculate expected days from the calendar month length
- **Rejected because:** Ignores `day_count_type` configuration and employee-specific working days, causing mismatches between the Daily Submission Summary and the Submit Monthly Review dialog.

## Consequences

### Positive
- Correct rating for all daily KPI polarity types
- Consistent expected days across all UI components

### Negative
- Special-case logic for missed_days_penalty in the scoring pipeline

### Neutral
- Applies to both Daily and Weekly frequency KPIs using this aggregation method
