# ADR-282 — A KPI's scoring model is group-owned; per-employee tuning is scope-only

Status: Accepted — 2026-08-16

## Context
The Performance Console's "Tune" dialog (`RowOverrideDialog`) was type-blind. For a
Yes/No KPI such as "Closure of audit observations related to spillage" it still
rendered a free-text **Unit** box (showing the literal `binary`), a **Direction**
selector and a six-box **R5…R0 scoring ladder** — none of which participate in
qualitative scoring, which is driven entirely by `kpis.qualitative_options`.

Consequences of leaving it as designed:
- Filling R0–R5 writes dead data and makes an unconfigured KPI look configured.
- Editing the unit desynchronises the row from every reviewer surface that branches
  on `uom_type` (ADR-271 parity).
- Per-employee divergence of the scoring model is the real hazard: one employee on
  Yes=5 while the group is on No=5 silently changes results and breaks aggregation.

## Decision
Per-employee tuning may change **how much a KPI counts and when it is measured**
(weightage, target, frequency, cycle anchor, day counting, source of data). It may
never change **how a value becomes a score** (`uom_type`, `qualitative_options`,
`r0..r5`, `criteria`, `threshold_mode`, and `uom` when it mirrors the type).
Value-based KPIs keep the ladder tunable — that is a target-level adjustment, not a
change of model.

Implementation:
- `src/components/admin/bu-console/rowOverrideModel.ts` — `rowEditableFields()` and
  `scoringModelLockReason()`, the client mirror of the server guard.
- `RowOverrideDialog` resolves the row via `resolveKpiScoringModel`, shows a type
  chip, and for binary/tiered replaces the ladder/direction/unit inputs with a
  read-only `KpiScoringScale` plus a shortcut into the group definition editor.
- `public.bu_console_scoring_model_lock(kpi_id, changes)` returns
  `scoring_model_locked`; `bu_console_row_override` returns it as a skip reason and
  `bu_console_bulk_row_overrides` records it as a skipped row (never a mid-run abort).
- `public.bu_console_validate_changes` now validates `qualitative_options` shape:
  a non-empty array of `{label, rating 0..5}`.

## Policy
POLICY §KPI-SCORING-MODEL-GROUP-OWNED (cross-referenced from §KPI-TYPE-PARITY).

## Verification
- `src/components/admin/bu-console/rowOverrideModel.test.ts` — 7 tests: editable set
  per type, ladder allowed only for numeric, type/options never per-employee.
- Existing console suites unchanged.

## Rollback
Revert the component and restore the previous bodies of
`bu_console_row_override`, `bu_console_bulk_row_overrides` and
`bu_console_validate_changes`. Nothing is persisted by this change.
