# ADR-071 — Functional Manager as a peer reviewer level

- **Status:** Accepted (2026-06-01)
- **Context:** PMS reviewers were limited to Reporting Manager, Skip-level, HR PMS, Auditor, and Management. Matrix-org workflows needed a sixth peer reviewer — the Functional Manager (FM) — mapped per-employee, optional per workflow template, and fully backward-compatible.
- **Decision:** Introduce `functional_manager` as a per-employee relationship on `profiles.functional_manager_id` (nullable, FK to `profiles(id)` ON DELETE SET NULL) and `functional_manager_check` as a new `review_status` enum value placed between `manager_check` and `skip_level_check`. The FM is **not** a global role pool — no new `app_role` enum value; access derives solely from the `functional_manager_id` pointer plus the workflow stage, enforced by the `is_functional_manager_of(uuid)` SECURITY DEFINER helper to avoid RLS recursion on `profiles`.
- **SSOT integration:** `workflowResolver` (ChainStage), `workflowEngine` (stage order), `bottleneckResolver`, `reviewConstants`, `inboxUtils`, `multimonthCycle`, `EMPLOYEE_MASTER_FIELDS` (20 fields) all extended in lockstep.
- **Surfaces shipped (Phases 1, 4, 6):**
  - Add User / Edit User → Functional Manager combobox in the Reporting section (mirrors Reporting Manager). Persisted via `profiles.functional_manager_id`; `create-employee` edge function accepts `functional_manager_id`.
  - ReportingStructureCard renders FM when set. KpiJourneySection renders FM stage card.
  - Workflow Config template builder exposes `Functional Manager Review` as an optional stage.
  - Employee import accepts header aliases `functionalManagerEmployeeId` / `functional_manager_code` / `fmCode` and `functionalManagerName` / `functional_manager` / `fm`. Resolution order = employee_code → full_name. Unresolved identifier raises a row-level error; row is skipped. Applied to both create and update paths.
  - Employee export emits `functionalManagerEmployeeId` and `functionalManagerName` (round-trip safe).
  - RLS additive policies on `kpis`, `review_submissions`, `kpi_observations`, `kpi_queries`: FM SELECT on mapped employees; UPDATE on `kpis` + `review_submissions` only when status = `functional_manager_check`; INSERT permitted on observations/queries for mapped employees. Hot-path partial index on `profiles.functional_manager_id`.
  - `useEmployeeFilterOptions` exposes a `functionalManagers` list for downstream report/filter wiring.
- **Deferred (later phases):**
  - `bulk_review_snapshot`, `bulk_scope_preview`, `bulk_write_stage_scores`, and `rpc_bulk_employee_attrs` need server-side wiring to (a) accept `viewer_stage = 'functional_manager'`, (b) scope the snapshot to employees where `functional_manager_id = auth.uid()`, and (c) advance `kpis.status` from `functional_manager_check` to `skip_level_check`/next-active when FM approves.
  - `review_submissions.functional_manager_score` / `functional_manager_rating` / `functional_manager_remarks` columns + universal scoring fallback chain (currently the FM stage records the workflow transition only; per-stage score columns are reserved for the next phase).
  - Reports (Employee Performance Summary, Manager Team KPI, KPI Matrix, Workflow Resolution, Custom Report builder): expose FM filter chip + optional column + "Group by Functional Manager".
  - Workflow Resolution export → new "Functional Manager" column; warning banner when a template includes FM stage but in-scope employees lack an FM mapping.
- **Backward compatibility:** Schema and stage list are purely additive. Templates that do not include `functional_manager_check` skip the stage cleanly (`inTemplate=false`, no exception). Rolling back requires `UPDATE workflow_templates SET stages = array_remove(stages, 'functional_manager_check')` before dropping the enum value (one-line statement).
- **Out of scope:** Multi-FM per employee (would require a junction table `employee_functional_managers`); auto-assigning FM by department/grade; FM-specific email reminder customisation (reuses existing per-stage reminder engine).
