# ADR-199: Universal employee Active / Inactive / All scope for reports

- Status: Accepted (July 2026)

## Context
ADR-177 added the `Active | Inactive | All` segmented control to the KPI Status Tracker only.
Every other employee-keyed report still counted separated employees as live work, inflating
pending tiles, department rollups and Excel exports.

## Decision
1. **Shared control.** `<EmployeeStatusFilter />` (URL-persisted `?emp_status=`) is mounted on
   every employee-keyed report. Default remains **Active**.
2. **Single filtering SSOT.** All scoping goes through `applyEmployeeStatusFilter()` in
   `src/lib/reportEmployeeFilter.ts`; unknown flags are treated as active (no silent data loss).
3. **Hydration.** Report data paths select `profiles.is_active` (paged via `fetchAllPaged` where
   the roster can exceed the PostgREST 1000-row cap).
4. **Server-paged reports.** `get_first_kra_rollout` gained `p_emp_status text default 'active'`
   and returns `is_active`, since client-side filtering cannot work across server pagination.
5. **Exports.** Excel/CSV exports honour the on-screen scope and stamp it via
   `appendEmployeeScopeNote()`, plus an "Employee Status" column where a field registry exists.
6. **Not applicable.** `DevelopmentReport` is not employee-keyed (feature/bug/timeline entries).

## Consequences
- Pending/among-total counts are consistent across reports and exports.
- Drift guard: `src/test/reportEmployeeStatusCoverage.test.ts` fails if a listed report drops the control.

## Coverage
CompletionReport, DepartmentReport, PerformanceReport, QueryReport, KRAIssuance, KpiDetailReport,
MonthlyScorecardReport, KpiScorecardDetail, VarianceReport, ManagerTeamKpiReport,
TeamVsManagerScoreReport, KpiEmployeeMatrix, TNIReport, FirstKraRolloutReport, CustomReport,
KpiStatusTracker.
